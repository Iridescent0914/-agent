# M6 工作总结与教师演示版交接

> 实现状态：打印、图片上传、答案抄读、待复核提交、教师核对、规则判分、审计和画像更新的工程闭环已经完成。
>
> 验收状态：fake adapter 的自动化闭环已经通过；真实 VLM 与真实照片的质量评估尚需供应商凭据和去身份化样本，因此当前不能宣称“真实识别质量验收完成”。

## 1. 本阶段交付

M6 没有让视觉模型解题或判分，而是在 M4 稳定答案合同之前增加图片输入层：

```text
发布快照 -> 学生打印卷/统一答题区 -> 上传照片 -> VLM 只抄读答案
         -> 全题 needs_review -> 教师对照原图确认/修正
         -> M4 grade_answer -> AttemptRevision -> 画像重算 -> M5 学情
```

已实现：

- 独立学生打印视图和 A4 打印样式，正文、答题区、页脚使用同一个实例码和版本号；
- 打印 API 不暴露标准答案、评分规则、分析或推荐审计；
- JPEG、PNG、WebP 上传，真实格式/大小/像素校验、EXIF 方向修正、去元数据和原子落盘；
- `VisionService` 协议、离线 fake adapter 和 OpenAI-compatible 视觉适配器；
- `m6-answer-reader-v2` 按题传递识别格式；选择题合法字母从发布快照动态推导，不固定为 ABCD，也不传标准答案；
- 大小写和全角选择字母归一化，超出本题合法集合以及组合小题缺失、重复或错位统一降级为 `ambiguous`；
- 严格结构化结果解析，区分 readable、blank、missing、illegible、ambiguous；
- `recognition_runs`、`recognition_items` 和 Alembic `0013`；
- 上传幂等、精确实例码核对、旧 superseded 版本按旧快照处理、withdrawn 版本拒绝新提交；
- 图片 Submission 创建后全题待复核，置信度不触发自动确认；
- 教师逐题或批量确认/修正，复用确定性判分，追加修订并只重算一次画像；
- 原图与识别结果并排展示，原图通过受控 API 读取，不挂载公开静态目录；
- 过期原图 dry-run 清理脚本、只读验收脚本和真实图片评估脚本；
- 桌面端和 390px 移动端打印/识别 Playwright 覆盖。

```text

```

原图只存受控目录，数据库记录哈希、尺寸、模型、提示版本、状态和保留期限。清理原图不会级联删除识别元数据和学习证据。

## 3. 必须保持的安全边界

- VLM 请求只有去身份化答题区图片、题号、题型和输出 schema，不包含学生姓名或标准答案。
- 模型输出不能写 `is_correct`，正确性只由教师确认后的答案交给 `grade_answer` 生成。
- missing、illegible、ambiguous 不会被自动解释成空白或答错。
- readable 和 blank 也不会因置信度高而自动进入画像。
- 已确认 Attempt 不会被重新识别覆盖；并发确认使用 `expected_revision_no` 防止丢失更新。
- VLM 失败时 run 记录错误，M4 手动录入入口仍可使用。
- API key 只能来自环境变量，不写入仓库、数据库、响应和日志。

## 4. 配置与启动

默认 fake 模式不需要网络：

```dotenv
VISION_ENABLED=false
VISION_PROVIDER=fake
VISION_MODEL=fake-m6-v1
```

真实模型使用兼容 Chat Completions 图片输入的供应商：

```dotenv
VISION_ENABLED=true
VISION_PROVIDER=openai_compatible
VISION_MODEL=Qwen/Qwen3-VL-4B-Instruct
VISION_API_BASE_URL=<api-base>
VISION_API_KEY=
VISION_TIMEOUT_SECONDS=45
VISION_MAX_TOKENS=2048
```

本地 vLLM 可以不设置 `VISION_API_KEY`，后端仅在密钥非空时发送 Bearer 请求头。当前推荐使用 Qwen3-VL 4B Instruct；若真实样本评测不达标，可只替换模型名升级到 8B Instruct。OCR 抄录任务不使用 Thinking 版本。

M6 新增了 Pillow、python-multipart 和 httpx。旧 Docker 镜像必须重新构建 backend；本机环境则重新执行 editable install。

## 5. 教师演示路径

1. 打开“组卷”，创建并发布一份学生试卷。
2. 在试卷详情点击“打印学生卷”，打印或保存 PDF，确认正文和统一答题区短码一致。
3. 学生在统一答题区填写答案；演示图片应裁去姓名、学号等身份信息。
4. 回到试卷详情点击“上传答题区照片”，核对纸面短码后上传。
5. 点击“开始提取答案”，查看原图、五类识别状态和模型自报置信度。
6. 点击“提交为待复核作答”，进入批改页。
7. 对照原图逐题确认或修正；无法辨认、缺失、歧义项必须显式修正。
8. 确认判分、修订时间线、学生画像和班级学情变化。
9. 关闭视觉服务或模拟超时，展示识别失败后仍可走手动录入。

## 7. 真实图片质量评估

复制 `data/eval/m6/manifest.example.json`，准备不进入 Git 的私人图片目录，并运行：

```powershell
cd D:\desktop\math-agent\code\backend
& '..\.conda-env\python.exe' -m scripts.evaluate_m6_recognition `
  --manifest '..\data\eval\m6\manifest.private.json' `
  --output '..\data\eval\m6\results.private.json' `
  --require-thresholds
```

评估脚本拒绝 disabled/fake 适配器和空样本；严格模式按 manifest 的 `acceptance_thresholds` 返回成功或失败。交付报告至少记录：模型与提示版本、样本数量与覆盖场景、答案准确率、漏识别率、需修改比例、教师平均复核耗时、失败样例分类。样本应覆盖负号、分数、真实空白、涂改、模糊、歧义和缺失题号。

没有真实凭据和真实样本时只能验证工程闭环，不能用 fake adapter 的固定结果代替质量报告。

## 8. 已知边界与后续工作

- 第一版要求教师上传手工裁剪后的单页统一答题区，不做自动透视校正、多页扫描和二维码定位。
- 视觉适配器以 OpenAI-compatible `/chat/completions` 为合同；非兼容供应商需新增 adapter，不应把供应商 SDK 渗入业务层。
- PP-OCRv5 与 PP-FormulaNet_plus-M 暂未接入主链路；必须先为打印答题区增加稳定定位标记与逐题裁剪坐标，否则专用 OCR 无法可靠对应题号。
- MathLive 仍是按路由加载的大模块，生产构建会如实给出体积提示，但不阻塞 M6。
- 真实质量达到阈值后，再决定是否增加自动裁剪、二维码或批量扫描；置信度自动放行仍不在当前范围。
