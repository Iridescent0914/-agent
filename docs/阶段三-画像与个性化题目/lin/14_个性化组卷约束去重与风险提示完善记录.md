## 1. 修正范围

本次按顺序完成五项修正：

1. 更正个性化换题错误显示“证据不足”的文案；
2. 候选题同时校验知识点与题目自身的主要素养标签；
3. 草稿编辑和发布阶段强制保留完整三道个性化题；
4. 班级批量组卷时尽量减少学生之间的重复题；
5. 增加近期布置与作答排除、班级复用警告和无替换题诊断。

本次没有新增数据表或迁移。新增审计字段保存在现有 JSON 审计快照中，旧快照读取时使用兼容默认值。

## 2. 换题理由口径

个性化换题不再调用掌握度推荐模块的“证据不足”业务解释。替换候选现在明确展示当前采用的素养整数分、基础星级、个性化题位、目标题星和教师知识点范围。

“证据不足”原本表示某知识点缺少足够掌握度作答证据，并不代表动态素养分不可用，因此不能作为个性化换题理由。

## 3. 主要素养双重匹配

首次预览、正式创建和后续换题统一执行：

```text
知识点 core_competencies 包含主要素养
且
题目 core_literacy 包含主要素养
```

例如教师选择“推理能力”后，只标注“抽象能力、应用意识”的题即使处于同一知识点和同一星级，也不会进入候选池。历史无效标签同样不会进入个性化自动组卷池。

## 4. 固定三题不可绕过

- 个性化题不能直接删除，只能在原题位执行换题；
- 前端将删除入口替换为“固定题位”；
- 发布前后端重新统计 `source_module = personalized` 的题目数量；
- 必须与审计中的请求数量一致，即当前版本固定为 3；
- 普通总题量不足的教师确认不能绕过个性化三题规则；
- 修订版同样执行该约束。

## 5. 班级最少复用分配

同一班级批量生成时，候选排序增加“本次班级已使用次数”：

```text
优先使用次数少 → 题目原始编号 → 题目 UUID
```

库存足够时，不同学生优先获得不同题；库存不足时才按稳定顺序循环复用。该策略不会跨知识点范围、跨主要素养或跨星级降级补题，也不会造成单个学生卷内重复。

每道正式个性化题新增冻结 `class_usage_count`。前端预检会显示本次班级被复用的题目数和单题最大使用人数。复用是库存风险提示，不阻止创建；缺少三个精确题位仍会阻止创建。

## 6. 近期布置、作答与替换诊断

个性化初次选题和换题现在都遵循 `avoid_recent_days`：

- 默认排除学生近 7 天已经布置或作答的题；
- 教师将天数设为 0 时不执行近期排除；
- 已选必做题、历史回顾题和当前试卷其他题继续排除。

换题接口新增诊断，返回教师范围内的目标题星题数、主要素养匹配数、可机判已审核数、当前卷排除数、近期布置或作答排除数、当前可替换数和中文结论。

正式创建若库存不足，后端错误会给出示例学生、缺失星级与数量，并说明主要素养、星级、审核状态和近期排除约束。

## 9. 与 01、02 的最终关联

- `01` 建立的学生画像入口现已读取 `literacy-dynamic-v1` 的 computed 动态素养整数分；本次个性化组卷使用同一份分数和同一取整边界，不另建能力口径。
- `02` 建立的年级、章节、节和正式知识点编码继续作为教师筛选范围；本次在该范围上进一步取“知识点主要素养 + 题目核心素养”的交集。
- 知识点正确率、历史作答和作业进度仍沿用 `01`、`02` 的展示与证据口径；个性化组卷没有反向修改画像历史。
- 正式作业保存创建时的整数分、星级、规则版本、生成时间和班级使用次数，后续画像变化不会自动换题。
