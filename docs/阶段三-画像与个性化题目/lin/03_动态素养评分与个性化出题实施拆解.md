# 动态素养评分与个性化出题实施拆解

> 记录日期：2026-10-31  
> 需求来源：`智能作业系统素养动态评分与个性化出题机制说明_修改版.docx`  
> 实施原则：评分算法、持久化、证据回放和个性化组卷全部通过测试后，再切换画像与班级学情的基础值展示。

## 1. 当前基础与边界

阶段二已经提供必做题、历史回顾、知识点“是 / 否 / 弱”状态和周总结流程，本阶段不重复实现这些功能，只做回归验证并确保新增个性化题不会破坏原有模块。

阶段三已有记录：

- `01_基础画像展示调整记录.md` 已建立 8 种素养雷达图和 `baseline / computed` 接口契约；
- `02_画像年级章节筛选与新知识点映射调整记录.md` 已统一年级、章节、节、知识点的正式编码和筛选口径；
- 当前画像仍固定返回 60 分，符合“算法未完整接入前保持 baseline”的约束；
- 仓库已有一组未接入业务的素养公式函数，但其中仍有与修改版文档不一致的旧难度目标和题量混合规则，需要先校正。

## 2. 权威需求口径

### 2.1 动态评分

- 8 种素养分别以 60 分、答题次数 0 初始化；
- 分数范围 `0～100`，内部保留小数；
- 星级难度映射为 `1→30、2→45、3→60、4→75、5→90`；
- 预期正确率使用 Logistic 公式，平滑尺度为 15；
- 选择题考虑猜测概率，四选一默认下限为 0.25；
- 学习率为 `max(3, 12 / (1 + n / 30))`；
- 多素养题去重后均分权重；
- 同一自然日、同一学生、同一素养的净变化限制为 `±8`；
- 未练习日向 60 分回归 1%；
- 只有已确认且具有合法发布快照的作答进入计算，`needs_review` 不进入计算；
- 教师改判或撤销确认后必须能够从当前有效证据确定性回放。

### 2.2 个性化题

- 教师必须选择年级、章节和知识点；
- 所选知识点必须已配置能力，教师从所选知识点对应能力中选择一个主要能力；
- 内部小数先按 `ROUND_HALF_UP` 四舍五入成业务整数，再按固定区间确定基础星级：`0～59→1`、`60～69→2`、`70～79→3`、`80～89→4`、`90～100→5`；
- 每名学生总共生成 3 道个性化题，题目来自教师所选知识点范围，星级为 `基础、基础+1、基础+2`，超过 5 按 5 处理；
- 选题必须使用对应知识点、对应星级的可自动批改题，并排除同一试卷已选题；
- 候选不足必须显式返回缺题诊断，不得静默降级到其他知识点或星级。

## 3. 分段实施计划

### 第一部分：锁定纯算法规则

- 删除与修改版无关的 `70/20/10` 题量混合规则；
- 将难度确定改为固定分数区间；
- 增加个性化三星序列、选择题猜测概率、多素养均分、显示取整和未练回归的边界测试；
- 本部分不读写数据库，也不切换画像接口。

验收：纯函数单元测试覆盖公式示例、所有分数区间边界、五星封顶、学习率下限、日限幅和非法输入。

### 第二部分：素养分证据回放与持久化

- 新增学生素养分物化表，保存分数、答题次数、最后练习时间、规则版本；
- 从 `Attempt + AttemptRevision + PaperInstanceItem` 当前有效证据回放素养分；
- 使用发布时的 `question_snapshot` 中星级、题型和素养，避免题库后续编辑改写历史；
- 按 `Asia/Shanghai` 自然日分组执行日限幅和未练回归；
- 提供幂等重建命令，并把新表纳入业务数据清理脚本。

验收：空学生为 8 个 60 分；重复重建不产生变化；改判、撤销、跨日和多素养题回放结果确定。

### 第三部分：提交与改判闭环

- 在人工提交、识别提交、教师确认、改判和撤销确认后刷新素养分；
- 与现有知识点掌握度、知识点状态更新处于同一事务；
- 任一刷新失败时整笔业务事务回滚。

验收：各写入入口的集成测试覆盖新增、重复请求、改判和撤销。

### 第四部分：小型 Demo 与画像关联

- 复用 `current_demo_scenario.json` 和当前发布、提交、批改链路形成差异化素养证据；
- 不直接写死分数，由回放服务生成 5 名学生的真实计算结果；
- 学生画像 `literacies` 从固定 60 切换到计算结果，`score_source=computed`；
- 班级学情雷达图改为班内学生同素养分的平均值；
- 沿用 `02` 的年级、章节和正式知识点映射，不改变知识点正确率统计；
- 空证据学生仍显示 60，但来源为已初始化/可回放的计算结果；
- 更新 `01`、`02` 的后续接入说明，形成明确的文档关联。

验收：学生与班级接口、雷达图、年级章节筛选、空数据状态和 Demo 重复构造全部通过。

### 第五部分：个性化选题服务

- 校验所选知识点能力目录和教师选择的单一主要能力；
- 读取每名学生该能力的最新素养分；
- 生成基础星级、`+1`、`+2` 三个槽位；
- 按知识点和精确星级确定性选题并输出完整审计信息；
- 与必做题、历史回顾题共享去重集合。

验收：覆盖五档分数、`4→4/5/5`、`5→5/5/5`、每名学生固定三题、多学生不同结果、候选不足及确定性。

### 第六部分：作业预览、创建和前端接入

- 将个性化题加入现有 `必做题 + 历史回顾` 预览和建卷流程；
- 保留“所选知识点范围 + 单一主要能力 + 固定三题”的权威筛选合同；
- 前端移除“算法后续接入”提示，展示每名学生的个性化题及缺题诊断；
- 试卷快照和选择审计标记 `source_module=personalized`。

验收：预览只读、创建幂等、发布快照不可变、换题保持个性化模块与星级约束。

### 第七部分：全链路回归与演示数据

- 确认 5 名 Demo 学生形成可解释的不同素养分和不同个性化星级；
- 回归必做题、历史回顾、“是 / 否 / 弱”和周总结；
- 运行后端全量测试、前端类型检查和现有验收脚本；
- 补充最终汇总记录，列出规则版本、迁移、命令、结果及已知边界。

## 4. 已明确的实现约定

- 内部计算和数据库保留小数，不在每题更新后损失精度；画像展示、班级均值展示和个性化星级分档统一使用 `ROUND_HALF_UP` 得到的业务整数；
- 历史证据以发布快照为准，当前题库字段只用于未来新试卷；
- 多素养按去重后的素养数量严格均分，不允许手工设置不等权重；
- 选择题优先按发布快照选项数量计算 `1 / 选项数`，缺少合法选项信息时回退到 0.25；
- 日界线采用系统当前业务时区 `Asia/Shanghai`；
- 候选不足只返回诊断，不跨知识点、跨星级补题；
- 在第四部分画像关联前，`01`、`02` 建立的画像页面继续显示 baseline，避免未闭环的分数进入演示。
