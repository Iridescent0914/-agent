# 试卷生命周期与画像证据口径记录

> 初始记录日期：2026-11-05
>
> 业务调整日期：2026-11-07
>
> 关联模块：学生画像、动态素养分、知识点回顾标签、试卷生命周期

## 1. 当前业务口径

试卷一旦存在已确认的批改结果，就不允许撤回。已确认结果包括：

- 自动判分确认（`auto_confirmed`）；
- 教师人工确认（`teacher_confirmed`）；
- 作答修订历史中曾经出现过以上任一状态。

最后一条用于防止先“撤销确认”为待复核、再撤回试卷来绕过限制。撤回请求被拒绝时，试卷、作答和画像均不发生变化，也不执行掌握度或素养分回放。

尚未产生任何确认批改结果的已发布试卷仍可撤回并重新发布。撤回期间，其未确认作答保留用于历史查看和审计，但不参与当前画像。

发布修订版导致旧版本被标记为“已被更新”属于版本替代，不属于教师主动撤回。旧版本的作答会退出当前画像，系统在发布新版本的同一事务中重放画像。

当前有效画像证据仍必须同时满足：

```text
试卷已发布
且试卷未失效
且作答已自动确认或教师确认
```

## 2. 实现调整

- 试卷摘要批量计算 `has_graded_attempts`、`can_withdraw` 和 `withdraw_block_reason`，供列表和详情页统一展示；
- 前端对已批改试卷禁用撤回入口，并说明“该试卷已有批改结果，不能撤回”；
- 后端撤回接口在数据库事务内锁定相关作答，同时检查当前批改状态和完整修订历史；
- 后端校验失败返回 `409 Conflict`，不能依赖前端按钮规避；
- 掌握度、动态素养分和知识点状态继续排除失效版本；
- 历史作答抽屉和批改详情继续使用统一的 `used_in_profile` 口径；
- 未批改试卷撤回、重新发布，以及修订版替代旧版后，仍在同一事务中刷新相关画像。

## 3. 与原方案的关系

2026-11-05 的初版方案允许已批改试卷撤回，并通过全量证据回放使掌握度和素养分退回。2026-11-07 根据教师确认的业务规则，该入口调整为“已批改即不可撤回”。

原有失效证据过滤仍需保留，用于处理：

- 修订版发布后被替代的旧版本；
- 历史环境中已经存在的“失效试卷且已有批改”数据；
- 其他合法产生的失效记录。

因此本次不是删除画像回放能力，而是阻止新的已批改试卷通过“撤回”进入失效状态。

## 4. 数据与验证

本次不删除试卷、提交、作答或修订记录，也不需要数据库结构迁移。撤回权限由现有作答和修订历史实时计算。

验证范围：

- 尚未产生确认批改结果的已发布试卷可撤回、可重新发布；
- 存在当前确认批改结果的试卷无法撤回，接口返回 409；
- 当前状态已回到待复核、但修订历史中存在确认结果的试卷仍无法撤回；
- 被拒绝的撤回不改变知识点掌握度、素养分和知识点状态；
- 已提交版本被新版替代后，旧版本作答仍退出当前画像；
- 批改详情、历史证据接口与画像计算使用相同的 `used_in_profile` 口径。
