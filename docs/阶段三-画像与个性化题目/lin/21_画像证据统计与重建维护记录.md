# 画像证据、统计与重建维护记录

日期：2026-11-09。对应维护讨论中的第1、2、3、6项，题库侧080撤池另见阶段五记录07。本轮不接入视觉模型，不调整动态素养公式和分档参数，不扩展转班、班级生命周期或算法版本管理。

## 1. 当前证据口径

新增 `profile_evidence.py`，集中定义题型范围、作答归属、发布版本有效性、快照完整性、当前修订和确认状态的基础检查，供个人画像、素养评分、知识点状态、学生列表和批改详情共用。

- 日常自动组卷和当前画像支持选择、填空、判断题。
- 有效历史计算题、解答题保留判分结果，以 `unsupported_profile_question_type` 表示不参与当前画像，不视为坏数据。
- 待复核和失效试卷为可解释的排除项；归属错误、无效快照、知识点无法映射和修订缺失仍为异常，重建不能静默跳过。
- 批改详情、历史作答和证据抽屉统一返回是否计入画像及排除原因。
- 周总结中待复核的同组题仍保留为分组事实，不能过滤后仅凭另一道正确题提前标“是”。

## 2. 历史知识点与题库生命周期

掌握度、正确率、知识点状态和周总结来源知识点改用 `PaperInstanceItem.knowledge_point_snapshot` 中保存的正式编码，不再读取题目当前的主知识点解释历史作答。试卷教师视图、学生视图、批改视图和修订版复制也保留该归属。

题目归档只影响后续选题和库存。历史有效作答继续参与画像；即使某章最后一道活动题被归档，已保存的正式知识点目录仍可承载历史证据。题库主知识点编辑只影响之后生成的题目快照。

未知历史编码必须显式诊断。本次没有自动猜测旧编码，没有改写发布快照，也没有新增历史分类纠错界面。确需迁移过去的错误分类时，应另行明确、审核迁移范围并重建受影响画像。

## 3. 学生列表与班级统计

学生列表和详情的 `attempt_count`、`correct_count`、`latest_answered_at` 改为当前有效确认作答口径；新增 `total_attempt_count` 和 `pending_review_count`。历史记录包括已失效、待复核和不参与画像的作答，不能用作正确率分母。

前端分别显示“有效确认作答”“有效确认正确率”“待复核”“历史记录”；无有效确认作答时显示“未评估”。班级异常证据数不把正常失效试卷和不支持画像的题型算作数据损坏。

## 4. 统一画像重建

新增 `scripts.rebuild_profiles`，支持 `--student-code`、`--class-id`、`--all` 三种互斥范围，默认只选择在读学生。指定归档学生会返回明确错误；原 `rebuild_mastery` 委托统一入口，保留命令兼容。

每名学生在独立事务中更新掌握度、素养分和知识点状态。单学生任一步失败全部回滚，其他学生可继续处理；批次存在失败则进程退出码为1。报告包含三类物化结果前后对比、变化组件和失败原因，异常消息附带作答ID。

`--dry-run` 在保存点中执行并回滚，输出预期变化。`--as-of` 统一传递给三类重建，表示基于当前最终修订计算到指定时点，不能当成恢复当时修订状态的历史查询。维护刷新不再先调用素养展示读取，避免重建前读取过期物化结果。

```powershell
docker compose exec -T backend python -m scripts.rebuild_profiles --all --dry-run
docker compose exec -T backend python -m scripts.rebuild_profiles --student-code DEMO-S001 --dry-run
docker compose exec -T backend python -m scripts.rebuild_profiles --class-id <班级UUID> --dry-run
# 核对报告后，确需写回时：
docker compose exec -T backend python -m scripts.rebuild_profiles --all
```
