# 个性化换题审计与班级画像批量查询优化记录

> 记录日期：2026-11-05

## 1. 个性化换题审计

个性化题首次生成时的 `personalized_audit` 继续作为不可变的生成依据，记录素养分、基础星级、题位目标星级、规则版本、生成时间和初始班级复用人数。

首次换题时新增 `initial_selection`，冻结初始题目、初始推荐理由和初始复用人数。每次换题向 `replacement_history` 追加一条记录，包括：

- 换题序号和操作时间；
- 换题前、换题后的题目 ID 与原始题号；
- 本次候选题的推荐理由和理由代码；
- 本次换题保存时该候选题涉及的班级学生数快照。

当前选择审计根级的 `reason_text` 始终保存当前题目的换题理由，不再被旧题理由覆盖。班级复用快照按作业内不同学生去重，并排除失效历史版本，避免同一学生的已发布版和修订草稿被重复计数。

试卷页面分别展示当前推荐理由、初始推荐依据、初始题理由以及逐次换题历史。“初始分配复用”和“换题时复用”明确区分，均不再表述为实时复用人数。

## 2. 班级画像批量查询

班级画像不再逐个学生调用 `load_context()`，而是一次调用 `load_contexts()` 并按原学生顺序组装结果。批量加载覆盖：

- 学生和知识点目录；
- 作答、试卷、提交和当前改判版本；
- 当前知识点回顾状态；
- 动态素养分物化记录。

新增批量素养分入口。物化记录完整时一次查询全班记录并在内存中执行跨日回归；物化记录缺失、过期或规则版本不一致时，也只进行一次批量证据查询，再按学生分别回放，不会退化为逐生查询。

## 3. 验证

- 个性化作业测试覆盖连续两次换题，确认初始审计不变、换题历史只追加、当前理由属于当前题目、每次复用快照独立保存；
- 班级画像测试确认现有 Demo 班的素养物化记录只执行一次查询；
- 冷缓存测试创建 3 名无物化记录学生，确认素养表和回退证据均为批量查询；
- 完整后端测试通过，共 181 项；
- 前端 TypeScript 检查和生产构建通过，仅保留既有 MathLive 分包体积提示。
