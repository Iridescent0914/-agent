# 个性化数据库候选与只读预览实现记录

> 记录日期：2026-11-02  
> 对应拆解：`03_动态素养评分与个性化出题实施拆解.md` 第五部分第二小节  
> 关联记录：`08_动态素养分取整每日维护与题目标签准入记录.md`、`10_个性化固定三星纯选题规则实现记录.md`

## 1. 本次范围

本次把 `10` 中的纯选题规则接到真实数据库读取，但仍保持为独立、只读的服务，不修改现有正式作业创建流程和前端。

服务完成以下链路：

1. 校验教师选择的年级、章节、知识点和主要能力；
2. 从题库装载该精确范围内的未归档题目；
3. 按“可机判且来源已审核”标记候选可用状态；
4. 在同一个 `as_of` 时间点读取每名学生该能力的最新有效素养分；
5. 将内部计算小数统一四舍五入为一个业务整数；
6. 调用固定三星纯选题规则，生成每名学生的三个题位和缺题诊断。

## 2. 数据与评分口径

- 知识点 `core_competencies` 已核对为动态评分八个正式维度的名称，不增加别名映射；
- 主要能力必须属于所选知识点能力集合；
- 知识点必须属于教师选择的章节；
- 候选题必须同时符合年级、章节、知识点范围且未归档；
- 未达到“`grading_readiness=machine_ready` 且 `source_review_status=reviewed`”的题仍保留在诊断总数中，但不能被选中；
- 每批预览只生成一个 `as_of`，所有学生按同一时点取分；
- 分数通过 `effective_literacy_scores()` 读取，能够对物化分数执行跨日回归或在缺少完整物化结果时从有效证据回放；
- 内部小数只在服务内部存在，进入选题边界前通过 `ROUND_HALF_UP` 得到整数；
- 预览输出明确返回 `score_source=computed` 和 `rule_version=literacy-dynamic-v1`；
- 预览不冻结结果、不写数据库；正式创建时仍须重新读取最新分数和重新选题。

例如内部计算结果为 `64.4386` 时，个性化服务只接收 `64`，基础星级为 2，三个目标题位为 `2、3、4` 星，不同时保留 `internal_score` 与 `display_score` 两套业务字段。

## 3. 题目排除与诊断

只读预览支持按学生传入已占用题目 ID，为下一步与必做题、历史回顾题共享去重集合预留接口。

- 每名学生使用自己的排除集合；
- 排除集合不能包含本次预览范围外的学生；
- 被排除题不再进入可用库存；
- 缺题仍沿用 `10` 的逐星级诊断，不跨知识点或星级补题。

## 5. 测试范围

- 数据库候选严格限制到年级、章节和知识点范围；
- 候选可用状态与题库审核、可机判字段完全一致；
- 同一批学生使用完全相同的 `as_of`；
- 内部 `64.4386` 只以业务整数 `64` 进入选题，生成 `2、3、4` 星；
- 当前 Demo 学生的真实有效素养分进入预览后，与评分服务的公开整数结果一致；
- 返回 `computed` 来源和动态评分规则版本；
- 学生级排除题目生效；
- 非法主要能力、跨章节知识点和范围外学生排除配置被拒绝；
- 调用后会话无新增、修改或删除对象，确认预览只读。

## 6. 与前后实现的关系

本次直接复用：

- `08` 的统一整数展示与星级分档口径；
- `08` 的最新有效分数和跨日回归读取能力；
- `10` 的精确三星选题、稳定排序、去重和缺题诊断。

下一步合入统一作业流程时需要：

1. 先选全班统一必做题；
2. 再按学生处理历史回顾题；
3. 把前两部分占用题目传给个性化预览；
4. 正式创建时重新执行上述过程，不复用旧预览；
5. 保存当时使用的整数分、基础星级、主要能力、规则版本、生成时间和 `source_module=personalized`；
6. 创建后保持试卷与审计快照不变，不因学生后续分数变化自动换题。
