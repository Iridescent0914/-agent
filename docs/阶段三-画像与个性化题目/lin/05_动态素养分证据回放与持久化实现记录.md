# 动态素养分证据回放与持久化实现记录

> 记录日期：2026-10-31  
> 对应拆解：`03_动态素养评分与个性化出题实施拆解.md` 第二部分

## 1. 本次范围

本次把纯评分公式扩展为可从真实业务证据确定性回放、可幂等保存的后端服务，暂不切换画像雷达图，也暂不挂接提交和改判事务。

实现内容：

- 新增 `student_literacy_scores` 物化表；
- 新增 `0025` Alembic 迁移；
- 从当前 Attempt、当前 AttemptRevision、Submission、已发布 PaperInstance 和不可变 PaperInstanceItem 快照装载证据；
- 按上海自然日回放 8 种素养分；
- 支持多素养均分、选择题猜测概率、动态学习率、单日 `±8` 限幅和未练回归；
- 新增单学生或全量学生的幂等重建命令；
- 将新表加入业务数据清理白名单；
- 验证改判和重新打开待复核后，重建结果只使用当前最终有效证据。

## 2. 数据结构

每名学生、每种素养保存一条记录：

```text
student_id
literacy_name
score
attempt_count
last_practiced_at
score_as_of_date
rule_version
updated_at
```

约束：

- 主键为 `student_id + literacy_name`；
- `score` 范围为 `0～100`，数据库保留 4 位小数；
- `attempt_count >= 0`；
- 当前规则版本为 `literacy-dynamic-v1`；
- 无有效作答的学生也物化 8 条 60 分、0 次记录。

## 3. 证据口径

进入计算的作答必须同时满足：

- 学生、提交、试卷、试卷题目归属一致；
- 试卷已经发布；
- Attempt 存在与当前 `revision_no` 对应的 AttemptRevision；
- 批改状态为 `auto_confirmed` 或 `teacher_confirmed`；
- `is_correct` 为明确布尔值；
- 发布快照题型为选择、填空或判断；
- 发布快照难度为 `1～5`；
- 发布快照素养属于固定 8 种素养目录。

`needs_review` 不进入评分，但计入待复核数量。其他所有不完整或不一致记录均作为非法证据，使物化重建失败并回滚，防止静默生成错误画像。

历史计算只读取发布快照中的题型、星级和 `core_literacy`。题库当前字段以后发生变化时，不会改写过去作业的评分语义。

## 4. 回放规则

- 以 `Asia/Shanghai` 自然日分组；
- 同日内按 `answered_at + attempt_id` 稳定排序；
- 同题多素养去重后均分权重，每个关联素养的答题次数分别增加 1；
- 当天全部题目处理后，对每种练习过的素养执行净变化 `±8` 限幅；
- 当天未练习的素养向 60 分回归 1%；
- 回放截止日由 `as_of` 明确指定，物化表保存 `score_as_of_date`；
- 同一证据和同一截止日期重复同步时，8 条记录均保持 unchanged。

## 5. 运维命令

预演：

```powershell
docker compose exec backend python -m scripts.rebuild_literacy_scores --all --dry-run
```

写入：

```powershell
docker compose exec backend python -m scripts.rebuild_literacy_scores --all
```

固定验收时间：

```powershell
docker compose exec backend python -m scripts.rebuild_literacy_scores --all `
  --as-of 2026-10-31T12:00:00+08:00 --dry-run
```
