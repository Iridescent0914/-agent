# M2 工作总结与 M3 交接

> 完成日期：2026-09-24  
> 阶段状态：当前仍处于 M2；“学生画像与规则推荐基础”及画像渐进展示调整已完成并通过验收，尚未开始 M3 的正式组卷、教师调整与发布。

## 1. 已完成范围

M2 将 M1 的历史作答转换为可重放、可追溯的考点画像，并实现只读的个性化选题预览。画像只使用 `auto_confirmed` 和 `teacher_confirmed` 的当前 Attempt 结论；主考点、题干、难度和答案来自已发布 `PaperInstanceItem` 快照。

本阶段没有创建新 Assignment 或 PaperInstance，没有实现答题判分、教师改判接口或 OCR。这些仍按 M3、M4、M6 的边界推进。

## 2. 画像计算结果

| 指标 | 结果 |
|---|---:|
| 虚拟学生 | 5 |
| 当前 Attempt / AttemptRevision | 150 / 150 |
| 有效画像证据 | 150 |

| 汇总作答数合计 | 150 |

所有考点从 0.5 开始，以 `alpha=0.2` 按 `(answered_at, attempt_id)` 稳定顺序重放。0 至 2 次证据为 low、3 至 7 次为 medium、8 次及以上为 high；界面将其标为作答证据量，不解释为统计置信概率。零证据考点对外返回 `mastery=null` 和“未评估”。

最近错误窗口为每个考点最后最多 5 次有效作答。关注项至少需要 3 次作答和 2 道不同题；低证据量只提示继续观察，不直接判断明显薄弱。

## 3. 推荐规则

规则版本为 `m2-v1`：

```text
score = 0.40 × weakness
      + 0.25 × recent_wrong
      + 0.20 × difficulty_match
      + 0.15 × review_interval
```

推荐先按章节、可判分状态、教师范围、题型、难度和近期重复过滤，再按得分稳定排序，并限制单一考点占比。同一题不重复，新知识与回顾题量不跨桶补足。候选不足时返回实际题量、缺口、筛选阶段和原因，不扩大教学范围或生成新题。

少于 3 次作答或少于 2 道不同题时使用 `diagnostic` 策略，以教师基础难度选题，不使用内部 0.5 推断能力。`forgetting` 字段在界面解释为回顾间隔，只影响选题优先级，不降低 mastery。

新增 API：


原历史作答接口改为从发布快照读取，并返回 `revision_no`、`used_in_profile` 和排除原因。GET 画像和 POST 推荐预览均为只读；显式重算才写 `StudentMastery`。

## 5. 前端交付

学生详情页现包含“画像 / 历史作答 / 推荐练习”三个视图：

- 画像：默认按现有 M2 规则聚焦最多 5 个薄弱、近期错误或低证据考点；点击重点柱状图联动唯一一张单考点变化曲线；
- 完整画像：全部考点表、逐次作答和最近错误改为按需展开，保留证据量、不同题目数、练习范围、未评估状态和证据回溯，不让画像分析压过推荐主流程；
- 历史作答：服务端分页、正确性及考点筛选，展示当时的题目和考点快照；
- 推荐练习：教师设置范围、题量、题型、难度、近期去重和考点占比，查看分项得分、理由、证据和候选缺口。

图表使用 ECharts。点击曲线点、最近错题或推荐证据会打开作答抽屉，展示历史题目快照、学生答案、当时标准答案、修订号和公式资源。

本次信息架构调整仍属于 M2：只改变画像的默认展示层级，不创建 Assignment、PaperInstance 或正式练习卷，也不修改 EMA、关注项和推荐评分规则。画像采用“重点诊断 → 单考点趋势 → 完整画像按需展开”的渐进展示方式，为 M3 的针对性组卷保留清晰入口。

## 7. M3 可直接使用的输入

M3 应直接调用现有 `preview` / `select_recommendations` 服务，输入教师设置和同一次计算得到的 `ProfileContext`。正式生成草稿时保存：

```text
rule_version、as_of、完整推荐参数
每题 bucket、strategy、score、components、contributions
reason_codes、reason_text、Attempt ID 与 revision_no
候选缺口和筛选诊断
```

创建 `PaperInstanceItem` 时仍从当前 Question 生成题干、选项、答案、判分规则和考点快照。发布后沿用现有数据库触发器保护，不修改旧快照。
