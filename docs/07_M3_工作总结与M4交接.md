# M3 工作总结与 M4 交接

> 完成日期：2026-09-26  
> 阶段状态：M3 个性化组卷、教师调整、发布冻结与版本追溯已实现；尚未开始 M4 的答案录入、判分、人工复核和画像事务重算。

## 1. 已完成范围

M3 将 M2 的只读推荐服务接入正式试卷工作流。教师可以先对多名学生做统一时间基准的只读预检，再在一个事务中创建 Assignment、每名学生的 draft PaperInstance 和题目快照。草稿支持换题、删题、调序；发布时生成全局唯一实例码并冻结。发布后如需改题，通过深拷贝旧快照创建新版本，旧编号继续定位旧版。

本阶段没有创建 Submission 或 Attempt，没有实现答案归一化、判分、改判、打印答题区或 OCR。

## 4. 关键规则

- 同批学生共用一个带时区 `as_of`；
- 预检前后数据库计数不变；
- 正式生成复用 M2 `preview`，不复制打分规则；
- 换题备选复用同一 `score_candidate`，并继续执行范围、题型、难度、近期去重、可判分状态和考点占比限制；
- `avoid_recent_days=0` 表示关闭近期去重；已有集成测试覆盖该边界；
- 草稿每次修改递增 `edit_revision`，陈旧请求返回 409；
- 调序用正偏移两阶段更新，避免非延迟唯一约束冲突；
- 删除后题号压紧为 `1..N`；
- 题量不足或教师删题后发布必须显式确认并保存原因；
- 实例码格式为 `RAT-XXXX-XXXX`，排除易混字符；
- 按码查询只精确返回 published 版本，不重定向最新版；
- 学生视图不返回答案和判分规则；当前 Demo 尚无认证，不能将响应隔离视为完整权限系统。

## 7. M4 可直接使用的输入

M4 创建手工 Submission 前必须：

1. 使用明确 `paper_instance_id`，或先通过 `instance_code` 精确解析；
2. 验证 PaperInstance 为 published；
3. 验证提交学生和 `PaperInstance.student_id` 一致；
4. 按最终 `PaperInstanceItem.order_no` 接收答案；
5. 从 `answer_snapshot` 和 `answer_rule_snapshot` 判分；
6. 从 `exam_point_snapshot.main` 更新画像证据归属；
7. 不回读当前 Question 的答案、题干或考点。

M4 应继续使用现有 Submission、Attempt、AttemptRevision 模型，并在一个事务中完成提交幂等、判分、修订记录和 `persist_mastery` 重算。`needs_review` 在确认前不能影响画像。

## 8. 已知边界

- 当前没有真实教师账户，审计 actor 固定为 `demo_teacher`；
- 当前没有 Class 表，页面按 Student 列表明确提交 student_ids；
- 换题只允许符合原生成条件的备选，不提供越界强制加入；
- M3 不生成 PDF、Word、二维码或统一答题区；
- M3 不允许删除整份已发布试卷；
- 实例码随机碰撞依靠高熵字符集、预查询和数据库唯一约束，实际碰撞概率极低。
