一 系统定位

本系统面向中学数学教师，围绕题目整理、作业设计、纸面作答采集、答案批改和学情分析提供辅助。教师可以从经过审核的题库中组织班级作业，为不同学生安排个性化练习和历史错题回顾；学生完成纸面作业后，系统通过视觉模型提取答案，再由规则判分与文本模型建议辅助教师核对，最终更新学生画像和班级学情。

目前，日常组卷、打印、作答录入、教师复核和画像更新的主要流程已实现。视觉提取和结合题干的答案判断已接入阿里云百炼，并完成少量真实作业试用；模型质量仍需扩大样本验证。批量资料处理已实现候选题提取、整理、查重和逐题审核工作台；批量确认及正式入库事务仍在后续开发范围。

系统首页与各模块可从本地前端入口 http://localhost:5173 进入。

二 系统解决的主要问题

教师日常需要从多份资料中整理题目，按教学进度和学生差异布置练习，再将纸面作答结果转化为可持续使用的学情记录。系统把这些环节连接起来，使题目、作业、作答和画像能够对应到同一条教学记录。

教学环节系统提供的支持
题目准备按年级、章节、知识点和核心素养组织题库，保存题图、参考答案和审核状态
作业设计组合必做题、个性化题和历史回顾题，预览库存缺口并调整草稿
纸面作答采集生成带答题区的学生版试卷，支持多页照片上传、补拍和答案提取
答案批改先使用确定性规则，再对允许范围内的答案提供结合题干的判断建议
学情分析根据有效批改结果更新学生知识点表现、动态素养分和班级统计

当前常规作业流程为：

审核题库 → 教师配置作业 → 逐学生生成试卷 → 打印与作答 → 上传照片或手动录入 → 教师核对批改 → 更新画像 → 安排后续练习。

三 题库与知识标签管理

系统使用统一的数学知识目录组织题目。每道题关联主属知识点，并由目录确定相应的年级、章节和核心素养，减少同一题目在题库、组卷和画像中使用不同标签的情况。当前共享样例题库覆盖“有理数”和“简单的代数式”两个章节，共180组题，其中77组处于可自动组卷状态；这是共享基线，后续可随审核和同步继续扩充。

教师可以筛选、查看和编辑已有题目，包括题干、选项、题图、难度、参考答案及判分规则。多空题按“小题—空位”保存答案；已支持普通文本、数值和可视化公式输入。参考答案经过审核后，符合要求的选择、填空和判断题才能进入日常自动组卷池。

题目内容与答案审核分别保留记录。教师可保存审核草稿、确认入池或撤回修改；题库内容后续变化时，已有试卷仍保留发布时的题目快照，历史作答不会随之被静默替换。

四 分层作业与个性化组卷

普通作业由必做题、个性化题和历史回顾题三个模块组成。教师先选择班级、学生及题目范围，系统预检后显示每名学生的推荐结果和缺题情况，确认后生成草稿。

模块当前组卷方式
必做题按教师指定的年级、章节、知识点、核心素养和难度题量选题，初始作为全班共同练习
个性化题根据学生当前动态素养分和所选知识范围，每人安排3道题；题位按基础星级、再提高一级和两级设置，最高五星
历史回顾题根据教师指定作业中三星及以下的必做错题，安排同知识点、同难度的回顾题，并排除来源试卷中的重复题

系统会显示选题依据和库存不足的具体原因。个性化模块无法凑齐规定题位时阻止创建，教师可以调整范围或补充题库。生成草稿后支持备选换题、删题和调整顺序；发布后如需修改，通过新版本继续处理，保留原有试卷与作答记录。

个性化能力以当前题库库存为基础。系统按学生分别选题，并控制近期重复和班级内题目复用；实际题目差异取决于知识范围、难度和可用库存。

五 独立周总结与持续回顾

系统支持单独创建周总结作业。教师从当前班级近期已全部批改完成的普通作业中选择来源，系统逐学生识别历史回顾中再次答错的知识点，为每个需要回顾的知识点安排两道题。当前周总结使用固定三星题。

知识点回顾标签关联具体作答链路：必做题答错后，历史回顾再次答错，形成“否”标签；周总结中同知识点仍出错，形成“弱”标签。教师可以据此区分需要继续巩固的知识点。没有相应回顾目标的学生会显示无需回顾。

六 学生画像与班级学情

学生画像

学生画像展示历史累计正确率、分知识点正确率、知识点回顾标签和九维动态素养分，并支持与班级平均水平对照。九项素养为抽象能力、运算能力、几何直观、空间观念、推理能力、数据观念、模型观念、应用意识和创新意识。

历史累计正确率覆盖全部年级、章节和作答时间，按已确认的有效题组统计。同一道题的不同次练习分别计入；一次作答经过多次改判，只取当前有效结果。待复核记录不计入答对、答错或分母。多空题仍沿用整题组判定口径。

动态素养分由题目关联素养、难度及有效作答记录计算，作为后续练习安排的参考。无证据维度保留初始化状态，不能解释为已经测得的实际能力。教师确认、修改答案或改判后，系统按当前有效证据更新画像。

班级学情

班级学情页面汇总知识点平均正确率、素养能力平均水平和作业进度。教师可以按班级、年级和章节查看，并进入具体学生进一步分析。暂无有效作答的知识点显示未评估状态，避免将缺少证据误读为零分。

作业进度区分未提交、待复核、已完成及历史版本，帮助教师定位尚未提交或需要人工处理的学生。

七 学生版试卷与答题区打印

系统统一生成一份学生版试卷，前面为题目，后面另页开始答题区。普通作业答题区按必做题、个性化题和历史回顾分块，并依据发布参考答案的小题、空位结构排版，保留原试卷题号。

答题页包含试卷短码、版本、产物标识、页码和定位标记，便于后续照片归属与逐空对应。多页答题区使用保存的页清单，打印内容与识别空位保持关联。教师可通过同一打印入口打印或保存PDF。

八 多页视觉识别与整卷核对

系统已接入阿里云百炼视觉模型，支持多页答题照片上传、缺页检查、补拍和有效页切换。每页识别任务保留状态和调用记录，未变化页面的提取结果可以复用。

视觉模型负责忠实读取学生原写答案，不接收参考答案。提取结果按页、小题和空位组织，区分可读、留白、缺失、不可辨和歧义。教师对照原图核对纸面标识及抄录内容，修正后保存整卷清单，再明确确认录入批改系统。

已经完成少量真实作业的提取与录入试用。对不同笔迹、拍摄角度、分数和涂改的识别质量仍需后续样本验证；目前保留教师核对环节。

九 规则判分与结合题干的答案判断

批改先使用现有规则处理选择、判断、数值及明确的文本匹配。对符合条件的候选答案，系统可以统一发起文本模型判断：读取实际发布题干中的相关条件，标记目标空位，并结合本空参考答案和学生答案，返回“本空可接受”“本空不可接受”或“无法确定”。

例如，标答为“较大”、学生写“大”时，需要依据本空题干判断含义是否一致。模型建议经教师核对、按题确认采用后，系统追加评分修订并更新画像。当前仍保留原有整题组规则：组内任一空明确错误，整题仍为错误。

批改页显示采用建议的具体小题、空号、结论及核对信息；后续产生新修订时，旧采用记录作为历史展示。教师可以查看原始答案、当前评分标准和修订历史，继续人工修正或改判。

十 批量资料处理与题库查重

批量导入模块面向PDF和DOCX教学资料，支持只有题目、题答同文件、题答分文件三种场景。当前内部流程已能够提取候选题、整理资料答案、处理题答对应、关联题图并给出标签建议；只有题目的批次可由教师显式发起答案生成，生成结果保留待核对状态。

候选题先进行批内去重，再与正式题库进行精确匹配和文字相近题召回。页面展示题干、数字、选项和题图差异，教师可保存跳过旧题、保留独立变式或判为无关的决定。候选内容或正式题变化时，旧查重结果会提示过期。相近度用于筛选和排序，不代表重复概率。

逐题审核工作台已接入批量导入页，可查看批次审核概况、筛选候选题，并在“预检与审核”中选择仅题目入库或题目与答案拟直接入池。服务端保存题目与答案审核记录、未认领答案及问题处理决定，并提供只读预检。审核决定与候选版本绑定，内容变化后须重新确认；预检按所选路径列出缺标签、关键题图缺失、查重未完成及答案未审核等阻断或提醒。

该模块目前用于候选题整理和内部审核试验。逐题工作台可保存审核意向，但批量确认及正式入库事务尚待开发；候选题不会由当前入口直接成为正式题库内容。后续正式提交还需在事务中复查题库重复及审核依据。

十一 技术实现与记录保障

层次当前实现
前端交互React、TypeScript、Ant Design；使用ECharts展示画像，支持数学公式显示和输入
后端业务FastAPI与SQLAlchemy，统一处理题库、组卷、提交、审核及画像更新
数据存储PostgreSQL保存题目、试卷快照、作答、模型任务及修订记录；Alembic管理结构升级
模型服务阿里云百炼分别承担资料识别、答题照片提取及文本答案判断，不同任务保留独立记录和配置
运行方式Docker Compose统一运行前端、后端和数据库
验证与评测自动化业务测试、浏览器回归，以及模型结果导出、人工标注和离线核对工具

模型任务保留调用次数、费用估算及超时等状态，并通过版本检查防止旧结果覆盖教师新修改。重复提交和重复采用有相应保护，避免同一次作答被反复计入画像。

协作开发中，题库审核结果可通过共享配置和显式同步工具对齐。代码拉取与数据库同步分开处理，既有历史试卷、作答和画像按各自记录保留。
