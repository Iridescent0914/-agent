# S3：逐空清单与多页合并离线准备记录

日期：2026-11-18。

后续更新：2026-11-19已完成[S3-B固定分页PDF与冻结产物](02_S3固定分页PDF与冻结产物记录.md)。本文保留S3-A交付时的边界；正式产物、持久化和下载以S3-B记录为准，人工试验计划不因此升级为正式产物。

后续照片上传、补拍及有效页管理已在[S3-C记录](03_S3作答照片采集与有效页管理记录.md)实现；本篇模拟响应合并仍是离线基础，尚未与照片集合或模型调用接线。

## 1. 本轮目标和实际状态

后续业务以整份作业为入口：上传答题卡各页，视觉模型逐页提取，按题号与空号合并学生答案，再统一触发规则和必要的文本等价判断。等价判断是整份作业批改的一环，不另建独立答案对试验页面。

本轮完成 S3 的离线准备基础：只读逐空清单、人工指定页面与空位的内部计划、逐页模型请求元数据、模拟结果的覆盖与身份检查、按原卷坐标合并。前次暂停时，新增用例与打印回归共44项通过；本次继续补齐保存/恢复、旧计划结果拒绝、单页及多页检查和阶段记录。

尚未实现新多页上传、打印产物持久化、真实视觉 HTTP、图片并排复核或正式提交。现有 `RecognitionRun` 单图流程继续使用原协议；本轮没有替换其状态或表结构，也没有新增迁移。

## 2. 逐空清单

`inventory_from_snapshots()` 从已发布且当前有效的 `PaperInstance` 和所属题项构建清单；`build_inventory()` 提供只读数据库查询。

- 使用 `PaperInstanceItem.answer_snapshot` 的结构，复用 `answer_subquestions()` 解析旧ID、坐标并检验冲突。只读取标答结构，不输出标答值、别名、规则或解析。
- 保留原卷 `order_no`、小题号、空号、题项ID与 `item_id`。分区取发布时的 `selection_audit.source_module`，不能因必做题、个性化、历史回顾的打印顺序而重新编号。
- 清单按原卷坐标排序；页面清单可以按实际打印位置指定不同顺序，也可以把同一题组的不同空分别放在两页，但一个空不能重复归属。
- 选择空只保留本题实际允许的字母。可以在本地从发布选项或旧题干抽取字母，不把题干、选项正文传给模型，也不默认补成ABCD。
- 人工判分空位标记 `MANUAL_SLOT`，选择字母无法确定时标记 `CHOICE_LABELS_MISSING`。清单保留这些空位和阻断原因，不能静默跳过后声称整卷识别完整。
- 清单生成SHA-256摘要，用于发现计划所依据的结构发生变化；它不是签名，也不替代真实调用前的服务端归属、有效版本和学生状态检查。

当前布局仍为 `answer-card-v2`，所以 `formal_recognition_ready` 固定为 `false`。

## 3. 只读内部接口

```text
GET /api/v1/internal/stage6/paper-instances/{paper_id}/vision-preparation
```

依赖 `APP_ENV=development/test` 和 `STAGE6_ENABLED=true`，沿用阶段六内部访问限制。没有可信教师身份和归属鉴权时，不开放生产入口。

返回 `stage6-vision-inventory-v1` 清单：包含试卷短码/版本、内部空位标识、坐标、分区、允许字母、阻断原因和摘要。不创建任务、不上传文件、不请求模型、不修改判分或画像。

未找到试卷为404；草稿、已失效试卷或非法空位结构为422。包含人工空位或缺失字母时仍可只读查看清单，但下一步构建页面计划会阻断。本轮没有为该接口增加前端按钮。

## 4. 人工页面计划和外发白名单

`PageAssignment` 显式指定每个答题卡页的空位集合，`build_trial_plan()` 校验：

1. 页数为1～100，页码从1连续编号且不重复。
2. 每页至少一个空、至多500个空；页面之间不重叠。
3. 所有页面空位的并集严格等于试卷清单，不能漏空、新增或跳过不支持单元。

输出 `stage6-vision-trial-plan-v1`，用途固定为 `manual_internal_trial`。页与空使用随机不透明令牌；内部映射保留在计划中。

每页 `provider_payload()` 仅输出S0定义的 `stage6-vision-request-v1` 白名单：

```text
schema_version, request_id, page_token, slots
slots: slot_token, order_no, subquestion_no, blank_no, answer_format
选择空额外提供 allowed_option_labels
```

不能把整个内部计划发给模型：内部计划含业务标识和绑定关系。请求元数据不含标准答案、题干、选项正文、学生身份、分区、数据库ID或文件路径。实际图像附件与供应商提示词、超时、费用控制将在后续接线，本轮不发送图片。

计划支持普通 `model_dump_json()` 保存及 `VisionTrialPlan.model_validate_json()` 恢复；导出时保留非选择空不带选项列表的协议约束。必须保存原计划后再核对响应：重新构建会产生新请求/页/空令牌，旧响应不得套用到新计划。

目前页面归属由开发者或教师对照纸面人工指定；页数指这份试验计划中的答题卡页，不应把题目正文页混入。它没有从浏览器实际分页自动生成，也没有证明PDF页上的内容与计划一致，不能代替冻结的正式打印产物。

## 5. 逐页检查和合并

`merge_trial_results()` 只接收调用者明确选出的当前有效页结果。照片上传、重拍历史、有效页选择和并发修订还没有接入；图片摘要由调用方提供，本轮不会打开图片重新计算或验证摘要。

检查内容：

| 情况 | 处理 |
| --- | --- |
| 预期页尚未收到 | `collecting`，列出 `missing_pages`；不生成该页答案，更不补成留白 |
| 页号越界、同页重复结果 | `UNEXPECTED_PAGE` / `DUPLICATE_PAGE`，进入复核，不以最后一条覆盖前一条 |
| 不同页使用相同图片摘要 | `DUPLICATE_IMAGE`，相关页不合并 |
| 请求ID、页令牌不对应，槽位漏返、重复或越界 | `INVALID_PAGE_RESPONSE`，该页不并入完整结果 |
| 短码、版本、页码、总页数有明确不一致 | `PAGE_IDENTITY_MISMATCH`；人工确认不能覆盖明确冲突 |
| 页身份字段无法读取 | `PAGE_IDENTITY_UNCONFIRMED`；仅显式记录核对人与理由后可通过内部归属检查 |
| 页完整但某空为 `missing/illegible/ambiguous` | 保留原识别状态，`SLOT_NEEDS_REVIEW`；不根据高置信度判为可读 |
| 明确 `blank` | 保留留白状态，与整页缺失和无法辨认分别处理 |

复用现有 `parse_vision_response()` 严格校验JSON，包括重复字段、状态与答案的一致性及实际允许的选择字母。

结果按原卷题号、小题号、空号排序，每空保留来源页和图片摘要。分数如 `-1/56` 原样保留，不在抄录环节改写为小数或化简。输入原响应由调用者持有；本轮合并函数没有实现数据库审计或原图存储。

`capture_status=ready` 仅表示这次离线页面集合的结构和识别状态检查通过，不代表模型抄录正确、正式成绩成立或可以自动提交。所有返回均固定 `can_submit=false`、`requires_transcription_confirmation=true`。

## 7. 后续顺序

| 顺序 | 工作 | 完成后具备的能力 |
| --- | --- | --- |
| S3-A（本轮） | 逐空清单、内部页面计划、模拟响应检查与合并 | 不用真实API验证题号/空号和多页边界 |
| S3-B | 正式打印产物及冻结页清单，确定渲染方案；保存PDF/摘要/布局版本，每页标明身份与页码 | 真实照片可以与确定的纸面产物核对；此时再落实 `answer-card-v3` |
| S3-C | 页面集合、图片修订、幂等上传、补拍、有效页选择、过期结果保护与持久化审计 | 实际收齐多页照片；重拍和重试不会覆盖历史或增加作答次数 |
| S3-D | 新协议视觉适配、独立配置、图像规范化、调用次数/费用和未知用量暂停 | 小额接入真实视觉API，按固定版本保存抄录与用量 |
| S3-E / S4 | 原图与逐空文本复核、识别错误反馈及异常提示 | 教师确认识别文本，分别核对识别与等价判断质量 |
| S5 | 整份作业统一调度规则和必要的等价判断，经确认进入原有提交/修订流程 | 正式成绩与画像闭环，保持一组题对应一个Attempt |

S3-A～E是S3内部拆分，不替换原S0～S7编号。等价候选当前仍只开放已支持的受限公式；短文本语义候选与整份作业调度尚未实现，需要在闭环前补齐，不能把现有精确文本未匹配直接视为语义不等价。

现在可以准备去身份化手写样本：三分区、单页/多页、多空、负号和分数、明确留白、涂改、模糊及漏拍；每张图标注来源产物、页号、人工逐空抄录和可读状态。开发样本与后续独立验收样本分开；真实照片放在默认不入Git的受控目录，文档只记样本ID。
