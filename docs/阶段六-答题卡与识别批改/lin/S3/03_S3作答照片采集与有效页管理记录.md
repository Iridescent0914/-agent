# S3-C：学生版试卷作答照片采集与有效页管理

开发日期：2026-11-19。

## 一、使用方式与范围

沿用一份学生版试卷：前面是题目，后面另页开始答题区域。教师正常使用原有“打印 / 保存 PDF”，无需再单独打印答题卡。上传时只收集答题区域的照片，每个答题页一张，保留页眉、页脚和四角标记。

例如整卷前两页是题目，后三页是答题区，这里只要求上传答题页1、2、3；不要求上传两张题目页，也不使用PDF总页码。试卷末尾的答题页页码由S3-B冻结产物决定。

本次完成照片收集与管理，不调用视觉模型，不识别照片中的文字，不执行等价判断，不生成正式作答或成绩。`collected`仅表示每个答题页都有未过期的有效照片。

## 二、教师操作

1. 从试卷详情点击“上传答题照片”，或从批改页点击“管理答题页照片”。阶段六内部功能启用时，进入新的多页照片管理界面。
2. 根据实际纸面页脚选择产物编号，核对学生、试卷短码及版本，再建立照片集合。界面不默认选择最新产物；同一试卷的旧打印产物仍可使用，不会偷偷切换成新产物。
3. 填写核对人与操作原因，一次选择多张JPEG、PNG或WebP照片。逐张预览并指定答题页编号；系统优先按当前缺页给出初始编号，必须人工对照照片确认，不能把文件选择顺序当作已识别的页码。
4. 核对产物编号和答题页编号后上传。已经有有效照片的页面再上传新照片，即为补拍；旧照片和操作记录保留。
5. 每页显示当前有效照片、历史照片和缺页/过期提示。可显式切换回历史照片，也可移除错误归属；移除后该页重新成为缺页。若把同一照片分错页，先移除旧归属，再按正确页码上传该照片。

批量上传按图片逐张提交。中途失败不会回滚已成功的图片；失败及尚未处理的图片继续留在待上传列表，刷新照片集合后可继续提交。恢复历史照片和移除归属同样记录核对人与原因。

页面仍保留“查看原单图识别记录”，供历史流程查看；关闭阶段六内部功能时维持原单图入口。新多页集合不借用旧`RecognitionRun`状态，也不把旧流程的“开始提取”当作多页接入已完成。

## 三、持久化设计

新增迁移`0035_answer_page_collections.py`，依赖S3-B的0034。

| 表 | 用途 |
| --- | --- |
| `answer_page_collections` | 每个冻结打印产物最多一个集合；记录集合修订号及答题页到有效照片的映射 |
| `answer_page_images` | 保存清理元数据并纠正方向后的JPEG、SHA-256、尺寸、字节数、保留截止时间和清理状态 |
| `answer_page_events` | 追加记录上传、补拍、有效照片切换、移除归属及过期照片重新上传；记录前后照片、核对人与原因 |

照片内容使用延迟加载的数据库二进制字段，照片与有效页变更在同一事务提交，避免文件写入成功但数据库保存失败的孤儿文件。列表不加载图片字节；查看图片走限定试卷及产物的专用接口。上传文件名和EXIF身份元数据不写入数据库。

操作记录带集合修订号，数据库唯一约束防止重复修订，并用触发器禁止更新或删除历史事件。照片清理仅清空图片字节，保留哈希、尺寸、映射和操作记录。照片恢复时只允许相同规范化内容复用原照片身份，并追加恢复事件。

内部第一版限制：单图沿用`RECOGNITION_MAX_UPLOAD_BYTES`和`RECOGNITION_MAX_PIXELS`；转码后的字节数也检查。每集合最多500张不同照片、128MiB尚未清理的图片和2000次有效变更。暂不接受多页PDF或一张照片包含多个答题页。

## 四、归属、幂等与并发

- 集合绑定具体`artifact_id`，同时核对纸面产物编号、试卷短码、试卷内容版本。新打印产物不会覆盖旧集合，跨试卷/产物的图片ID无法直接取图或设为有效。
- 这些是人工声明及服务端关系检查。当前尚不能从像素中判断是否拍错学生、旧版或页码；输出`identity_status=manually_assigned_not_model_verified`。S3-D须再校验照片中实际观察到的编号。
- 每个答题页最多一张有效照片。同一规范化图片不能同时占用本集合内两个答题页；这是精确内容去重，不检测不同照片是否拍了同一张纸。
- 当前有效照片重复上传直接复用，不新增照片、修订或事件。旧照片重复上传不会覆盖较新的照片；界面提示使用显式历史切换。
- 对照片的修改按“试卷行→集合行”顺序加锁，并要求`expected_revision_no`。过期页面操作返回冲突，不能覆盖其他窗口刚完成的补拍。重复选择已生效的图片或重复移除空归属为无变化操作。
- 返回`effective_input_sha256`，包含冻结清单哈希、集合修订、逐页有效图片及可用状态。补拍、历史切换、移除和图片过期都会改变后续识别依据。S3-D/E的任务及结果采用必须核对这个指纹；本次尚无识别结果，不宣称已经实现识别任务失效或调度。
- 不为照片补拍建立`Submission`、`Attempt`或判分修订，不触发画像重算。缺页和图片过期都不能变成学生留白或答错。

## 五、状态与图片保留

逐页状态为`missing`、`uploaded`、`expired`。集合状态只有`collecting`与`collected`；还需检查`is_active`才能得到`collection_ready=true`。

`recognition_status`固定为`not_started`，`can_submit`固定为`false`。收齐照片、完成识别、核对抄录、形成成绩是后续不同动作。

照片使用现有`RECOGNITION_RETENTION_DAYS`，当前默认30天。本次收集尚无抄录复核状态，因此不套用旧流程“未复核延长至180天”的机制。界面返回每张照片的保留截止时间；到期立即阻止取图和计为完整，即使定时任务尚未物理清理。`run_file_maintenance`集成清理，重复运行幂等；保留过期状态和历史记录，可重新上传相同内容或重新补拍。

试卷失效或学生停用后仍能查看本集合的历史及保留期内图片，但禁止继续修改或声明可进入识别。重建试卷或选择另一打印产物不会迁移照片。

## 六、接口和代码位置

以下前缀为：

`/api/v1/internal/stage6/paper-instances/{paper_id}/answer-card-artifacts/{artifact_id}/page-collection`

| 方法及后缀 | 用途 |
| --- | --- |
| `POST` 根路径 | 核对纸面编号并幂等创建集合 |
| `GET` 根路径 | 读取集合、缺页、图片元信息及操作历史；尚无集合时返回null |
| `POST /pages/{page_no}/images` | multipart上传照片，附集合修订号、核对人和原因 |
| `PUT /pages/{page_no}/effective-image` | 选择历史照片或以null移除归属 |
| `GET /images/{image_id}` | 返回保留期内的JPEG；校验哈希，禁止缓存，跨范围不可取图 |

所有新接口沿用阶段六门禁：`APP_ENV=development/test`且`STAGE6_ENABLED=true`。核对人仅是审计标签，当前没有新增可信身份认证或多教师授权。模型开关、Key和调用预算与本功能无关。

主要代码：`backend/app/models/answer_pages.py`、`schemas/answer_pages.py`、`services/answer_pages.py`和现有`api/routes/assessment.py`；前端为`AnswerPageCollectionPanel.tsx`，接入原`RecognitionPage.tsx`，批改页补充入口。

## 八、后续S3-D/E

1. 版本化扩展视觉请求/响应协议，校验产物编号、相对答题页码、总页数、短码及版本，不能仅相信上传时的人工声明。
2. 依据冻结页清单和当前有效照片建立任务，持久化调用、用量、失败与重试；补拍后用集合指纹拒绝旧结果。
3. 对每页逐空抄录，保留原始输出、图片依据和可修订的人工抄录；缺页、错码或不清晰阻断完整性确认。
4. 全部有效答题页提取并核对后，再统一走规则与必要的文本等价判断。短文本候选、整卷等价调度和正式采用仍在后续阶段实现。

真实手写样本、模型质量、异常阈值与账单验收均未因本次照片管理完成而通过。
