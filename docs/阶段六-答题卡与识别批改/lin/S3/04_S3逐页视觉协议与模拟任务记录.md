## 一、教师可见流程

学生仍使用一份“题目在前、另页答题区在后”的试卷。本轮不增加打印入口或独立模型试验页面。

在原“上传答题照片”页面核对产物、收齐有效答题页照片后，填写核对人与操作原因，点击新增的“运行模拟提取”。系统为每页建立任务，后台处理后点击“刷新任务”查看结果。可以查看本页记录、取消等待/处理中的任务、重试失败页，或显式重新模拟单页。

模拟适配器只校验图片字节摘要和请求结构，不读取手写答案；所有槽位返回“无法辨认”，所有观察到的纸面身份字段为null。界面明确显示模拟和待核对，不能据此宣布识别成功、计分或质量达标。即使测试适配器返回清晰答案和完全匹配的编号，也保留`synthetic=true`、`needs_review`及`can_submit=false`。

照片收齐、任务处理完成、抄录核对和正式采用继续分开。S3-E尚未实现多页正式合并与人工抄录修订；本轮没有正式提交入口。

## 二、V2协议与外发边界

原S0/S3-A的`stage6-vision-request-v1`和响应解析器保持不变。S3-D新增`schemas/vision_pages.py`及`services/vision_page_protocol.py`，使用独立V2协议。

请求白名单：

| 字段 | 内容 |
| --- | --- |
| `schema_version` | `stage6-vision-request-v2` |
| `request_id` | 此次任务的UUID |
| `page_token` | 冻结页清单中的不透明令牌 |
| `page_size_pt` | 模板画布尺寸 |
| `slots` | 空位令牌、原题号/小题号/空号、答案形式、实际允许的选项字母及作答框坐标 |

图片作为适配器的独立参数传入，不把图片base64写入任务JSON。请求不包含预期试卷短码、版本、产物编号、学生/试卷数据库ID、题干、参考答案、别名、判分规则或解析。预期身份只保存在服务端快照中；未来真实模型须从图片观察编号，不能照抄提示词给出的正确编号。

响应为`stage6-vision-response-v2`，除请求/页令牌与逐空结果，还必须包含七个可空但不可省略的观察字段：

- `artifact_code`、`artifact_revision_no`；
- `instance_code`、`version_no`；
- `layout_version`、`page_no`、`total_pages`。

服务端逐项比较冻结产物：非空字段不匹配即`PAGE_IDENTITY_MISMATCH`；字段为null即身份未确认，不能当作匹配。响应空位集合必须恰好覆盖请求，拒绝缺空、重复、额外空、未知字段、重复JSON键、错误令牌和超出实际字母表的选择答案。清晰项必须有非空文本；留白/模糊等状态不能携带自造答案。文本保留原样，包括负号和分数。

V2校验有限坐标、矩形正方向、模板边界和槽位唯一性。允许模板中的纯空分区说明页有零个槽位，此时仍校验页身份，不伪造作答空；整份产物仍由S3-B生成。模板坐标不等于手机照片像素坐标，本轮没有实现透视校正或裁剪。

## 三、逐页绑定与复用

任务绑定具体冻结产物、清单SHA-256、答题页号、有效照片ID/内容摘要，以及该页最后一次归属操作的修订号。集合全局修订和全局输入指纹另存为建立任务时的审计依据。

采用逐页绑定的原因：补拍第2页只需要重建第2页任务，未变化的第1、3页可以复用。不能因为一个页面补拍就让整份试卷重新调用模型。普通“运行模拟提取”按当前页绑定复用已有最新任务；失败/取消任务不由刷新自动重试，须明确操作。

同一照片先被替换、再切换回来，该页归属修订已变，不会让之前尚在运行的旧租约重新有效。过期图片、移除归属、试卷失效、学生停用、清单变更都使旧结果不可用。

读取列表立即计算`is_current`和`effective_status`，不等后台轮询才提示失效。后台在领取前、响应返回后也检查绑定，旧照片不能开始新调用或覆盖当前页结果。保留旧任务与原始调用便于追溯。后续S3-E整卷合并还必须重新核对集合全局指纹与全部当前页绑定，不能仅以某一页任务完成作为整份答案可用。

## 四、任务、调用与恢复

新增0036迁移，依赖0035：

| 表 | 用途 |
| --- | --- |
| `vision_page_tasks` | 独立逐页任务、不可变输入快照/请求、冻结模型/协议、生成代次、状态修订、重试次数、租约及操作历史 |
| `vision_page_calls` | 每次调用、领取令牌、原始/解析响应、用量、错误、迟到标志和时间 |

不复用等价任务队列或旧`RecognitionRun`单图状态，避免不同任务的worker误领。任务快照、绑定与配置由数据库触发器禁止更新，任务历史禁止删除。

状态为`queued → running → needs_review/failed/stale`，另支持`cancelled`。`needs_review`是模拟调用已返回的状态，不代表真实抄录已确认。调用记录中的`succeeded`仅表示协议及观察到的非空身份未报错，不是识别准确率结论。

领取按“试卷→集合→任务”加锁，短事务内确认图片摘要、预占调用记录及领取令牌。适配器调用时已经关闭worker数据库会话，返回后另开事务保存。后台独立循环使用现有`STAGE6_WORKER_INTERVAL_SECONDS`。

处理超时或进程中断后，可重新领取过期租约；旧调用标记abandoned，后续迟到响应只写回原调用并标late，不能覆盖新领取。取消中的调用返回同样不覆盖取消状态；重复完成回调不改写第一次收到的输出。处理失败保留已收到的原始输出，异常字符串不直接保存或日志输出。响应最多保留262144字符，超长返回失败并记录截断标志。

失败页可在冻结的`max_attempts`范围内显式重试；默认3次，使用既有`STAGE6_MAX_ATTEMPTS`。达到上限或希望检查另一轮结果时，显式rerun生成新任务，记录前驱、核对人与原因；普通刷新不会重跑。每集合最多1000个任务，同一页绑定最多10代，防止内部模拟无限堆积。

## 五、配置及接口

新增配置：

```dotenv
STAGE6_VISION_PROVIDER=fake
STAGE6_VISION_TIMEOUT_SECONDS=45
STAGE6_VISION_LEASE_SECONDS=120
```

租约必须长于超时。沿用`STAGE6_ENABLED=true`及`APP_ENV=development/test`的内部门禁。新增配置均有默认值，本地`.env`无需为了本轮新增Key；仓库示例和Compose已同步，本轮没有修改本地`.env`。

供应商只允许fake。设置其他供应商会阻断建立任务并暂停领取，不能静默降级；不会读取旧`VISION_*`或文本等价模型的供应商/Key。当前不存在HTTP适配器，所以没有真实API、真实Token或账单费用。模拟调用用量标为synthetic和零费用。

以下路径接在S3-C的`.../page-collection`后：

| 方法及后缀 | 用途 |
| --- | --- |
| `POST /vision-tasks` | 核对集合修订/全局指纹、完整性及槽位，幂等建立缺少的当前页任务 |
| `GET /vision-tasks` | 当前任务、历史摘要和模拟配置状态 |
| `GET /vision-tasks/{task_id}` | 限定本试卷/产物的任务快照、结果及逐次调用记录 |
| `POST /vision-tasks/{task_id}/{retry,cancel,rerun}` | 带任务预期修订、核对人与原因的显式操作 |

列表最多返回最近100条历史摘要，当前页任务另行完整返回。图片集合的`recognition_status=tasks_created`只表示存在任务历史，不能解释为识别完成。

核对人仍是审计标签，不能替代多教师身份授权。所有新增API只在内部开发环境开放；后续教师试用仍需落实可信身份与归属授权。
