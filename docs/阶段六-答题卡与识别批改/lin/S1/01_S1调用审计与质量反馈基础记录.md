# S1：调用、审计与逐空质量反馈基础

> 日期：2026-11-18。状态：内部fake基础已实现；真实模型、费用联调及真实质量验收尚未完成。
>
> 前置：[阶段计划](../阶段开发计划.md)、[S0契约](../S0/需求与状态契约.md)。本次没有调用外部模型，没有修改学生最终判分或画像。

## 1. 本次交付与边界

- 新增独立的答案输入版本、等价建议任务、逐次调用审计与人工质量反馈。
- 支持内部创建、查询、重试、取消、显式重跑；后台worker可恢复过期租约。
- 等价fake始终返回`uncertain / unsupported_answer`，明确标记合成结果，不模拟真实数学效果。
- 将S0等价协议与新视觉协议落实为严格运行时校验器；视觉fake只验证槽位协议，不接收或读取图片。
- 给旧`RecognitionItem`补充逐空质量标签；保留原识别值和反馈修订历史。
- 所有新入口默认关闭，仅允许`development/test`环境。`reviewer`是内部审计标签，还不是可信教师身份。

本次提供内部API，没有新增教师页面。S2负责候选范围、规则优先、格式门禁、真实等价供应商与建议展示；S3负责实际图片、多页冻结产物及新视觉协议接线。本次内部fake入口允许显式指定一个短答案单元，不表示这些答案都具备真实模型调用或采用资格。

金额预算、真实HTTP客户端超时、供应商用量及未知费用处理，必须在S2/S3接入真实适配器时完成；本次不提供任何真实供应商执行入口，也不把fake的零费用当作真实费用验收。

## 2. 数据结构与迁移

新增迁移：[0032](../../../../backend/alembic/versions/0032_stage6_assessment_foundation.py)，接续0031，不改阶段四暂存或正式题库数据。

| 表 | 用途 |
| --- | --- |
| `assessment_inputs` | 每个`(paper_instance_item_id, item_id)`的当前内部输入及修订号 |
| `assessment_tasks` | 固定的输入、标答与规则快照、版本、请求、模型配置、结果和操作历史 |
| `assessment_calls` | 每次领取及调用的令牌、原始响应、解析结果、错误、用量、迟到标记和时间 |
| `model_quality_feedback` | 每个目标单元的当前质量反馈及固定原始证据 |
| `model_quality_feedback_revisions` | 追加保存每次反馈的核对人、时间、原因、人工结果与修订号 |

现有`Attempt/AttemptRevision`不拆成逐空作答。S1未增加正式采用入口。新表已加入业务清理脚本白名单；本次没有运行业务清理。

旧识别流程会在重新提取时删除、重建`RecognitionItem`。因此反馈中的旧识别行ID作为历史审计标识保留，不设置阻断其删除的外键；同时固定题项、空号、原识别结果、图片哈希、供应商和模型依据。旧识别行被替换后，已保存的反馈仍可查询并标记输入失效，证据不会改指向新结果。

旧识别结果只有在`ready_for_review/committed`稳定状态下才接受首次核对。整题组不可辨时，无法可靠推出每一空的状态，接口会拒绝猜配；S3再提供真正的逐空识别证据。反馈中的`not_adopted`指反馈修正尚未通过新采用操作生效；旧图片业务是否已提交仍以原`RecognitionRun`及证据中的`legacy_run_status`为准。

## 3. 输入与版本保护

1. 仅接受已发布、有效试卷中的正式题项，题目须已审核且可机判；范围仍为选择、填空、判断。
2. 未提交时，显式输入只保存为内部实验草稿。用`expected_input_revision`保护更改，不创建`Submission`。
3. 已提交时，学生答案从`Attempt`读取，必须提供当前`expected_attempt_revision`，不能另传一段文本冒充正式作答。
4. 有效标答沿用`_initial_grading_reference()`及`_grading_reference()`。内部草稿首次锁定后，不因题库后来修改就静默换标答；S2再增加显式重绑动作。
5. 校对发布空位和有效标答的完整ID、坐标集合；不一致返回`REFERENCE_STRUCTURE_CHANGED`。
6. 服务端快照包含试卷版本、学生归属、原题号、三类来源模块、小题空号、输入/标答哈希、作答修订、协议和模型版本。外发请求只投影该空的一对答案。
7. 输入更改时，旧建议转为`stale`；完成、查询和重试时继续核对有效输入。新提交、教师改判或试卷失效后，旧输出保留审计，不能成为当前建议。

哈希采用`stage6-input-hash-v1`规定的UTF-8、键排序、紧凑JSON，不先把分数、小数或代数式化简为另一种写法。

## 4. 调用、恢复与限制

执行顺序为“短事务领取并提交 → 事务外适配器调用 → 短事务检查版本和令牌并写入”。测试核对适配器执行时不持有任务Session。

- PostgreSQL `FOR UPDATE SKIP LOCKED`防止两个worker领取同一任务。
- `lease_token`与`lease_until`保护归还结果；过期可重领，原调用标记放弃，不删除。
- 旧worker、取消后的响应及失效输入的响应仍归档在原调用，不覆盖当前任务结果。
- 重复执行同一完成动作不覆盖首次收到的原始响应。
- 普通重复创建复用同范围、同输入及同配置任务；失败不会因刷新自动调用。
- 显式`retry`复用任务并新增调用审计；显式`rerun`创建新任务并保存来源与理由。调用次数达到上限即停止，不能抹除旧调用后重新计数。
- 超时、供应商异常、非法JSON、重复JSON键、多余字段、错误请求ID、结论与原因冲突均为任务失败，不映射成学生答错。
- fake用量明确为合成且已知零；旧识别调用没有用量证据时记为`unknown`。

当前适配器只允许fake。超时参数、耗时检查及错误分类已具备；真实调用还必须由其HTTP客户端执行实际超时，并落实金额预算和未知费用停机后才能接线。

## 5. 配置与内部入口

| 配置 | 默认值 | 限制 |
| --- | --- | --- |
| `STAGE6_ENABLED` | `false` | 新建、修改和worker默认关闭；内部历史查询可用 |
| `STAGE6_WORKER_INTERVAL_SECONDS` | 5 | 1～300秒 |
| `STAGE6_TIMEOUT_SECONDS` | 10 | 1～120秒 |
| `STAGE6_LEASE_SECONDS` | 30 | 2～600秒，必须大于超时 |
| `STAGE6_MAX_ATTEMPTS` | 3 | 1～5次/任务 |

这些是内部运行资源限制，不是模型质量阈值或学生低分阈值。S0质量阈值仍保持未定。

需体验时，在本地`.env`显式设`STAGE6_ENABLED=true`，随后按仓库惯例重新创建后端容器；后端启动执行迁移并运行fake worker。不需要API密钥。生产环境即使打开该开关，也拒绝S1入口和worker。

API统一前缀：`/api/v1/internal/stage6`。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /equivalence-tasks` | 创建或复用一个单元的内部任务 |
| `GET /equivalence-tasks?paper_instance_item_id=…` | 必须按题项查询，最多返回最近50条 |
| `GET /equivalence-tasks/{task_id}` | 输入快照、建议、状态和全部调用审计 |
| `POST /equivalence-tasks/{task_id}/retry` | 失败后显式重试，仍受调用次数上限约束 |
| `POST /equivalence-tasks/{task_id}/cancel` | 取消排队或运行中的任务 |
| `POST /equivalence-tasks/{task_id}/rerun` | 对有效的已结束任务显式建立新运行 |
| `GET/PUT /quality-feedback/{target_kind}/{target_id}/{item_id}` | 读取或修订逐空质量反馈 |

`target_kind`为`equivalence`或`recognition`；`target_id`分别为新任务ID或旧识别结果行ID。操作接口提交`{"reason":"具体原因"}`。

未提交试卷的创建请求：

```json
{
  "paper_instance_item_id": "实际试卷题项UUID",
  "item_id": "sub_1.blank_1",
  "student_answer": "2x",
  "expected_input_revision": 0
}
```

首次输入版本为1；修改时传当前版本，内容相同的普通重复请求可直接复用。已提交时省略`student_answer`并传当前`expected_attempt_revision`；单值旧题的单元ID为`answer`，不要猜填`sub_1.blank_1`。

人工反馈示例：

```json
{
  "expected_revision": 0,
  "review_status": "incorrect",
  "error_type": "equivalence_error",
  "gold": {"verdict": "equivalent"},
  "reviewer": "dev-lin",
  "reason": "合成样例核对，仅验证反馈保存"
}
```

`is_error`由服务端派生：未核对/不确定为`null`、正确为`false`、错误为`true`。错误须有适配任务类型的归因及不同于模型结果的人工正确结果；标答问题、输入改变和证据不足使用`uncertain`。更正须携带当前反馈修订号并追加历史。过期结果可针对其原始输入核对，但反馈和人工gold均不改正式作答或画像。

## 7. 验证与已知限制

本次仅使用独立`math_agent_stage6_s1_test`库。验证了空库升级到0032，以及0032回退0031后再次升级；没有在现有业务库执行本次迁移或重评分。测试不启动无关后台worker，不发送真实模型请求。

S1测试涵盖持久化重读、字段白名单、三态响应校验、新旧视觉协议、逐空反馈及历史、输入/作答修订失效、标答结构冲突、锁定标答、租约重领、迟到与重复回写、取消和重跑、调用上限、内部环境门禁，以及任务调用前关闭Session。

独立临时schema中的真实双连接并发测试验证：同输入只生成一个任务；一个任务只被一个worker领取；首次反馈和已有反馈修订都只能成功写入一次，竞争方得到`REVISION_CONFLICT`。该schema由测试创建并在结束时清理。

全库`alembic check`发现四项既有索引元数据差异：`uq_active_published_paper_per_student`、`ix_questions_archived_at`、`ix_recognition_runs_retention_pending`、`ix_students_archived_at`。它们不属于0032，本次没有删除或改写；新增五表另做过滤比较。

测试库题库导入成功，但`prepare_current_demo`在创建个性化三题时因题池不足而退出，事务已回滚。因此不能把完整旧演示业务验收记为本次已通过。实际回归覆盖范围和最终结果见下方验证结论。

**最终验证：90项针对性测试全部通过，其中41项为S1测试。** 同一次运行还回归了清理白名单、答题卡排版、规则判分、答案单元、阶段四S1暂存、健康/迁移版本，以及旧M6解析、选项范围和模拟HTTP适配。新增五表与迁移的过滤比较无差异。`git diff --check`通过。未运行全量业务回归、真实模型评测或前端浏览器验收，本次没有前端页面改动。

尚未完成：真实供应商与账单、可信身份和学校归属授权、教师工作台、真实图片及v3冻结分页、规则候选门禁、正式采用、真实样本质量及阈值验收。
