# S5-A：整卷等价判断调度与教师采用

日期：2026-11-20。

后续变更：用户确认接入题干后，新任务已升级为[S5-B上下文判断](02_结合题干的答案可接受性判断记录.md)。本文中只比较答案对的限制、v2采用策略和零调用统计均属于S5-A当时记录；以S5-B的新协议与策略为准，原有整卷调度、人工确认及事务保护继续复用。

## 本轮范围

承接已完成的S3-E整卷核对录入，在原批改页增加“整卷等价判断”。读取已提交的服务器答案，先逐空运行既有规则，再统一创建必要的等价任务；有效的真实建议经教师按题确认后追加评分修订，并在同一事务刷新画像。手工录入和已核对的图片录入共用这条流程，不另建试验页面。

视觉模型仍只抄录，文本模型每次只接收本空标答、学生答案和无业务含义的协议编号，不接收题干、其他空答案、解析、学情或学生身份。整卷统一调度是后端逐空建任务，继续由现有worker在事务外调用供应商，沿用次数/金额预占、超时、重试和用量未知暂停。

按卷记录识别错误、错误率接受阈值、低正确率异常提示、自动采用及独立真实质量验收继续暂缓。本轮没有调用真实模型，没有用测试向业务库提交答案或改写成绩。

## 候选口径

- 已经规则确认正确、已登记别名、明确数值不等、选项不等及留白继续由规则处理。例如`+30`和`30`不调用模型。
- 新增首批短中文术语候选：填空题`exact`文本未匹配，标答和学生答案均为1～24个汉字，且规则没有额外格式/条件约束。例如“相等/一样”“负/负数”。只是允许请求建议，不预先认定等价，也不自动登记别名。
- 原有受限公式候选继续保留；数值规则已能判断、单位/最简形式约束、条件缺失及超范围写法按既有门禁处理。非中文短术语不在本轮新增范围。
- 图片答案必须先经S3-E逐页核对并录入，或通过既有识别复核。高置信度不能替代核对。
- 等价策略与路由版本升级为v2。旧策略任务保留审计，不作为新版采用依据。

## 调度及版本保护

新增`paper_equivalence.py`服务，提供三个内部接口：

```text
GET  /internal/stage6/paper-instances/{paper_id}/equivalence
POST /internal/stage6/paper-instances/{paper_id}/equivalence-tasks
POST /internal/stage6/paper-instances/{paper_id}/equivalence-adoptions
```

GET仅预检和读取结果，不建任务、不调用模型。预检摘要绑定试卷、已提交作答修订、原始答案、当前有效的冻结标答/规则及候选策略。后续写入必须带相同摘要；改答、人工改判、显式重评分或试卷失效会阻断旧操作。

统一发起复用当前有效任务，包括失败/取消记录，避免普通点击反复付费；重试和显式重跑仍从原有逐题侧栏操作。刷新、轮询和关闭重开抽屉都不创建任务。当前任务完成后可再次检查，无需重新识别照片。

判分读取本次提交锁定的标答，题库后续编辑不会悄悄替换本次依据；只有现有“重新评分”流程才会切换并使旧建议失效。

## 教师采用与画像

采用以题为单位，须覆盖该题全部当前候选空，且全部具有有效、确定的真实建议。模拟、无法确定、迟到、过期、缺少相符成功调用记录，以及已经人工标为错误/无法确定的质量记录均不能采用。其他题无需同时完成，仍可逐题处理。

按学生、试卷及作答加锁后再次核对依据。评分保留学生原始答案、归一化结果及原始规则判定，在`grading_details.equivalence_review`保存所用任务、逐空决定、有效汇总、核对人和原因；追加`AttemptRevision`，任务历史追加`teacher_adopt`事件。再次提交完全相同的操作返回重放结果，不增加修订。

整题汇总沿用原规则：任一空明确错误则整题错误；否则有未解决空则待复核；全部正确才整题正确。因此一空等价不会遮盖另一空数值错误。没有改成按空计算画像，仍是一题组对应一个Attempt。评分修订与统一画像刷新同一事务提交；画像异常时整单回滚。后续改答、重评分和人工改判继续使用原有入口。

本轮复用现有任务和修订表，没有新增迁移，当前迁移仍为0037。

## 前端操作

1. 在批改工作台打开已经录入答案的试卷，点击“整卷等价判断”。
2. 点击“检查或刷新整卷”，查看总空数、候选数、需新建任务数及跳过原因。
3. 填写核对人、原因，点击“统一发起等价判断（调用模型）”并确认本次任务数量和付费说明。模拟模式显示模拟按钮和不可用于正式评分的提示。
4. 页面轮询任务结果。本题全部候选有有效、确定的真实建议后，点击“采用第N题建议”，再次确认后更新评分和画像。
5. 在原批改页查看当前结果、修订历史及最新画像；无法确定的题使用原有人工复核。若提示输入已变化，重新检查，不自动重发调用。

沿用现有`STAGE6_EQUIVALENCE_*`配置，不需要再次填写视觉Key、重拍答题页或重新提取。开发环境后端和前端均挂载源码并自动重载；如页面仍缓存旧版本，可刷新页面，必要时重启对应服务。

## 真实试用：采用按钮禁用原因提示

用户统一判断一次后反馈“采用第N题建议”无法点击。只读核对最近一批任务：第3题共4个短文本候选，4次真实调用均成功，响应结构、版本绑定和调用核验均有效。其中1个“不等价”、2个“等价”，均可作为确定结论；第2小题第4空返回`uncertain/context_required`，表示模型在仅比较答案的条件下需要上下文。

当前按题完整采用，任何候选空无法确定都会阻断该题采用。因此此次禁用符合既有规则，但原提示只泛泛说明条件，没有列出具体空位，用户难以定位。

修复：后端为每个任务增加`adoption_blocker`，明确区分等待、模拟、无法确定、调用核验问题和已有质量核对问题；保留原采用门禁。前端在按钮旁列出阻断的具体小题/空号与原因，同时提示未填写核对人、原因不足或正在处理。兼容旧响应缺少该字段时的原因判断。确定的“不等价”不会被误当作不可采用。

该题仍可在原批改页对照逐空结果进行人工复核，整题最终结果需保留其他空的错误。本轮未重试模型、未修改既有评分或画像，未放宽“无法确定”的采用条件。上述0/20为开发完成时的检查记录；此次用户已真实调用4次，不能将前次零调用状态当作当前状态。

提示修复回归：S5后端19项、桌面/手机浏览器10项及前端构建通过。覆盖具体阻断空位、核对人缺失提示、确定“不等价”允许采用，以及原有完整采用和过期保护；开发记录链接、补丁格式和本地凭据检查通过。
