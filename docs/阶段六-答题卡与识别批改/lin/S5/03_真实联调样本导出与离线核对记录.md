# S5-C：真实联调样本导出与离线核对准备

日期：2026-11-20。承接[S5-B](02_结合题干的答案可接受性判断记录.md)，统一[S0评测口径](../S0/评测标注与验收.md)。本轮为联调准备，不代表真实质量验收完成。

## 实现范围

新增`python -m scripts.evaluate_stage6`，分为只读`export`和纯离线`report`。沿用现有逐页视觉V2和带题干文本V2，不改变批改、画像、任务worker、供应商配置或数据库结构。没有新增前端试验入口，也不调用模型。

`export`按显式指定的试卷导出所有已有任务，包括失败、重试、旧协议与历史任务，避免只挑成功结果。使用数据库只读、可重复读事务，导出冻结请求/结果的哈希、任务/调用ID、供应商版本、调用费用及耗时。视觉内容按冻结槽位令牌映射到原卷小题/空号；文本内容取当时真正外发的题干、标答和学生原答。后续改答及建议采用不改写评测输入。

导出不包含图片、PDF、姓名、学号、解析、当前判分、画像、核对人或原始HTTP响应；也不导出供应商配置和Key。纸面身份只导出校验状态。文件仍含私有作答及题干，仅保存到被Git忽略的`data/uploads/stage6-eval/`。查看原图使用已有前端；原图已清理且无法复核的单元保留未核对。

生成`evidence.json`及`labels.json`。后者所有人工状态均为`pending`、答案/结论均为`null`，不会照抄模型输出、已采用建议或已有修订作为金标准。新目录才允许导出，报告也不覆盖已有文件，避免擦除人工标注。

## 操作方法

先使用现有流程完成小批真实作业。3～5份仅作为开发联调起点，覆盖多页、多空、正负号、分数、留白及涂改，不能据此宣称质量达标。导出已有任务无需重复识别或重新发起判断。

在项目目录运行，将`$paperId`替换为批改页地址中的UUID：

```powershell
$paperId = "从批改页地址复制的试卷UUID"
docker compose exec backend python -m scripts.evaluate_stage6 export --paper-instance-id $paperId --dataset-version stage6-development-v1 --output-dir /app/data/uploads/stage6-eval/run01
```

可以重复传`--paper-instance-id`一次导出多份试卷。每次导出换一个新目录。宿主机文件位于`data/uploads/stage6-eval/run01/`，在IDE打开`labels.json`标注。不要修改`evidence.json`、`sample_id`或`unit_key`；不评测的任务保留在清单中并设`include=false`，不要直接删除。

每条样本可填`capture_tags`记录拍摄条件；`source_group_id`默认按试卷分组。重复答题者须填同一去身份化的`answerer_group_id`，同源试卷或题目变式也应合并来源组。开发集使用`split=development`；独立验收集使用`acceptance`。相同试卷、图片、答题者、来源组或同一题干答案输入不能跨两集。程序只能发现已提供信息中的关联，不能自动识别未填写的同源变式。

视觉样本先不看标答对照原图，按原卷题号和空号定位：

- 样本填写`reviewer_alias`、带时区的`reviewed_at`；核实照片归属后填写`identity_correct`。整页已核对时将样本`annotation_status`改为`labelled`。
- 每个已核对空填写`annotation_status=labelled`、`recognition_status`及忠实原写法`answer`。可辨有内容使用`readable`；明确留白使用`blank`且`answer=null`；不可辨/歧义分别使用`illegible/ambiguous`。未核对留在`pending`，争议填`disputed`。
- `units`中只有稳定空位键；题号及小题/空号在`evidence.json`同名样本的`units`中查找。人工可辨但模型未提取的空也要标注，不能略过。

文本样本依据`evidence.json`中的实际`answer_context`、标答及学生答案独立核对，填写以下字段，保留模板其余字段：

```json
{
  "annotation_status": "labelled",
  "reviewer_alias": "reviewer-01",
  "reviewed_at": "2026-11-20T14:00:00+08:00",
  "gold_verdict": "equivalent",
  "gold_reason": "实际题干已明确比较关系，学生写法保留了本空数学含义。"
}
```

`equivalent / not_equivalent / uncertain`对应本空可接受/不可接受/无法确定。标答疑似错误、题干或图片信息不足时在理由中说明，争议未解决不作为确定真值。不得根据模型建议决定人工标签。

填写后运行离线核对，报告路径也使用新文件名：

```powershell
docker compose exec backend python -m scripts.evaluate_stage6 report --evidence /app/data/uploads/stage6-eval/run01/evidence.json --labels /app/data/uploads/stage6-eval/run01/labels.json --output /app/data/uploads/stage6-eval/run01/report01.json
```

`report`不连接数据库、不读取图片、不访问模型、不保存质量反馈或改判。参数/标注错误返回2；生成报告返回0，表示工具正常完成，不能解释为模型验收通过。终端只输出计数和文件路径，不打印答案或校验异常中的私有字段。

## 统计口径

按任务类型、模型、供应商、提示词、策略、协议、布局及开发/验收划分分别报告，不把不同版本平均成一个准确率。输出任务、来源组、已知答题者、独立图片及试卷数量；零分母的比率为`null`。

| 项目 | 本轮行为 |
| --- | --- |
| 视觉忠实抄录 | 分母为已标注的人工可辨空；失败或无可核验结果计为未正确提取 |
| 抄录规范化 | 仅去空白及将Unicode减号转换为普通减号；不约分、不转小数、不折叠上下标、不使用模型判等价；LaTeX/纯文本分数转换本轮也不默认放行 |
| 状态及漏识 | 状态准确率单独统计；人工可辨而未输出可读内容计入漏识；留白误当有内容、有内容误当留白分别计数 |
| 完整页/整卡 | 模型纸面编号须完整匹配、人工归属确认且所有空为正确可读/明确留白；有不可辨/歧义不算完整页；缺页不能算整卡完整 |
| 重复页任务 | 同一产物同页选择多次提取时，逐任务指标仍展示，整卡标为选择有歧义；用`include=false`明确选定一次整卡试验，避免静默选最佳结果 |
| 文本判断 | 确定结论一致率与确定处理覆盖率分别给分子/分母；错误接受、错误拒绝及对人工uncertain越界给确定结论分别计数 |
| 失败与未核对 | 完成但无可核验结果的真实任务计入已标注样本的失败分母；排队/运行中的未完成任务单列；pending/disputed不进入准确率分母 |
| 旧协议/模拟 | 分别计数并排除新版质量统计；不能用于真实验收 |
| 调用费用 | 所有纳入样本的真实供应商调用含失败、重试、迟到及旧协议调用；去重调用ID，未知费用单列，已知部分是估算而非最终账单 |

已成功结果须有相匹配的成功、非迟到、非模拟调用记录才能用于比较。历史过期任务按冻结输入评测时保留原结果，不用于当前判分。报告只描述此次显式选择的样本；排除任务不表示总体没有错误。

所有报告固定`acceptance_status=not_evaluated`、自动采用错误率为`null`。本轮不实现整卷错误字段、接受阈值、低分异常提示、自动采用及正式验收门槛；人工标注不能回写为业务评分。
