阶段四的配置、PDF处理及费用规则保持原状；阶段六使用独立配置和调用台账。只发送单空标答、学生答案、协议版本和随机request_id，不发送题干、其他空、解析、学生身份或评分规则。建议与质量反馈不改写Attempt、AttemptRevision或画像，视觉模型与自动采用仍按后续阶段实施。

## 本地填写Key与首次运行

`https://dashscope.aliyuncs.com/compatible-mode/v1`是API基础地址，不是浏览器操作页面。程序在其后拼接`/chat/completions`，使用带Bearer鉴权的POST请求。直接用浏览器GET打开无法验证接口可用性。

项目根目录`.env`不入Git；`.env.example`是可提交的空值模板。若本地没有`.env`，从模板复制；如果已经有文件，只编辑阶段六字段，不覆盖已有数据库或阶段四配置。首次内部联调配置如下：

```dotenv
STAGE6_ENABLED=true
STAGE6_EQUIVALENCE_PROVIDER=bailian
STAGE6_EQUIVALENCE_API_KEY=在本地填入你的完整API_Key
STAGE6_EQUIVALENCE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
STAGE6_EQUIVALENCE_MODEL=qwen3.7-flash
STAGE6_TIMEOUT_SECONDS=60
STAGE6_LEASE_SECONDS=90
STAGE6_EQUIVALENCE_MAX_OUTPUT_TOKENS=512
STAGE6_EQUIVALENCE_MAX_CALLS=20
STAGE6_EQUIVALENCE_MAX_BUDGET_CNY=1
```

这里要求北京地域普通按量API Key，不能与其他地域或Coding/Token Plan专用凭证混用。Key不填在前端，也不写进`.env.example`或聊天。实现允许北京DashScope地址或北京业务空间专属地址；暂不支持其他地域，以免误套北京价格。只允许已登记报价的`qwen3.7-flash`、其`2026-07-15`快照和`qwen3.8-flash`；更换模型时需重新评测。模型名和API Key是两项配置，Key不是某一模型专属凭证。

填写后在项目根目录运行：

```powershell
docker compose up -d backend frontend
```

修改`.env`后再次运行同一命令，以重新创建带新环境变量的后端；单独restart不会更新容器环境变量。后端启动会按项目原流程运行已有数据库迁移，本次没有新增迁移。

访问`http://localhost:5173/grading`，选择已发布有效试卷进入批改页，点击题目旁“答案等价建议”。侧栏应显示“文本模型：qwen3.7-flash”。选择一空，先检查是否需要建议，再点击“生成等价建议（调用模型）”。只有候选预检通过才允许创建；前端不会自动调用付费模型。尚未提交的手动答案也可预检；已提交答案必须从服务端读取。

可先在草稿中使用标答`x+x`、学生答案`2x`这类受支持的代数式。纯数字、规则已确定的答案、已经匹配的别名、未核对的OCR输入、已由教师确认的结果或范围外形式不会走模型，这不是接口故障。真实效果须补充不等价、定义域、根号/绝对值等人工标注样本，不应只验证一个可判等价例子。

内部状态页`http://localhost:8000/api/v1/internal/stage6/status`仅检查本地配置并显示累计预算，不触发模型调用；`real_provider_available=true`不表示已验证密钥或网络。正式生产环境仍阻断内部入口。

## 实现与审计

- `equivalence_bailian.py`：受控北京HTTPS目的地址、非思考单次POST、512 Token默认输出上限、JSON Schema、HTTP超时与响应大小上限。无SDK依赖、无自动重试或自动切换模型；HTTP 400/401/403/404/429映射明确错误码，不保存可能回显凭证的供应商错误体。
- `assessment.py`：按供应商、模型、提示词、价格及输出配置去重；创建动作冻结不含Key的配置，不修改原有输入快照或外发白名单。配置变动后旧排队任务失败为`CONFIG_CHANGED`，显式重新运行才创建新配置任务。
- `assessment_worker.py`：按paper→task顺序短事务锁定，并在付费前复核有效输入。HTTP期间不持有数据库会话。使用数据库事务级advisory lock序列化累计预算检查与调用预占，覆盖不同学生及worker。恢复租约时，真实调用用量未知不会自动重发。
- `AssessmentCall.usage`：开始时保存预占费用、价格和公开配置；返回后保存实际Token计数、供应商响应ID、返回模型名及估算费用。费用已知的非法数学JSON仍记录消耗，不当成免费失败。合法响应保留供应商JSON原文语义，去除可选隐藏思考字段，再按既有严格协议校验答案内容。
- 超时、网络异常、服务器错误、超大响应或缺失/非法usage时记录`usage_status=unknown`、费用`null`，暂停后续真实调用。取消、输入失效和迟到结果不能释放尚未确认的消耗；迟到结果只能结算原调用，不覆盖当前建议。重复完成不覆盖第一次记录。
- 侧栏按服务端状态显示模拟/真实模式，并显示累计调用与估算费用。更换模式不会把历史fake结果伪装成真实结果。

使用既有任务/调用表，无新表或迁移。任务公开配置记录在初始`action_history.provider_config`，每次调用另在`usage.provider_config`保留；密钥仅在发送时从后端配置读取，便于本地轮换而不入审计。

## 预算口径与暂停处理

默认20次、1元是**当前数据库内所有百炼等价调用的累计上限**，不是每学生、每任务或每月刷新。失败、取消和重跑均计入调用次数；变更Key、重启进程不会清零。进行中的调用按UTF-8请求字节数加固定余量估算输入上界，加最大输出Token费用预占，已知结果再按Token计数结算。价格按2026-11-18北京短上下文标准价登记，不计免费额度、缓存折扣或批处理；实际账单以阿里云为准。

这只是阶段六等价任务的程序估算检查，不能限制阶段四、其他应用或云资源的账户消费，也不是阿里云的硬停机承诺。余额20元与阶段六1元预算相互独立。

用量未知时保持暂停：先按调用ID、时间和供应商响应ID核对网络/账单，确认是否实际执行，再以审计方式补充结算。当前尚无通用人工结算入口，不应通过删调用行、换Key或把未知写0恢复；发生时须由开发者处理并记录依据。已暂停的任务在核对完成后仍需显式重新运行，不自动补发。累计次数/金额达到上限时，审核已知用量后可提高本地上限，重建后端并显式重新运行。
