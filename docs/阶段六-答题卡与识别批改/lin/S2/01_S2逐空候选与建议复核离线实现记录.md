> 日期：2026-11-18。状态：规则候选、模拟建议和质量反馈页面已实现；真实供应商、金额预算与真实等价质量验收待完成，不代表S2全部验收。

> 前置：[阶段计划](../阶段开发计划.md)、[S0契约](../S0/需求与状态契约.md)、[S1记录](../S1/01_S1调用审计与质量反馈基础记录.md)。

## 1. 本次范围

完成S2可提前进行的两部分：

1. 从人工录入或已经核对的识别文本中，逐空决定是否需要等价建议。
2. 在现有批改页展示运行时答案、三态建议、输入状态、质量反馈及修订历史。

继续使用S1 fake：每次仅返回`uncertain / unsupported_answer`，不执行数学判断。不接入阶段四的付费账号，不上传真实资料，不新增正式采用动作。质量核对不会写入`Attempt/AttemptRevision`或画像；正式教师改判继续使用原有入口。

没有新增数据库表或迁移，继续使用0032。本次修改的是候选领域服务、S1创建入口的服务端门禁，以及批改页的可选侧栏。

## 2. 逐空候选口径

实现：[equivalence_candidates.py](../../../../backend/app/services/equivalence_candidates.py)。

先按现有`grade_answer()`隔离判定当前叶子，沿用参考答案中的匹配类型、归一化规则及已登记别名。一个题组可能因另一空明确错误而整体为错误，这不抹掉当前公式空仍待判断的事实。

| 情况 | 本次处理 |
| --- | --- |
| 规则已匹配，包括别名 | 不创建模型任务 |
| 选择项不同、数值不同、明确格式不符或普通精确文本不同 | 保留规则结果，不创建任务 |
| 留白、非文本、超长或语法不在允许范围 | 人工处理，不猜成表达式 |
| 数值解析失败、符号有理式需定义域复核 | 保持待人工复核，不自动升级为模型候选 |
| 图片答案尚未显式核对 | 先确认或修正抄录；即使置信度为1也不放行 |
| 整题已由教师最终确认 | 不再建立新的建议任务 |
| 填空题、`latex_exact`、原因是`formula_not_exact_match`，且通过形式与约束检查 | 可创建一对答案的模拟建议任务 |

首批表达形式限定为128字符内、有限AST规模的代数式、四则及幂、分式、平方根和绝对值。支持常见括号、隐式乘法及有限的LaTeX命令，例如`\frac`、`\sqrt`、`\left/\right`和`x^{2}`。不支持自然语言、方程、不等式、集合、未知LaTeX命令或任意函数；首批未支持的形式仍交人工处理。

语法检查只用于判定是否在试验范围，**不证明数学等价**，不执行学生表达式。转换后的语法文本不外发、不覆盖原答；实际模型请求保留原写法。`sqrt(x^2)`与`x`即使进入候选，也不能自行假定变量条件而认定等价，未来真实模型应允许无法确定。

对公式匹配未确定、但受限数值规则已经能比较的一对数值，补做数值检查并跳过模型；这里只决定是否需要模型，不借此改写当前正式判分。涉及额外格式要求、禁止分数/小数互换或未知约束时保守阻断，不让模型覆盖格式要求。

## 3. 服务端门禁与版本

- 新增`POST /api/v1/internal/stage6/equivalence-preview`。请求使用现有`CreateAssessmentTask`，返回候选资格、原因、该空标答/学生答案及当前输入、作答版本。
- 预检只读，不创建内部输入、任务、提交或修订；没有通过预检的答案也能展示阻断原因。
- 原`POST /equivalence-tasks`在创建时再次执行同一筛选；直接请求创建不能绕过页面预检。阻断返回`NOT_ELIGIBLE`。
- 已提交文本仍从服务端`Attempt`读取，要求当前修订号；未提交内容只作为内部人工草稿。
- 对图片来源，同时核对`Submission.source`和已有`recognition_reviewed`，不相信客户端声称已经核对。
- 当前路由版本为`stage6-equivalence-routing-v1`；采用依据版本改为`stage6-equivalence-candidates-v1`，将本次候选结论保存于任务快照。
- S1旧策略任务保留审计，但在新策略下读取或返回时标记失效，避免把旧的宽泛内部试验当作经过S2筛选的结果。
- 继续使用S1输入版本、参考答案冻结、结构冲突检查、租约与迟到响应保护。教师最终确认后，旧建议也会失效。

模型请求仍严格只有`schema_version`、不透明`request_id`、`reference_answer`和`student_answer`；不会追加题干、选项内容、学生身份、候选原因、规则或其他空的答案。

## 4. 批改页体验

实现：[EquivalenceReview.tsx](../../../../frontend/src/components/EquivalenceReview.tsx)，接入[PaperGradingPage.tsx](../../../../frontend/src/pages/PaperGradingPage.tsx)。

页面先读取`GET /internal/stage6/status`。只有内部开关启用时，题项卡片才显示“答案等价建议”；默认关闭时沿用现有批改体验。

侧栏操作：

1. 按已有单元ID和原小题/空号选择一空，不重新编号。
2. 点击“检查本空是否需要建议”，查看当前比较答案及阻断/放行原因。
3. 符合范围后显式“生成模拟建议”，后台仍使用S1任务worker。
4. 显示排队、处理中、已返回、失败、取消和失效等状态；运行中短时轮询，关闭侧栏后停止。
5. 选择该空已保存的运行记录，查看**当时**参考答案和学生答案，避免把旧建议误当作当前输入。
6. 填写核对状态、人工正确三态结论或无法确定原因、核对人与理由，保存独立质量反馈；可查看历史修订。
7. 失败可按规则重试，已结束的有效运行可显式重跑，排队或运行中可取消；操作需要理由，沿用S1审计和次数上限。

整题已错但某空仍待判断时，侧栏可以为该空生成建议，整题原有结果不会随模拟建议或质量反馈发生改变。需要最终改判时，教师仍使用原批改按钮；本次没有加入“一键采用”或暗中把逐空建议汇总成整题正确。

## 5. 配置和数据边界

沿用`STAGE6_ENABLED=false`及S1默认资源限制，生产环境拒绝内部入口和worker。开发环境设为`true`并重新创建后端容器后，可在批改页体验模拟侧栏。不需要API密钥。

核对人仍是开发审计标签，未新增可信教师登录或学校授权。真实教师试用前须补齐S0列出的身份和归属要求。

旧内部草稿继续绑定首次锁定的标答。本次没有实现显式切换草稿标答；已提交作答仍通过既有显式重新评分机制切换依据。不要通过更改任务快照来达到“更新标准答案”的目的。

## 6. 验证记录

- [后端S2测试](../../../../backend/tests/test_stage6_s2.py)：规则优先、别名、整组错/单空待定、形式和格式限制、未核对识别文本、预检只读、创建门禁、策略失效、字段白名单及正式数据不变。
- 同时运行S1恢复、并发、反馈及版本保护回归；使用既有`math_agent_stage6_s1_test`隔离库，不在业务库做迁移或重评分。
- [浏览器测试](../../../../frontend/tests/stage6-s2.spec.ts)：使用明确的模拟API，验证桌面及390px下的预检、阻断、建议返回、质量标签、刷新读取、开关和横向溢出。
- 前端执行类型检查及生产构建。

最终结果：**132项后端针对性测试通过，其中42项为新增S2测试；桌面与390px手机共4项浏览器测试通过；前端类型检查、最终生产构建及`git diff --check`通过。** 浏览器还验证保存反馈后重新加载可读取历史记录，过程中未请求正式改判接口。

首轮浏览器回归因测试把Ant Design下拉输入框当作可点击的选择区域，以及误将作业副标题定位为标题而失败。已按项目既有下拉框测试方式修正，最终两端回归通过；这些失败未计入通过结果。


以上为功能验证；fake、合成答案和模拟浏览器API不能替代真实模型效果评测，也不代表真实教师验收。未重复执行此前受个性化题池不足影响的完整演示初始化或全量业务验收。

## 7. 下一步

S2尚需接入具体真实等价供应商，落实独立的密钥、提示词、HTTP超时、调用/金额预算、真实用量和未知费用停机策略；再用人工可靠文本建立开发集及独立验收集，分别记录等价、不等价和条件不足的表现。

仍保持只比较一对答案，不传题干，不复用阶段四识别提示词，不因任务成功或质量标签为正确就自动采用。真实视觉与多页识别属于S3；整体质量统计、学生低分异常和正式采用闭环分别按S4/S5及后续阶段推进。
