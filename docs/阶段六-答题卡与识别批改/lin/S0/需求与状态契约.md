# S0：需求与状态契约

日期：2026-11-18。契约版本：`stage6-contract-v1`。

2026-11-19需求更新以[历史累计正确率与后续视觉任务口径记录](../02_历史累计正确率与视觉识别后续口径记录.md)为准：本轮仅实现画像历史累计正确率；按整卷记录视觉提取错误、质量接受阈值和低正确率异常均暂缓。后续本卷与历史比较均采用题组单位，0.6仅为候选；本文以下早期逐空质量/异常设计属于后续设计输入，未因本轮更新而接入运行时。

后续扩展：2026-11-19的[S3-D记录](../S3/04_S3逐页视觉协议与模拟任务记录.md)新增`stage6-vision-request/response-v2`，用于冻结产物与实际照片的逐页任务，增加观察到的产物编号、产物修订和布局版本。本文及原JSON样例中的V1继续用于S0/S3-A离线契约，不直接替代为新版，也不表示真实视觉模型已接入。

本文件冻结阶段六S1内部开发所需的业务含义、任务边界和检查规则；它是设计契约，尚未接入运行时，不代表模型效果、甲方业务或自动采用已验收。配套文件为[模型协议与样例](模型协议与样例.json)、[评测标注与验收](评测标注与验收.md)、[阈值配置示例](阈值配置示例.json)。

## 1. 首批范围与生效方式

- 使用现有前两章正式题库，沿用选择、填空、判断题的日常题池范围和 `answer-units-v1`。
- 选择、判断和可可靠判定的数值优先走现有规则。等价模型首批处理规则不能可靠判断的代数表达形式；普通文本差异只有在服务端明确列入范围后才可调用，不能把所有 `exact` 不匹配都解释为数学表达式。
- 不处理证明、解题步骤评分、题意理解、新答案生成，也不自动核准题库标答。
- S1～S6的模型结果为建议。人工质量反馈只用于核对与统计；改变学生最终作答或判分必须另外执行明确的采用/改判操作。
- 当前 `Attempt`、`AttemptRevision` 和画像语义保持不变；一个题库题组仍对应一个作答，新增的逐空任务与反馈作为其子记录。
- S7之前禁止模型自动采用。将来自动采用仍须按通过验收的任务范围和版本启用，不能假装为教师确认。

等价模型和视觉模型是两种独立任务，可共用调用基础设施，但分别管理输入、提示词、质量标签和采用资格。

## 2. 单元身份、版本与标答

### 2.1 服务端标识

| 字段 | 含义与约束 |
| --- | --- |
| `paper_instance_id`、`version_no` | 学生实际发布的试卷；不能自动改指向最新卷 |
| `paper_instance_item_id`、`item_id` | 最小答案单元的稳定组合键；不同题组可以有相同的 `item_id` |
| `order_no` | 正文原题号；三类模块的展示排序不改变题号 |
| `subquestion_no`、`blank_no` | 来自发布参考答案结构的小题与空号，不根据文字横线猜测 |
| `source_module` | 发布选题记录中的必做、个性化、历史回顾等；不能读取题库当前必做标记猜模块 |
| `attempt_revision_no` | 已有作答的当前修订号；离线或未提交任务可为空，但须有独立输入版本 |
| `input_revision`、`input_sha256` | 本次学生答案文本或图片集合的固定输入版本与哈希 |
| `reference_source`、`reference_sha256` | 本次实际使用的标答来源及完整标答/规则依据哈希；仅服务端保存 |
| `layout_version`、`print_artifact_id` | 打印布局及具体打印产物；视觉任务必须绑定 |
| `provider`、`model`、`prompt_version`、`policy_version` | 调用与采用依据，均需保存，不能只保存当前配置 |

UUID、数据库主键、教师操作信息和标答版本等属于服务端封套，不进入等价模型输入。模型使用无业务含义的 `request_id`；视觉模型另使用 `page_token` 和 `slot_token`，由服务端映射回真实单元，不能把回显令牌当作模型独立读到了正确页面的证明。

### 2.2 标答绑定

沿用 `_initial_grading_reference()` 与 `_grading_reference()`：首次判分可能锁定题库中当时已审核可机判的答案修订，已有提交可能继续使用其保存的修订或发布快照。不要重新实现一条只取“当前题库最新答案”的模型支路。

创建任务时固定本次标答、规则和学生答案依据。哈希对象的版本记为 `stage6-input-hash-v1`：采用UTF-8、对象键排序、无多余空格的JSON序列化；数组保留确定的单元顺序；输入答案不先执行可能改变语义的数学化简。图片哈希针对服务端规范化后的实际外发图片，同时保存原件哈希。

调用结束和正式采用前分别复检：

1. 试卷、题项和学生归属仍一致，试卷仍为当前允许处理的有效版本。
2. 输入版本、作答修订号、标答依据、打印产物与任务创建时一致。
3. 标答中的单元集合与答题卡槽位集合一致；结构变化不能靠模型补齐。
4. 当前单元未被教师用更新修订处理。

任何一项不一致，旧任务进入 `stale` 或产生采用冲突；保留原输出，不覆盖新答案。仅当前题库又发生修改，不自动废弃已锁定的判分依据；是否切换标答仍由既有显式重新评分动作决定。

## 3. 等价判断协议

协议版本分别为 `stage6-equivalence-request-v1` 与 `stage6-equivalence-response-v1`。首版一个请求只比较一个单元的一对答案，不提前定义无边界的整组比较；后续若引入批量传输，需单独版本化并逐项对齐。

### 3.1 输入白名单

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `schema_version` | 固定字符串 | 请求协议版本 |
| `request_id` | 不透明UUID字符串 | 与响应严格一致，仅用于对齐 |
| `reference_answer` | 非空字符串 | 该单元本次采用的标准答案 |
| `student_answer` | 非空字符串 | 待比较的学生答案；留白不调用模型 |

其他字段一律拒绝。特别禁止题干、选项内容、解析、学生姓名/编号、历史画像、其他单元答案及评分规则。标准答案与学生答案是待比较数据，其中出现的“忽略指令”等内容不能改变任务。

已登记别名先走规则处理；首版只给模型规范标答，不把别名串成含义不明的第三段输入。格式要求在服务端执行，不通过向模型暗加题干来补充。

### 3.2 输出与结论

响应仅含 `schema_version`、原 `request_id`、`verdict`、`reason_code`、`explanation`。`explanation` 为简短核对说明，不要求模型提供隐藏推理过程。

| `verdict` | 允许的 `reason_code` | 含义 |
| --- | --- | --- |
| `equivalent` | `equivalent_form` | 从两个答案本身可确定等价 |
| `not_equivalent` | `different_value_or_expression` | 可确定值或表达式不同 |
| `uncertain` | `context_required`、`unparseable_answer`、`unsupported_answer` | 缺少条件、无法解析或超出任务范围 |

响应字段缺失、多余字段、请求ID不一致、枚举或结论与原因冲突均属于协议失败，不是学生答错。未知供应商响应先保留原文，再按版本解析；不能宽松提取一个“对/错”字样作为正式结果。

### 3.3 调用与采用边界

- 规则已确认正确：不调用模型。
- 可靠的数值不同、选择项不同、明确格式违规：规则结论不被模型覆盖。
- 公式规范化后仍无法可靠判断：可进入等价建议队列。
- 数值解析失败不自动视为表达式可比，须先通过格式和任务范围检查。
- `sqrt(x^2)` 与 `x`、有序答案与集合写法、依赖单位或题意的自然语言等情况，不能自行补充条件；不足以判断时返回 `uncertain`。
- 判定位置为组答案的叶子，不只看整组的 `grade_status`。其他空已错不应抹掉本空待判断和质量反馈的事实。
- 模型“等价”只是一项建议。是否符合已冻结的答题格式、是否具备最终采用资格，仍由服务端检查。

## 4. 视觉识别协议

协议版本为 `stage6-vision-request-v1` 与 `stage6-vision-response-v1`。这是未来S3的新协议设计，不更改现有 `m6-recognition-v1/v2`；新旧适配与存量数据读取在S3明确实现，不能只替换现有版本常量。

### 4.1 逐页输入

JSON元数据仅含 `schema_version`、`request_id`、`page_token`、`slots`；实际图片作为同一次供应商请求的图片附件传入，不把本地路径、私有URL或文件权限凭据写入模型元数据。

每个槽位包含：

- `slot_token`：本页唯一的不透明单元令牌。
- `order_no`、`subquestion_no`、`blank_no`：图片上的原题号、小题号和空号。
- `answer_format`：`choice_letter / true_false_mark / math_or_text`。
- `allowed_option_labels`：仅 `choice_letter` 时存在，为实际允许的选项字母，不默认只有ABCD，不包含选项内容或正确选项。

标准答案、解析、评分规则、学生身份与学情不在白名单。外发图片应只保留必要答题内容；实际姓名等非必要信息先去除。图片规范化、尺寸和资源限额在S1/S3由服务端配置并验证，超限不静默截断。

### 4.2 逐空输出

响应含原请求ID和页令牌、`observed_identity` 及 `answers`。

`observed_identity` 只抄读图片实际显示的 `instance_code`、`version_no`、`page_no`、`total_pages`，无法读取的字段为 `null`，不能从请求令牌推断。服务端与打印产物复核；不可读时需要显式人工确认，不能猜测归属。

每个答案含 `slot_token`、`recognition_status`、`answer`、`confidence`：

| 状态 | `answer` | 含义 |
| --- | --- | --- |
| `readable` | 非空字符串 | 可明确抄录的最终书写；不包含推测补全 |
| `blank` | `null` | 图片中该位置存在且明确留白 |
| `missing` | `null` | 图片未覆盖该槽位，如裁切；与整页尚未上传分别记录 |
| `illegible` | `null` | 位置可见，但无法可靠辨认 |
| `ambiguous` | `null` | 涂改、多种读法等无法唯一确定 |

`confidence` 为 `null` 或0～1之间的数，仅供辅助展示。未经核准的候选读法可留在私有原始响应中，不转成正式 `answer`。

模型须完整返回本页预期令牌集合，不能重复或新增。遗漏、越界、ID不一致或状态与值冲突时，该页校验失败，保留原响应与可查看的部分结果，但不标记为完整成功；不得将漏返回项补成 `blank`。即使完整返回，含 `missing/illegible/ambiguous` 的单元仍需复核。

选择字母只允许明确的全角/大小写归一化，并检查实际允许集合。判断题保留原符号或文字，由后续规则处理；数学抄录允许排版形式转换，不允许化简或替换数值。例如分数转为等价小数仍属于改写，不记为忠实抄录。

## 5. 多页答题卡与冻结产物

### 5.1 内部开发决定

现有 `answer-card-v2` 有短码、版本、原卷题号和续页表头，但没有服务端冻结的页码、总页数与逐页槽位清单。S0不将其宣称为完整多页识别模板。

S3正式多页链路需新增独立的打印产物记录和冻结页清单；布局版本暂定 `answer-card-v3`。具体渲染技术留在S3确定，但以下语义是实现条件：

- 保存可复现的最终PDF、产物哈希、布局版本，以及每页页码、总页数和槽位集合。
- 页码、总页数、短码与试卷版本显示在每页；二维码可以后置。
- 浏览器或渲染器重新分页时产生新的打印产物版本，不能只修改清单或覆盖原PDF；发布试卷快照不改写。
- 首批短答案的一个作答位只属于一页，不跨页拆分；原卷题组跨页时按槽位清单合并。
- 各页槽位集合不交叠，其并集严格等于该打印产物的可处理单元集合。

现有v2或手工制作的页面仅可用于显式标注的内部试验；由人工建立并确认试验页清单，不能据此开放自动采用。不要求先完成v3才能开发S1或开展离线等价试验。

### 5.2 页面集合状态

以下为新领域状态，不能未经迁移直接写入现有 `RecognitionRun.status`：

| `capture_status` | 含义 |
| --- | --- |
| `collecting` | 尚在收集或补拍，页面集合不完整 |
| `needs_review` | 归属不明、重复页或覆盖冲突等待处理 |
| `ready` | 预期页面完整且归属与覆盖检查通过 |
| `cancelled` | 操作员显式取消，不产生最终提交 |

重拍产生新的页面修订；保留原图和历史处理记录，由教师明确选择当前有效页。相同内容重复上传复用已有页；即使图像哈希不同，同页身份重复也不能同时生效。未收到页属于集合层缺页，不能产生该页学生留白结论。

页面身份或槽位变化后，仅复用输入和版本完全相同的页结果。合并后的学生答案仍须通过人工确认及既有提交入口；补拍不创建新的学习次数。

## 6. 调用、反馈与采用状态

### 6.1 通用任务状态

| `task_status` | 进入条件与处理 |
| --- | --- |
| `queued` | 输入及版本已固定，等待领取 |
| `running` | worker领取并持有处理令牌，网络调用在事务外 |
| `succeeded` | 响应和覆盖检查通过；允许业务结论为无法确定，不表示已采用或模型正确 |
| `failed` | 供应商、超时、协议或结构检查失败；记录错误、用量及是否可重试 |
| `cancelled` | 显式取消；迟到响应只保留审计，不采用 |
| `stale` | 输入、有效修订或归属已改变；旧输出保留，不回写 |

合法主路径为 `queued → running → succeeded/failed/stale`；未终结任务可取消。过期运行任务由租约检查后重领并分配新令牌；旧令牌响应不能覆盖新结果。显式重试保留旧调用记录，不能把它擦除后假装首次调用。

调用去重键包含任务类型、实际外发输入哈希、模型/供应商/提示词版本及必要协议依据。不同业务单元即使可复用模型响应，也必须分别做归属与版本检查；反馈和采用不能跨学生复用。

费用未知使用 `usage_status=unknown`，不能记为0。预算不足或用量未知时停止后续真实调用，已有结果保留；阈值是调用前的停机检查，不能保证已发出的单次请求不超估算。具体预算、超时和重试限额在真实接入前配置，避免无界循环。

### 6.2 人工质量反馈

识别和等价反馈分别记录在 `(task_id, paper_instance_item_id, item_id)` 上，保留核对人、时间、理由和反馈修订号。

| `review_status` | `is_error` | 规则 |
| --- | --- | --- |
| `unreviewed` | `null` | 初始状态，没有人工真值 |
| `correct` | `false` | 人工确认模型对其实际输入的处理正确 |
| `incorrect` | `true` | 人工确认模型处理错误，必须有错误类型及正确结果 |
| `uncertain` | `null` | 现有证据不足以给模型定性，记录原因 |

`is_error`是反馈状态的派生展示，不独立接受客户端任意写入。更正反馈须提交预期反馈修订号并追加历史；教师质量核对不自动改变学生作答。

`error_type` 限于 `transcription_error / slot_mismatch / blank_confusion / equivalence_error / reference_issue / input_changed / evidence_insufficient`。前四项可用于确认模型错误；后三项用于问题归因，单独存在时使用 `uncertain`，不能直接计作模型错误。

人工正确结果为识别的“状态＋忠实抄录文本”，或等价判断的“三态结论”；不得写成题库标答。OCR抄错而等价模型正确判断了收到的文本，只记录OCR错误；题库标答有问题先走既有答案审核流程，不把正确响应倒算成模型误判。

### 6.3 采用状态

`adoption_status` 为 `not_adopted / adopted / rejected / superseded`，与任务成功、质量反馈、学生答题正误分别记录。发现模型正确也不意味着必须采用；人工拒绝采用也不自动证明模型错误。

S1/S2的最小接口只保存与查看建议和反馈，不增加绕过教师确认的自动采用入口。后续采用需要明确对象、预期作答修订号、输入和标答版本、动作原因，并生成既有 `AttemptRevision`；同一依据重复采用不增加修订或作答次数。

取消、失效、标答结构变化或归属不符时阻断采用。已采用结果发现错误，通过新的正式修订纠正并重算画像，不删除原任务或旧修订。S7的策略放行及紧急关闭机制另行实现和验收。

## 7. 异常、错误码与阈值

### 7.1 结构阻断与低分提示

以下情况阻断模型结果采用：错短码/版本、缺页、未解决的重复页、槽位缺失/重复/越界、输入失效、标答结构冲突、非法响应、未完成复核或未满足采用策略。不能通过“整体错误率较低”绕过这些检查。

学生作答正确率低只生成 `low_student_correct_rate` 疑似异常。若使用未最终确认的建议计算，命名为“暂估正确率”；显示已判断单元数、总单元数及覆盖率，不把未知项补成错题，不自动改变原图、抄录或标答。

### 7.2 错误返回

建议统一返回 `code`、`message`、`task_id`（可空）、`unit_key`（可空）、`retryable`，必要时附预期版本。错误正文和日志不打印整张图片或学生身份。

| 错误码 | 含义 |
| --- | --- |
| `MODEL_DISABLED`、`CONFIG_INCOMPLETE` | 未启用或真实调用配置不完整 |
| `MODEL_TIMEOUT`、`MODEL_PROVIDER_FAILED` | 网络或供应商失败，不是学生错误 |
| `MODEL_SCHEMA_INVALID` | 字段、版本、枚举或响应请求ID不符 |
| `BUDGET_EXHAUSTED`、`USAGE_UNKNOWN` | 停止后续真实调用，等待处理 |
| `PAPER_IDENTITY_MISMATCH`、`PAGE_IDENTITY_UNCONFIRMED` | 归属矛盾或不可确认 |
| `PAGE_SET_INCOMPLETE`、`DUPLICATE_PAGE` | 页面集合不完整或同页冲突 |
| `SLOT_SET_MISMATCH` | 单元覆盖、唯一性或范围错误 |
| `REFERENCE_STRUCTURE_CHANGED`、`INPUT_STALE` | 标答结构或实际输入已失效 |
| `REVISION_CONFLICT`、`ADOPTION_NOT_ALLOWED` | 并发修订冲突或不具备采用资格 |

### 7.3 阈值状态

[阈值配置示例](阈值配置示例.json)中的质量与低分数值均为 `null`，真实调用和自动采用默认关闭。`null`表示尚未确定，不能按0、无限制或通过处理；零阈值如将来明确填写则是有效业务数值，不能与未设置混淆。

S0只冻结配置字段和统计含义，不预设质量门槛。S6完成样本量、分层质量与复核工作量验收后，才形成具体阈值和可用范围。低分提示、模型质量验收和单次调用预算分别配置。

## 8. 与阶段四的接口边界

本阶段只消费正式审核结果，不修改导入暂存候选、标签或批量提交事务。继续使用正式题型、`machine_ready`、`source_review_status=reviewed`、参考答案/别名及既有判分规则；阶段四是否完成不影响S1及现有题库上的独立试验。

共享代码前需要协作者对齐：答案单元ID稳定性、标答修订锁定方式、正式入库与仅入库状态、标答结构变化时的历史作答处理。当前属于内部交接约束，不表示协作者或甲方已经确认。
