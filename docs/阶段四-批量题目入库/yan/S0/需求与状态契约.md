# S0：批量导入需求与状态契约（试点草案）

更新于 2026-11-13。本文供 S1～S6 使用；S2 采用 Qwen PDF 理解方案。用户已明确的试点决定和开发建议分开标注，尚未经过教师试用验收。

## 1. 试点范围与标签真源

试点先覆盖六年级上册第 1 章“有理数”和第 2 章“简单的代数式”。运行时标签目录是 `data/knowledge_graph_catalog.json`，由仓库根目录《上海市五四制初中数学知识图谱.html》的 `DATA` 与 `SECTION_BY_KP` 导出，包含全部年级、41 章、345 个 KP 的名称、节、素养和课程依据，以及正式题型、难度、必做和图谱九项素养枚举。HTML 只在重新生成目录时读取。前两章 21 个 KP 有现存数据库 code，可用于试点入库；其余 KP 的 `code=null`、`available_for_import=false`，暂不可作为正式题库标签。提交时按 JSON 复核关联标签，并确认所选 KP 在数据库中存在；原 S0 局部快照已移除。

两章共有 10 个节、21 个 KP。HTML 的 21 条映射与两份知识树的 KP 顺序和名称一致，现有 180 道结构化题的节和核心素养字段与各自主属 KP 一致。两份种子树现已为各 KP 写入 `section`；`0026` 补齐 KP 节名，`0027` 检查全库无图谱外旧 KP 并归一题目的章/年级/节，`0028` 归一题目核心素养。后续标签目录直接从全量 JSON 读取，不从 KP code 或历史题目猜标签。JSON 的正式素养与 HTML 的9项名称及顺序一致；“数据意识”仅为图谱解释中的小学对应项，不是正式初中标签。扩大章节范围前仍需分配正式 KP code 并完成种子树和数据库准备。

题型正式值：`choice`、`fill_blank`、`calculation`、`solution`、`true_false`；候选暂存可为 `unknown`，正式建题不得为 `unknown`。难度 1～5 星，参照下表由模型建议、教师核对；同一题型不固定星级，按本年级已学内容、解题路径和思维负担判断。新候选题的 `is_required` 一律初始为 `false`，模型不推荐“必做”；教师可在导入复核时或入库后明确设置哪些题必做，不把资料原有标注自动转换为必做。模型只能推荐白名单 KP code；教师只确认主属 KP，章、节、年级和**完整核心素养集合**由正式 JSON 自动派生，候选中的原始建议可展示作对照但不能独立提交。现有21个可入库 KP 的素养属于正式九项目录；候选与正式题都完整保留 KP 的素养集合，不能静默改名、使用小学标签别名或截掉素养。

| 星级 | 开发用建议参照（待教师用真实题校准） |
| --- | --- |
| 1 星 | 概念辨认、直接计算或直接代入，通常一步完成。 |
| 2 星 | 一个主要知识点的常规应用，需少量连续步骤，方法明显。 |
| 3 星 | 需要选择方法、转换表示或结合本章多个已学知识点，步骤与判断均有一定负担。 |
| 4 星 | 条件较隐含，需多步推理、跨节综合或检验特殊情况，常规套用不足以完成。 |
| 5 星 | 非常规情境或多重约束，需要构造思路、综合论证或较强迁移。 |

这只是 S0 开发参照，不是甲方已验收的评分标准。模型需给出判级理由；教师可逐题改星级，难度不因题干长、含图片或题型为解答题而自动升高。

## 2. 文件与答案

本轮仅开放前两章的正式 KP。S2 验证百炼 Qwen PDF 理解直接切题：PDF 保留私有原件，DOCX 保留原件并转为 PDF；按少量连续页调用模型，保留原始页号和文件哈希。实际使用 Qwen 前须在上传入口明确说明百炼处理，确认资料无学生个人信息并由服务端控制调用。模型不能替代教师确认。

试点资源限额采用开发建议值，S1 已按服务端可配置实现部分预检，S2/S3 用真实批次验证后再调整：单文件不超过 **30 MB**；PDF 每份不超过 **50 页**；DOCX 转换后 PDF 也按 **50 页**控制；每批最多 **2 份文件**（题目文件、可选答案文件）、合计不超过 **60 MB**，最终最多 **200 道候选题**。DOCX 转换失败或转换后超页数须明确拒绝。现有 7 份 PDF 的最大文件约 2.95 MB、最大 36 页，均落在建议范围内。文件数、大小和 PDF 页数在模型任务前预检；切题后超过 200 道时保留诊断但不静默截断或继续自动提交，提示按页/章节拆成新批次。

临时文件策略（2026-11-27 将保留期由 72 小时延长为 7 天，并将试点批次数上限由 30 调为 100）：上传原件、转换后的 PDF 和仅用于预览/模型输入的中间图片，从上传成功时起最多保留 **7 天（168 小时）**；同时最多保留最近 **100 次上传批次**的这些文件，以先达到者为准。超过 100 批时先清理最早的已完成或已取消批次；若 100 批都还在处理/审核，则拒绝下一次上传并提示取消不再使用的旧批次，不静默删除进行中的资料。7 天到期的未完成批次标记过期，提醒重新上传；清理可重试且留审计摘要。优先通过请求内文件数据向 Qwen 提供少量页段 PDF，避免新增第三方持久化文件；模型请求本身的数据保留遵循供应商服务条款，不能由本地清理任务保证。已正式入库题目所引用的图片是题库资产，须与题目一起保留，不受临时文件 7 天规则影响；必要的批次元数据和审核记录可保留，但过期后不能再依赖原文件预览。当前试点代码统一使用 `internal-demo` 工作区计数；多教师场景需按可信服务端身份隔离计数，不能依赖客户端自报 `operator_name`。

| 场景 | 输入 | 答案处理 |
| --- | --- | --- |
| `questions_only` | 题目 PDF/DOCX | 初始缺答案；教师可选择模型生成或手填 |
| `combined` | 题目与答案同一 PDF/DOCX | 提取原文答案并按题号、小题和内容配对 |
| `separate` | 题目文件及答案文件，均可为 PDF/DOCX | 分别解析后依据题号、小题、内容和位置证据配对 |

答案来源为 `source_extracted`、`model_generated`、`teacher_entered`、`missing`。模型生成答案仅适用于 `questions_only`（只有题目文件）批次；`combined` 和 `separate` 批次沿资料答案提取与核对流程，缺失或无法配对时由教师处理，不触发模型生成。生成答案与资料答案作为不同版本保存，不覆盖来源。资料答案提取只取标准答案及定位证据，不提取或存储解题步骤、解析，也不填候选题的 `solution`；源文件仍按原件策略保留供核对。仅资料提取答案可选择独立模型冲突预审，输出 `matched`、`suspect`、`uncertain` 及依据，不能直接改变教师决定；模型生成答案和教师手填答案不再发起二次模型预审，由教师直接核对和确认。题目文字与附图独立提取后再依据来源证据匹配，不在提取时强行绑定。答案或附图没有可靠对应证据时统一放入批末待认领，供教师确认；**不得按顺序猜配**。未归属的答案、图片、疑似漏题不能被静默丢弃。题干依赖的关键图片未归属时，该题不得确认入库。

## 3. 一次操作可完成两项审核

系统仍保留两个独立的校验门槛，但教师可以在**同一张候选题卡片上一次确认**：题目入库审核核对题干、选项、图片、题型、难度、年级、章、主属节、主属 KP、核心素养、必做标记和重复提示；答案入池审核核对选定答案的来源、各小题/空的 `answer-units-v1` 结构、标准答案和判分方式。模型生成、资料提取或预审不能替教师勾选确认。

教师可选两条路径：

1. **确认题目与答案并入池**：教师在工作台逐题核对或选中已核对题目，点击一次明确的提交动作。后端先复检标签、图片、重复、候选版本与答案来源，创建 `Question` 并写入题目审核事件；在**同一数据库事务**内复用现有答案审核服务，以结构化答案、题型、素养、标准答案自判分和审核版本规则晋级，另写答案审核事件。两道门槛均通过，最终 `source_review_status=reviewed`、`grading_readiness=machine_ready`；任一阻断校验失败则该次选中集合不提交，并列出逐题原因，不出现已入池但未入库的中间状态。
2. **仅确认题目并入库**：无答案、答案/图片错配、计算/解答题或教师暂不确认答案时，创建正式 `Question`，`source_review_status=reviewed`、`grading_readiness=raw_answer_only`。后续在现有答案审核页补充或修正答案，再晋级。当前日常自动组卷池只支持 `choice/fill_blank/true_false`。

“一键”指教师在审阅后对选中题目作出一次明确决定，不表示模型替教师自动批准整批。提交前显示可直接入池、仅可入库、重复和待处理数量；不能直接入池的题不会被静默降级为仅入库。答案审核仍沿用 `promote_question` 的校验与审计语义，可由批量导入领域服务在同一事务中调用服务层能力，不通过 HTTP 自调用。

## 4. 状态与阻断规则

批次主状态：`uploaded → parsing → classifying → reviewing → ready_to_commit → importing → completed`；若仍有待认领内容，以 `completed_with_unassigned` 结束。`failed` 记录失败步骤并可从检查点重试；`cancelled` 是显式终止；`partially_reviewed` 表示保存了部分教师决定、尚未可提交。状态迁移由服务端执行，客户端不可任意指定。

候选标签状态：`matched / needs_confirmation / out_of_scope / invalid`。教师决定：`pending / approved / rejected / skipped_duplicate`；提交意向 `commit_intent=library_only / direct_pool`。题答匹配：`not_applicable / matched / uncertain / unmatched / conflict`。重复状态：`none / exact_in_batch / exact_in_catalog / suspected / resolved_variant`。资料答案可选预审：`not_run / matched / suspect / uncertain / failed`；模型生成和教师手填答案保持 `not_run`。待认领项类型：`answer / image / possible_question`，决定：`pending / assigned / ignored / deferred`。教师修改候选后重跑标签一致性和 S4 题库查重；修改后是否与本批其他题重复由教师自行确认。`direct_pool` 提交还须携带与现有 `QuestionReviewRequest` 相同的逐小题/空审核数据，并由服务端认证身份绑定确认动作；仅有模型答案文本或 `selected_answer_id` 不满足入池条件。

阻断题目入库：本批任一候选题缺少完整入库标签、题目或标签未确认、`unknown` 题型、无效难度、KP 不在冻结白名单或数据库中不存在、正式目录缺失该 KP 的章/年级/节/可用素养映射、关键图片缺失、精确重复未跳过、疑似重复未作决定、并发版本冲突。完整入库标签包括正式题型、1～5 星难度、主属 KP 及其派生的章/年级/节/完整素养集合；模型未给出标签时允许教师手工补齐。服务端始终按所选 KP 派生章/年级/节/素养，不接受候选或客户端独立覆写。**答案缺失不阻断仅入题库**，但阻断直接入池。直接入池还须教师明确确认来源与结构化答案，并通过现有晋级规则；低置信配对不能伪装成已确认的资料答案。

建议错误码：`INVALID_FILE`、`FILE_LIMIT_EXCEEDED`、`PARSE_FAILED`、`MODEL_FAILED`、`MODEL_SCHEMA_INVALID`、`TAG_OUT_OF_SCOPE`、`TAG_CONFLICT`、`CONTENT_INCOMPLETE`、`ASSET_UNASSIGNED`、`ANSWER_MATCH_UNCERTAIN`、`EXACT_DUPLICATE`、`DUPLICATE_DECISION_REQUIRED`、`REVISION_CONFLICT`、`CATALOG_CHANGED`、`COMMIT_CONFLICT`、`IDENTITY_REQUIRED`。错误返回含 `code`、`message`、`batch_id`、可选 `item_id`、`retryable`，不把原文件内容放进错误日志。

## 5. 防重复与审计

本次导入任务内部的初次整批去重归 S3；S4 仅对 S3 保留的候选题与正式题库查重。题库内用索引查询规范化题干、选项和关键图片的精确指纹，并以相似度索引召回疑似题，**不逐题遍历整库**。教师修改后使原题库查重结果失效并重查，提交事务内加锁并复查题库重复，防止不同批次并发建题。题库精确重复默认建议跳过并关联旧题；疑似题并排展示，教师确认变式才可独立入库。新答案或图片只形成旧题补充建议，绝不自动合并或覆盖。`exact_in_batch` 保留为 S3/历史状态；教师在 S3 去重后新增或修改题目，由教师自行确认不与本批其他题重复，系统不保证再次发现或阻断。

保存源文件受控引用与 SHA-256、原题号和页/段证据、标签快照哈希、模型与提示词版本、模型原建议、答案来源版本、预审结论、教师修改和决定、重复处理及入库结果。候选题的 `selected_answer_id` 必须指向自身 `answers` 中存在的版本；`catalog_snapshot_sha256` 必须与批次冻结目录一致。字段置信度和证据只能辅助复核，不能当作自动放行条件。文件和模型调用的身份边界须由服务端执行，客户端 `operator_name` 不可充当权限凭据。

## 6. 待甲方确认与后续补测事项

1. 难度表是开发建议，待教师用真实题校准；前两章试点、候选题初始非必做且由教师自行修改、资料无学生个人信息，以及 7 天/100 次临时文件保留是当前已明确的决定。Qwen 是当前技术路线；后续对外试用仍需核对上传入口提示和外发数据范围。
2. 30 MB / 50 PDF 页 / 2 文件 / 200 题为试点建议上限，S2～S3 用真实批次测耗时、容量与切题质量，再决定是否调整；特别补测 DOCX 转 PDF 与扫描件。
3. 已有 `校本/题` 下 7 份 PDF 可直接用于开发测试，其中两组“习题 + 习题解析”可测试分文件配对，例题和《有理数》可测试无答案流程。无需先挑题或标注才能上传测试；只有要统计准确率、做回归对照时，才对选定结果保留人工核对记录。目前没有经确认的扫描页、题答同文件和明确错位答案样本，取得资料后补测。
4. 核对百炼账号可用模型、DOCX 转 PDF 效果、失败重试/费用上限；正式多教师试用前完成服务端身份、批次归属和授权校验。实际外发 PDF 不得包含学生个人信息，若资料情况变化，先处理数据范围。
