# S0：批量导入需求与状态契约（试点草案）

更新于 2026-11-10。本文供 S1～S6 使用；甲方尚未确认的参数见文末，不将草案称为已验收。

## 1. 试点范围与标签真源

试点先覆盖六年级上册第 1 章“有理数”和第 2 章“简单的代数式”。运行时标签目录是 `data/knowledge_graph_catalog.json`，由仓库根目录《上海市五四制初中数学知识图谱.html》的 `DATA` 与 `SECTION_BY_KP` 导出，包含全部年级、41 章、345 个 KP 的名称、节、素养和课程依据，以及正式题型、难度、必做和系统八维素养枚举。HTML 只在重新生成目录时读取。前两章 21 个 KP 有现存数据库 code，可用于试点入库；其余 KP 的 `code=null`、`available_for_import=false`，暂不可作为正式题库标签。提交时按 JSON 复核关联标签，并确认所选 KP 在数据库中存在；原 S0 局部快照已移除。

两章共有 10 个节、21 个 KP。HTML 的 21 条映射与两份知识树的 KP 顺序和名称一致，现有 180 道结构化题的节和核心素养字段与各自主属 KP 一致。两份种子树现已为各 KP 写入 `section`；`0026` 补齐 KP 节名，`0027` 检查全库无图谱外旧 KP 并归一题目的章/年级/节，`0028` 归一题目核心素养。后续标签目录直接从全量 JSON 读取，不从 KP code 或历史题目猜标签。JSON 保留 HTML 的 9 项素养，同时单列当前系统正式八维；试点正式题只接受系统八维，扩大章节范围前需逐章核对并确定差异处理口径。

题型正式值：`choice`、`fill_blank`、`calculation`、`solution`、`true_false`；候选暂存可为 `unknown`，正式建题不得为 `unknown`。难度 1～5 星，`is_required` 须教师确认，未确认默认 `false`。模型只能推荐白名单 KP code；教师只确认主属 KP，章、节、年级和**完整核心素养集合**由正式 JSON 自动派生，候选中的原始建议可展示作对照但不能独立提交。现有 21 个可入库 KP 的素养均属于系统八维；HTML 全量九项与系统八维尚有名称差异，后续章节开放前须确定映射，不能静默改名或截掉素养。

## 2. 文件与答案

| 场景 | 输入 | 答案处理 |
| --- | --- | --- |
| `questions_only` | 题目 PDF/DOCX | 初始缺答案；教师可选择模型生成或手填 |
| `combined` | 题目与答案同一 PDF/DOCX | 提取原文答案并按题号、小题和内容配对 |
| `separate` | 题目文件及答案文件，均可为 PDF/DOCX | 分别解析后依据题号、小题、内容和位置证据配对 |

答案来源为 `source_extracted`、`model_generated`、`teacher_entered`、`missing`。生成答案与资料答案作为不同版本保存，不覆盖来源。可选模型预审输出 `matched`、`suspect`、`uncertain` 及依据，不能直接改变教师决定。分文件答案没有可靠对应证据时，`answer_match_status=unmatched`，放入批末待认领；**不得按顺序猜配**。未归属的答案、图片、疑似漏题可以在批末处理或保留，且不能被静默丢弃。题干依赖的关键图片未归属时，该题不得确认入库。

## 3. 一次操作可完成两项审核

系统仍保留两个独立的校验门槛，但教师可以在**同一张候选题卡片上一次确认**：题目入库审核核对题干、选项、图片、题型、难度、年级、章、主属节、主属 KP、核心素养、必做标记和重复提示；答案入池审核核对选定答案的来源、各小题/空的 `answer-units-v1` 结构、标准答案和判分方式。模型生成、资料提取或预审不能替教师勾选确认。

教师可选两条路径：

1. **确认题目与答案并入池**：教师在工作台逐题核对或选中已核对题目，点击一次明确的提交动作。后端先复检标签、图片、重复、候选版本与答案来源，创建 `Question` 并写入题目审核事件；在**同一数据库事务**内复用现有答案审核服务，以结构化答案、题型、素养、标准答案自判分和审核版本规则晋级，另写答案审核事件。两道门槛均通过，最终 `source_review_status=reviewed`、`grading_readiness=machine_ready`；任一阻断校验失败则该次选中集合不提交，并列出逐题原因，不出现已入池但未入库的中间状态。
2. **仅确认题目并入库**：无答案、答案/图片错配、计算/解答题或教师暂不确认答案时，创建正式 `Question`，`source_review_status=reviewed`、`grading_readiness=raw_answer_only`。后续在现有答案审核页补充或修正答案，再晋级。当前日常自动组卷池只支持 `choice/fill_blank/true_false`。

“一键”指教师在审阅后对选中题目作出一次明确决定，不表示模型替教师自动批准整批。提交前显示可直接入池、仅可入库、重复和待处理数量；不能直接入池的题不会被静默降级为仅入库。答案审核仍沿用 `promote_question` 的校验与审计语义，可由批量导入领域服务在同一事务中调用服务层能力，不通过 HTTP 自调用。

## 4. 状态与阻断规则

批次主状态：`uploaded → parsing → classifying → reviewing → ready_to_commit → importing → completed`；若仍有待认领内容，以 `completed_with_unassigned` 结束。`failed` 记录失败步骤并可从检查点重试；`cancelled` 是显式终止；`partially_reviewed` 表示保存了部分教师决定、尚未可提交。状态迁移由服务端执行，客户端不可任意指定。

候选标签状态：`matched / needs_confirmation / out_of_scope / invalid`。教师决定：`pending / approved / rejected / skipped_duplicate`；提交意向 `commit_intent=library_only / direct_pool`。题答匹配：`not_applicable / matched / uncertain / unmatched / conflict`。重复状态：`none / exact_in_batch / exact_in_catalog / suspected / resolved_variant`。预审：`not_run / matched / suspect / uncertain / failed`。待认领项类型：`answer / image / possible_question`，决定：`pending / assigned / ignored / deferred`。教师修改候选后重跑标签一致性和查重。`direct_pool` 提交还须携带与现有 `QuestionReviewRequest` 相同的逐小题/空审核数据，并由服务端认证身份绑定确认动作；仅有模型答案文本或 `selected_answer_id` 不满足入池条件。

阻断题目入库：题目或标签未确认、`unknown` 题型、无效难度、KP 不在冻结白名单或数据库中不存在、正式目录缺失该 KP 的章/年级/节/可用素养映射、关键图片缺失、精确重复未跳过、疑似重复未作决定、并发版本冲突。服务端始终按所选 KP 派生章/年级/节/素养，不接受候选或客户端独立覆写。**答案缺失不阻断仅入题库**，但阻断直接入池。直接入池还须教师明确确认来源与结构化答案，并通过现有晋级规则；低置信配对不能伪装成已确认的资料答案。

建议错误码：`INVALID_FILE`、`FILE_LIMIT_EXCEEDED`、`PARSE_FAILED`、`MODEL_FAILED`、`MODEL_SCHEMA_INVALID`、`TAG_OUT_OF_SCOPE`、`TAG_CONFLICT`、`CONTENT_INCOMPLETE`、`ASSET_UNASSIGNED`、`ANSWER_MATCH_UNCERTAIN`、`EXACT_DUPLICATE`、`DUPLICATE_DECISION_REQUIRED`、`REVISION_CONFLICT`、`CATALOG_CHANGED`、`COMMIT_CONFLICT`、`IDENTITY_REQUIRED`。错误返回含 `code`、`message`、`batch_id`、可选 `item_id`、`retryable`，不把原文件内容放进错误日志。

## 5. 防重复与审计

批内用规范化题干、选项和关键图片哈希建立指纹表；题库内用索引查询精确哈希，并以相似度索引召回疑似题，**不逐题遍历整库**。教师修改后重查，提交事务内加锁并复查，防止并发双写。精确重复默认跳过并关联旧题；疑似题并排展示，教师确认变式才可独立入库。新答案或图片只形成旧题补充建议，绝不自动合并或覆盖。

保存源文件受控引用与 SHA-256、原题号和页/段/区域证据、标签快照哈希、模型与提示词版本、模型原建议、答案来源版本、预审结论、教师修改和决定、重复处理及入库结果。候选题的 `selected_answer_id` 必须指向自身 `answers` 中存在的版本；`catalog_snapshot_sha256` 必须与批次冻结目录一致。字段置信度和证据只能辅助复核，不能当作自动放行条件。文件和模型调用的身份边界须由服务端执行，客户端 `operator_name` 不可充当权限凭据。
