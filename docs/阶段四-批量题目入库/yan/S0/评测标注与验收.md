## 人工标注方法

1. 标注者打开 `source_file` 原 PDF，以原页为准标出每题的起止位置、跨页关系、题干、选项、图片/公式、题号、小题号；封面、页眉、答案目录和孤立图片另记为非题目或待认领。
2. 分别标出资料答案原文位置及与题目的对应证据。只有题号、小题号、上下文或题意形成可复查的对应关系才填 `gold_answer_match`；对不上写 `unmatched`，不按顺序猜配。模型生成答案须单独核验正确性和来源。
3. 按正式目录选择主属 KP，并核对由 KP 派生的年级、章、节；不能确定时写 `needs_confirmation` 或 `out_of_scope`。题型、1～5 星、核心素养和必做标记分别核验。
4. 记录批内/题库内精确重复与相似变式，标注冲突答案和图片差异；不把新答案或图片并入旧题。
5. 每题至少一名标注者填写，第二名复核有分歧或困难的题，教师裁定最终版本。保留原标注、复核记录和裁定理由。将最终金标准与来源文件的 SHA-256 绑定。

## 当前覆盖与缺口

工作区已有 7 份真实 PDF，包含无答案和两组分文件题答资料，可立即用于试解析。尚未确定哪些页是扫描页，也没有人工复核的题级切题边界、答案配对和 KP 金标准；故 S0 的“≥100 道人工评测集”仍未完成。需要从这 209 页中实际标注不少于 100 道题，并补充题答同文件、明确错位答案和扫描件样本。评测时分开报告“提取正确率”和“与现有题库重复的检出率”，避免旧题同源掩盖提取质量。

后续固定评测报告至少给出：切题正确率、字段完整率、KP Top-1/Top-3 准确率、题答匹配准确率、重复召回率和误报率、教师修改率、耗时及调用成本。先确定标注规则和分母，再设甲方认可的阈值；本阶段不编造指标目标。

## 模型与运行配置待核准

服务端配置应包括 DeepSeek API Key、文本模型名、可用图片模型名、请求超时、每批调用次数上限、每批预算上限、并发数和重试次数。API Key 不进入前端或版本库。PDF/DOCX 在本地解析；只发送必要的文本块和受控裁剪图，按来源记录调用。JSON 响应须经过本仓库 `候选题.schema.json` 和运行时标签白名单双重校验。超时、限流、非法 JSON 或越界标签保留失败项并允许单题重试；预算耗尽则暂停批次并显示原因，不能自动写题库。最终模型和数值限额需在真实账号、样本与费用口径确定后填入服务端配置并验收。
