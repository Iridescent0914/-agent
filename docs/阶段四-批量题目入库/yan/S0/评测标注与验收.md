# S0 评测标注与验收准备

## 标签目录与 S0 辅助文件

| 文件 | 用途 | 现阶段是否必须运行/使用 |
| --- | --- | --- |
| `data/knowledge_graph_catalog.json` | 由 HTML 导出的全量知识图谱和正式题目标签枚举；运行时直接读取，只有带正式 KP code 的前两章可入库 | 是，运行时标签目录 |
| `scripts/export_knowledge_graph_catalog.py` | HTML 或前两章种子树变化时重建全量 JSON；`--check` 检查仓库 JSON 是否过期，并核对候选题 Schema 的素养枚举 | 仅维护标签时运行 |
| `候选题.schema.json` | 描述将来暂存区中一条候选题的字段与状态；模型原始响应还需要 S3 单独的格式 | 否，S1 实现时可用作契约参照 |
| `评测候选清单.csv` | 自动列出 PDF 文件和页码、哈希、文本量及可能的题答文件组；不是题目清单或人工答案 | 否，直接上传 PDF 测试即可 |
| `generate_baseline.py` | 从 PDF 重新生成页级清单 | 否，只有 PDF 来源变化或要重建清单时运行 |

当前种子导入器、题库目录和画像目录已从全量 JSON 读取正式 KP 的主属节与核心素养；阶段四批量导入流水线仍待 S1～S6 实现。空白 CSV 不是已完成的题目提取或评测结果。

简单区分：`候选题.schema.json` 是**未来一条暂存候选题应长什么样**的设计清单，给 S1 数据结构和接口实现作参照；目前没有接入运行时校验，文件里的 `readOnly` 只是说明，仍须由服务端真正执行派生。`评测候选清单.csv` 是**PDF 页码索引**，便于以后按文件哈希和页码找到人工评测样本，不包含已抽出的题。`generate_baseline.py` 只负责**重新生成这份 CSV**；平时直接上传 PDF 做开发测试，三个文件都无需手动运行。若不做页级评测，CSV 和生成脚本可以留作可选资料，不是 S1 的运行依赖。

`评测候选清单.csv` 以工作区 `校本/题` 下 7 份 PDF 为来源，按页建立 209 条候选索引，记录文件 SHA-256、页码、文本层字符数及题答文件配对组。它**不是 209 道题，也不是人工金标准**；`gold_*` 留空、`annotation_status=pending`。开发时可直接把 PDF 交给解析/导入流程，完全不需要先使用这份 CSV。旧 Word 样本与题库现有题同源，只适合回归和查重对照，不作为新 PDF 提取准确率的主评测集。运行 `python docs/阶段四-批量题目入库/yan/S0/generate_baseline.py` 可复现页级清单；正式标注前须复制成独立版本，避免重跑覆盖人工结果。脚本使用本地 `pypdf` 读取文本层，正式解析器选型仍按 S2 验收。

| `有理数.pdf` | 33 | 单文件题目提取；低文本量页面需结合视觉核对 |

PDF 首页可读性抽检与页级统计表明，这 7 份 PDF 均有文本层，但有低文本量页面；文本层不保证公式或图片完整。`L7` 系列的年级和 KP 适用范围须按实际题目与正式目录判断，不能由文件名强行指定。解析文件里也有题干，标注时须区分“答案来源证据”和“新题来源”，避免把解析页重复入库。

## 人工标注方法

1. 标注者打开 `source_file` 原 PDF，以原页为准标出每题的起止位置、跨页关系、题干、选项、图片/公式、题号、小题号；封面、页眉、答案目录和孤立图片另记为非题目或待认领。
2. 分别标出资料答案原文位置及与题目的对应证据。只有题号、小题号、上下文或题意形成可复查的对应关系才填 `gold_answer_match`；对不上写 `unmatched`，不按顺序猜配。模型生成答案须单独核验正确性和来源。
3. 按正式目录选择主属 KP，并核对由 KP 派生的年级、章、节和完整核心素养集合；不能确定时写 `needs_confirmation` 或 `out_of_scope`。题型、1～5 星和必做标记分别核验。
4. 记录批内/题库内精确重复与相似变式，标注冲突答案和图片差异；不把新答案或图片并入旧题。
5. 每题至少一名标注者填写，第二名复核有分歧或困难的题，教师裁定最终版本。保留原标注、复核记录和裁定理由。将最终金标准与来源文件的 SHA-256 绑定。

## 当前覆盖与缺口

工作区已有 7 份真实 PDF，包含无答案和两组分文件题答资料，可直接用于试解析。目前没有已确认的扫描页、题答同文件或明确错位答案样本，也还没有人工复核的题级切题边界、答案配对和 KP 金标准。先开发并用 PDF 观察实际结果；需要量化准确率或固定回归样本时，再选择有代表性的输出做人工核对，不设预先标注数量门槛。缺失场景拿到资料后补测；此前只可用受控合成资料验证程序分支，不能据此报告真实资料准确率。评测时分开报告“提取正确率”和“与现有题库重复的检出率”，避免旧题同源掩盖提取质量。

后续固定评测报告至少给出：切题正确率、字段完整率、KP Top-1/Top-3 准确率、题答匹配准确率、重复召回率和误报率、教师修改率、耗时及调用成本。先确定标注规则和分母，再设甲方认可的阈值；本阶段不编造指标目标。

## 模型与运行配置待核准

服务端配置应包括 DeepSeek API Key、文本模型名、可用图片模型名、请求超时、每批调用次数上限、每批预算上限、并发数和重试次数。API Key 不进入前端或版本库。PDF/DOCX 在本地解析；只发送必要的文本块和受控裁剪图，按来源记录调用。模型原始 JSON 应用 S3 单独定义的提取响应格式校验，再转换成候选题并按 `候选题.schema.json` 和运行时标签白名单校验；该 Schema 含批次 ID、审核状态等系统字段，不能直接要求模型输出。超时、限流、非法 JSON 或越界标签保留失败项并允许单题重试；预算耗尽则暂停批次并显示原因，不能自动写题库。最终模型和数值限额需在真实账号、样本与费用口径确定后填入服务端配置并验收。
