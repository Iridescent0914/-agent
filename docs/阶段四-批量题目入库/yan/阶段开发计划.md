## 一、阶段划分总览

本功能拆分为 7 个开发阶段。各阶段形成可检查的交付物；已明确的契约可支持后续内部开发。缺失样本和甲方未确认口径单独跟踪，在涉及真实模型调用或对外试用前完成相应验收，不把尚无样本的场景伪称已通过。

| 阶段 | 名称 | 核心结果 | 是否可供教师正式使用 |
| --- | --- | --- | --- |
| S0 | 需求与数据契约冻结 | 标签白名单、状态与模型协议、评测方案确定 | 否 |
| S1 | 导入基础设施与暂存区 | 批次、候选题、文件存储和可恢复任务链路可用 | 否 |
| S2 | Qwen PDF 识别与切题 | PDF 直接交给 Qwen；DOCX 保留原件并转 PDF；按页段生成带来源的候选题 | 仅内部测试 |
| S3 | 答案、题图与精准标签治理 | 答案配对/生成/预审、题图保存、KP 建议及质量校验 | 仅内部测试 |
| S4 | 重复题检测 | 索引查询批内和题库内的精确/疑似重复题 | 仅内部测试 |
| S5 | 教师审核工作台 | 教师核对题目、标签和答案，最后处理待认领内容 | 试运行 |
| S6 | 正式入库与验收 | 事务性建题，按教师选择和现有答案校验决定是否入池 | 满足身份和模型评测门槛后试用 |

总体依赖关系：

```text
S0 契约冻结
  ↓
S1 暂存与任务基础
  ↓
S2 Qwen 切题
  ↓
S3 答案、题图与标签
  ↓
S4 重复检测
  ↓
S5 教师审核工作台
  ↓
S6 正式入库与验收
```

S2 的实际模型输出先通过小样本验证，再确定 S3 的题图和答案处理细节；合并验收仍按阶段顺序进行。

## 二、S0：需求与数据契约冻结

> 已形成[需求与状态契约](./S0/需求与状态契约.md)、[候选题 JSON Schema](./S0/候选题.schema.json)、[全量标签目录](../../../data/knowledge_graph_catalog.json)及[评测标注说明](./S0/评测标注与验收.md)。试点仅看前两章，批量导入题默认非必做；难度表和资源上限已有开发建议，临时文件最多保留 72 小时、最近 30 次上传。评测输入使用 `校本/题` 下的 PDF；计划在导入工作台一次确认题目和答案并直接入池。前两章 KP 对章、节、年级和核心素养的关系已接入现有题库，详见[修复记录](./KP主属节映射修复记录.md)。

### 1. 阶段目标

把容易产生返工的业务口径先确定下来，形成前后端、模型和数据库共同遵循的契约。

### 2. 开发内容

- 盘点正式知识点数据，确认首批开放的年级、章、主属节和 KP 范围。
- 冻结当前题型枚举 `choice / fill_blank / calculation / solution / true_false`、HTML 图谱九项核心素养和“新候选题初始非必做、仅教师可修改”的口径；1—5 星先按[需求与状态契约](./S0/需求与状态契约.md)的建议表开发，再由教师用真实题校准。候选可暂存 `unknown`，正式题不可写入。
- 明确标签依赖关系：HTML 是知识图谱编辑来源，运行时读取由它导出的 `data/knowledge_graph_catalog.json`。主属 KP 驱动章、节、年级和完整核心素养集合；只有目录中带正式 KP code 且数据库存在的知识点才可入库。后续章节正式开放前须先分配并导入稳定 code，不能从名称或 code 猜节或素养。
- 定义候选题 JSON Schema，包括题干、选项、答案、解析、图片、标签、证据位置和字段置信度。
- 冻结三种文件场景：只有题目、题目与答案同文件、题目与答案分文件；答案来源区分资料提取、模型生成、教师录入和缺失。
- 明确两项审核门槛及一次操作路径：导入工作台可同时确认题目内容、标签和结构化答案，后端同事务建题并复用现有答案晋级服务，分别留审核事件；仅确认题目者为 `raw_answer_only`，以后再审答案。
- 定义题答匹配、模型预审、教师确认及待认领答案/图片/疑似漏题的状态与审计字段。
- 定义批次状态、候选题标签状态、教师决定状态和错误码。
- 按试点建议定义 PDF/DOCX 文件大小、PDF 及 DOCX 转换后页数和单批题量限制，并在 S2～S3 实测后调整；超限明确拒绝或提示拆分，不静默截断。
- 当前优先验证 Qwen PDF 理解：PDF 原件保持私有；DOCX 转 PDF 并同时保留原件。按小页段提供 PDF 给模型，记录发送范围、模型与调用费用；仅在确认资料不含学生个人信息且上传入口明确说明第三方处理后外发。临时文件按 72 小时且最近 30 次上传清理，正式题图长期保留。
- 核对百炼账号、地域、可用模型和输入方式；测试支持 PDF 理解的 Qwen 模型，服务端校验模型 JSON、页码和来源证据。
- 明确演示与多教师试用边界：当前只有 `operator_name` 字符串，正式多教师试用前须有可信服务端身份与批次归属校验。
- 开发和试解析时直接使用现有 PDF。需要客观计算切题、答案匹配和标签准确率时，再对测试中遇到的部分题目保留人工核对结果（来源位置、题干、答案证据、KP、重复关系）；这不是上传前或 S1 开发前必须完成的步骤，不设固定 100 题门槛。
- 当前已有文本层 PDF、无答案与分文件题答资料。扫描页、题答同文件、明确错位答案等目前没有经确认样本，列为后续补测；在拿到真实样本前可用受控合成资料验证处理逻辑，但不得宣称已验证真实资料的识别效果。

### 3. 阶段交付物

- 《批量导入业务口径说明》；
- 候选题 JSON Schema；
- 状态机和错误码文档；
- 正式标签枚举及知识点范围清单；
- 题级标注规则和逐步扩充的人工复核样本；
- Qwen PDF 理解模型、服务端配置、批次预算和失败处理方案；
- 全量 JSON 中的 KP—章—年级派生规则及多教师试用的身份方案。

### 4. 验收标准

- 同一题目在产品、后端和模型侧使用相同字段定义。
- 模型无法确定 KP 时允许返回 `needs_confirmation` 或 `out_of_scope`，不存在“必须猜一个标签”的要求。
- 章、节、年级和核心素养均由 KP 派生；系统正式素养与 HTML 九项一致，不将“数据意识”当作“数据观念”别名；未分配正式 KP code 的章节仍不开放入库。
- 模型生成答案与资料原答案分开存储；模型预审只提示疑点，不能代替教师确认。
- 已标注样本可回溯原文件，疑难项经过人工复核；未覆盖场景与后续补测时点明确记录。
- 甲方尚未确认的事项被显式列为未决项，不以代码中的临时值代替业务决定。

### 5. 当前复核结论（2026-11-10）

S0 的内部开发输入已齐备：全量 HTML 衍生 JSON、正式 KP 白名单、候选题 Schema、三类文件和答案来源、两项审核与一次确认路径、状态及阻断规则、重复题处理口径，以及可直接试解析的 7 份 PDF。已有数据库按 `0027`、`0028` 校正为“题目只选主属 KP，章、年级、节和完整核心素养集合自动派生”，并拒绝目录外旧 KP；详情见[修复记录](./KP主属节映射修复记录.md)。因此可以开始 S1，不必先手工挑出固定数量的题或等待扫描件样本。

S1 已完成。1～5 星建议表待教师用真实题校准；30 MB、50 PDF 页、2 文件、200 题的试点限额在 S2/S3 实测后可调整，DOCX 转换后同样按 50 页控制。Qwen 账号能力、模型费用预算与多教师可信身份仍需在真实调用或对外试用前落实。题目资料必须不含学生个人信息，且上传入口须告知将发送给百炼。扫描页、题答同文件和明确错位答案收到样本后补测，现有 PDF 不作为这些场景已验收的证据。

## 四、S2：Qwen PDF 识别与切题

### 1. 阶段目标

在现有 S1 上传和批次任务上，用 Qwen PDF 理解直接识别数学题、公式和图形关系，生成带原文件页码的候选题。S2 只供内部测试，模型结果不能直接入库。

### 2. 开发内容

- PDF 保留原件；DOCX 保留原件，并通过 LibreOffice 无界面转换为 PDF。检查转换成功、页数和公式/图片可见性；失败时明确报错，不把缺图的文本当成完整题目。
- 将 PDF 按可配置的少量连续页拆成处理单元，只在每段后方保留跨页所需的重叠页。页号映射回原文件；合并输出时去重。避免一次请求要求模型返回整份长卷，也减少重复发送的页数。
- 默认使用百炼支持 PDF 理解的 `qwen3.8-flash`；模型名、地域、接口地址、超时、并发、调用次数和批次预算由服务端配置。用私有 PDF 的请求内数据传输，不公开源文件 URL；若输入上限不满足则提示拆分。
- 要求模型返回题号、题干、公式、选项、子题、题图线索、来源页，以及无法确定的片段。新批次还提供预提取位图清单与页预览，让模型在同一次调用中引用已有题图或给出缺图坐标及所属题目；服务端验证后裁剪。输出使用单独的模型响应 Schema 校验，再映射为现有候选题 Schema；不得让模型填写批次 ID、教师决定或 `is_required=true`。
- 核对每个处理单元是否完成、输出是否截断、页码是否存在、候选数是否超过试点上限；失败单元可重试，未确认的文字或图片保留待处理，不静默丢题。
- 保存模型、提示词/Schema 版本、来源文件哈希、处理页段、耗时和用量摘要；原 PDF/DOCX 与中间 PDF 遵循临时文件清理规则。文档内容按不可信输入处理。
- 用现有真实 PDF 和 DOCX 选取代表性题目建立人工核对小样本，记录漏题、公式、题图、跨页、耗时及成本；先验证直接 PDF 理解，再决定是否需要 Parse/OCR。

接口依据：[百炼 PDF 理解](https://help.aliyun.com/zh/model-studio/pdf-understanding)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。官方支持 PDF 输入仅证明接口可用，准确率须以本项目样本实测为准。

### 3. 阶段交付物

- DOCX 转 PDF 与 PDF 页段处理服务；
- Qwen PDF 理解调用、响应校验与可恢复批次任务；
- 候选题及来源页证据、待处理内容；
- 真实样本质量、耗时和费用记录。

### 4. 验收标准

- PDF 和转换成功的 DOCX 可生成待审核候选，并能定位回原件页码；图形、公式和原题视觉内容保留可复核途径。
- 不可靠页码、跨页重复、空响应、截断或超预算不会静默入库；批次可显示具体失败单元。
- 题级人工样本能报告切题完整率、公式准确率和题图关联情况；未拿到真实扫描样本时不声称扫描件已验收。
- fake provider 仍仅供测试，与真实 Qwen 结果明确区分。

## 五、S3：答案、题图与精准标签治理

### 1. 阶段目标

在 S2 候选基础上处理答案、题图和正式标签；保留原件视觉证据，完成教师审核前的质量校验。

### 2. 开发内容

- 题目文字和附图分别保存：S2 调用前提取原 PDF/转换 PDF 的嵌入位图，并在同一页段题答识别调用中让模型判断位图是否覆盖所需题图、给出缺图坐标及题目对应关系。服务端校验位图 ID、页码和坐标后裁剪并关联；不确定结果留待核对，不让模型直接写文件。直接提取和裁剪的图片均记录来源、页码、实际裁剪框和哈希以便复现。题图最终作为独立资产保存，不能只存模型的图形描述；正式入库前仍需教师确认。
- 题答同文件或分文件时，只提取标准答案及必要的题号、小题号、来源页证据；源文件中的解题步骤和解析不提取为答案，也不写入候选题的 `solution`。先按讲次、题号、小题号和来源证据配对；疑难项列给教师核对，不按顺序猜配，也不为单个问题再次发送原页给模型。对不上题目的答案统一留到批末待认领，供教师确认。只有题目时由教师选择生成答案或手填，模型答案单独标记且待教师确认。
- 独立预审题答冲突，返回疑点和原文证据；生成答案、资料答案、教师答案分别留痕，不互相覆盖。
- 从正式 JSON 与数据库读取当前开放 KP 白名单，由模型只建议正式 code 或未确定；最终章、节、年级和完整核心素养集合由主属 KP 派生。非法题型、未知 code 或不支持的素养阻断确认。
- 为字段保留原文证据、模型建议和必要的置信信息，支持整批重新打标签与教师修订；模型结果不能覆盖教师决定。
- 统计答案匹配、标签、题图和教师修改情况，并评估是否需补充百炼 Parse、OCR 或本地版面工具。

### 3. 阶段交付物

- 题图自动裁剪与来源元数据查询、答案版本与预审服务；
- 标签白名单和关联字段派生服务；
- 整批重新打标签接口与模型效果评测报告。

### 4. 验收标准

- 100% 的正式 KP 建议来自白名单，无法判断的题进入 `needs_confirmation` 或 `out_of_scope`。
- 题图来源页码及裁剪坐标可追溯；裁剪结果须由来源和视觉内容复核，不能把错误裁剪图当作完整原图。导入页不展示原 PDF。
- 资料答案与模型生成答案分离，冲突可定位，教师确认前不进入自动组卷池。
- 能报告题答匹配、KP Top-1/Top-3、题图关联和教师修改率；fake 结果不能正式入库。

### 5. 实施记录补充

- 导入批次中裸 LaTeX 的成对括号曾被拆开显示；已修复 `\left...\right` 及嵌套界符的前端解析，见 [17_裸LaTeX成对括号渲染修复](S3/17_裸LaTeX成对括号渲染修复.md)。

## 六、S4：重复题检测

### 1. 阶段目标

在教师审核前尽量找出重复题，并在正式提交时提供并发条件下的最终保护。

### 2. 开发内容

- 实现题目规范化纯函数，保留数字、正负号、单位、比较符号和选项顺序。
- 计算题干、选项和关键图片共同构成的规范化 SHA-256。
- 检测同一批次内的精确重复题。
- 历史题指纹一次回填、后续建题或编辑时维护；批量用 B-tree 索引按指纹查询题库精确重复，不逐题遍历全库。
- 使用 PostgreSQL `pg_trgm` 索引召回少量文本疑似重复题，再做 Top-K 精排与并排差异展示；中文题干召回效果需实测。
- 同年级、章节、KP 和题型优先比较，但不以标签不同为理由跳过查重。
- 对图片题增加图片内容哈希和感知哈希；关键图不同不能仅凭文字相同判为精确重复。
- 对题干高度相似但答案不同的情况增加“疑似数据冲突”提示。
- 精确重复默认“跳过并关联已有题”；新文件若带来更完整答案或图片，形成已有题补充建议，由教师在现有编辑/审核流程处理，不自动覆盖；疑似变式允许教师确认独立入库并记理由。
- 用标注过的重复题与合法变式题评测后冻结相似度分级和阈值；计划中的示意数值不直接上线：
  - 精确重复：禁止作为新题导入；
  - 高疑似：默认阻止，需填写强制导入理由；
  - 中疑似：警告并由教师确认；
  - 低相似：不主动打扰教师。
- 在候选题生成后、教师修改后和正式提交事务内分别执行重复检查。

### 3. 阶段交付物

- 规范化和指纹模块；
- 历史题目指纹回填报告；
- 精确重复检测服务；
- `pg_trgm` 疑似重复召回服务；
- 图片相似度服务；
- 重复检测接口和评测报告。

### 4. 验收标准

- 相同题目改变题号、空格、全半角或选项标号后仍能识别。
- 数字、符号、单位或选项发生实质变化的题目不会被当作精确重复。
- 批内精确重复和题库精确重复默认无法作为新题提交。
- 疑似重复结果能够返回已有题 ID、相似度和主要差异，供前端并排展示。
- 两个批次并发提交同一精确重复题时，不会同时产生两道正式题。
- 真实题库查询使用指纹和相似度索引，记录批量查重耗时；原题答案和图片不会因重复导入被静默改写。

## 七、S5：教师审核工作台

### 1. 阶段目标

提供教师真正可用的导入审核界面，在同一候选题卡片核对题目、标签、答案来源和判分方式，再集中处理待认领内容和重复题；教师可一次确认两项审核。

### 2. 开发内容

- 完成五步式工作台：
  1. 选择三种文件方式、答案生成/预审选项与标签范围；
  2. 查看解析进度；
  3. 复核和修改题目、标签、资料答案/生成答案/手填答案；
  4. 集中处理重复题、错配答案及待认领图片和疑似漏题；
  5. 查看提交前检查和结果。
- 左侧显示候选题列表，右侧并排显示原文证据和结构化编辑区。
- 表格展示题号、题干摘要、题型、难度、年级、章、节、主属 KP、核心素养、必做、标签状态和重复状态。
- 支持按低置信、超范围、缺答案、生成答案未确认、预审疑似错配、精确重复、疑似重复等状态筛选。
- 支持合理的批量修改，但批量修改后重新执行一致性和重复检查。
- 主属 KP 使用正式知识点选择器；改选后自动刷新章、节等派生字段。
- 支持题干、选项、答案、解析和图片的数学内容预览与编辑。
- 重复题页面并排展示候选题和已有题，并突出差异。
- 明确区分“保存修改”“确认题目与答案并入池”“仅确认题目并入库”几个动作；支持教师审阅后批量执行，并在提交前展示两条路径的题目数量。仅入库题显示“答案待审核”及现有答案审核入口。
- 展示版本冲突、模型失败、标签越界和文件解析警告。

### 3. 阶段交付物

- 批量导入完整工作台；
- 原文证据预览和题目编辑组件；
- 正式标签选择与联动组件；
- 重复题并排比较页面；
- 待认领内容集中处理页与答案来源、预审疑点展示；
- 教师决定和批量操作能力；
- 前端组件测试和端到端测试。

### 4. 验收标准

- 教师可以独立完成三种文件方式、查看模型结果、修改标签与答案、拒绝无效题、处理重复题和待认领内容。
- 页面刷新、网络中断或重新登录后，已保存审核结果不丢失。
- 教师不能输入不存在的正式 KP，也不能制造章、节和 KP 冲突。
- 低置信、范围外和重复题有明确文字提示，不能只依赖颜色。
- 只有已标记 `approved` 且无阻断问题的候选题可以进入待提交集合。
- 教师可在批量工作台一次确认题目和答案；后端仍分别执行题目审核与现有答案晋级校验。未解决的答案/图片可保留待处理，不会被错误挂到题目上。

## 八、S6：正式入库与验收

### 1. 阶段目标

完成事务性正式入库，并衔接现有答案审核与组卷池规则，通过甲方试运行完成交付。

### 2. 后端开发

- 建立批量建题领域服务，统一字段校验、资产关联、答案来源和审计。
- 提交时检查候选题 `revision`、教师决定、标签一致性和重复状态。
- 在同一数据库事务中完成最终查重、正式建题、候选题回写和审计记录。
- 使用事务锁或 advisory lock 防止并发重复入库。
- 提交接口要求幂等键；相同请求重试只能返回首次结果。
- 教师在导入页确认题干、图片和标签后建题，`source_review_status=reviewed`；若同时确认结构化答案且通过现有答案晋级校验，事务中直接设为 `machine_ready`，分别留下题目和答案审核事件。否则仅入题库并保持 `raw_answer_only`；模型生成或预审不能替教师确认。
- 原文件题号保存在候选项；正式 `source_question_number` 使用整数批内序号，并生成独立命名空间 `original_qid`。
- 写入来源文件、批次、原题号、模型版本和教师修改摘要。
- 题目、答案来源、教师确认、入池检查结果和重复处理选择分别留审计记录。

### 3. 前端开发

- “批量导入”提供三种文件方式及答案生成、手填、预审和末尾待认领处理入口。
- 在正式题库列表中展示批次来源，并可回看导入审计摘要。
- 保留已有题目的查看、编辑、答案审核和状态晋级功能。

### 4. 全链路测试

- 现有真实 PDF 用于无答案和分文件题答的全链路测试；PDF、DOCX、扫描页、题答同文件及明确错位答案等处理分支可先用受控固定样本验证。缺失的真实场景取得资料后补测，在此之前不得宣称其真实资料识别效果已验收。
- 模型超时、非法 JSON、低置信标签和知识图谱范围外题目。
- 批内重复、题库重复、相似变式和答案冲突。
- 同批重复提交、多人并发编辑、两批并发导入同题。
- 提交中任一题失败时整组事务回滚。
- 服务重启后任务恢复和人工重试。
- 同页同时确认且通过现有答案晋级校验的题直接入池；仅入库题保持 `raw_answer_only`。两项审核事件独立可追溯，校验失败不得静默降级。
- 未认领答案、图片和疑似漏题在批次末尾可处理或保留；已确认题目可先行提交。
- fake 适配器只能用于联调；入库事务用受控真实模型响应桩测试，Qwen 的切题、答案与预审效果用标注样本单独验收。

### 5. 甲方试运行

- 选取首批开放章节的真实资料进行试导入。
- 记录每批处理耗时、模型成本、切题错误、标签修改率、重复误报/漏报。
- 由甲方教师完成盲测和问题确认。
- 只修复影响数据正确性和主流程的问题，新增范围需求进入后续版本。
- 形成试运行报告、已知限制和操作说明。

### 6. 阶段交付物

- 事务性批量入库服务；
- 答案来源、题答预审、待认领内容与入池状态的验收记录；
- 完整自动化测试报告；
- 人工标注集评测报告；
- 甲方试运行记录；
- 部署、配置、备份恢复、文件清理和教师操作文档。

### 7. 最终验收标准

- 三种文件方式均可从上传走到教师确认和正式建题；无答案题可选模型生成或教师手填。
- 已有题目的编辑、审核和历史作业快照不受批量导入影响。
- 所有正式入库题均经过教师 `approved`，并可追溯原文件、模型版本和教师修改。
- 所有正式 KP 均来自数据库白名单，未知 code 100% 被拒绝。
- 精确重复题不能作为新题入库；高疑似题必须经过明确决策。
- 提交具有幂等性和事务性，失败不会产生半批数据。
- 未经教师明确确认结构化答案和现有答案晋级校验的题 0% 进入 `machine_ready`；合格题可在导入事务中直接入池，两个审核事件均可追溯；仅入库题保持 `raw_answer_only`。
- 题答预审异常与未认领答案/图片可集中处理，未处理项不丢失，也不会被误标为已确认。
- fake provider 不能用于正式入库；Qwen PDF 输入、JSON 输出、失败重试、DOCX 转 PDF 和题图保留均经过真实样本验收。
- 多教师真实资料试用前，服务端身份、批次归属和授权校验已经落地；否则只允许隔离内部演示。
- 评测报告至少包含切题正确率、字段完整率、KP Top-1/Top-3 准确率、重复召回率、重复误报率、教师修改率、处理耗时和模型成本。

## 九、开发提交与评审建议

每个阶段建议拆成小型、可回滚的提交，不把数据库迁移、解析器、模型提示词和大规模前端页面混在一个提交中。每阶段结束执行一次评审：

1. 数据库和 API 契约评审；
2. 安全和隐私检查；
3. 自动化测试；
4. 使用固定评测集回归；
5. 更新阶段文档和已知问题；
6. 确认无阻断问题后进入下一阶段。

建议在 S3、S5、S6 设置三个明确里程碑：

- **内部模型里程碑**：模型能从正式白名单贴标，但暂不允许正式入库；
- **教师试用里程碑**：教师能在同一工作台完成题目、标签和答案确认，并处理或保留待认领内容；
- **正式交付里程碑**：事务性入库、重复保护、真实模型评测和身份边界全部完成。

## 十、阶段完成定义

任一阶段只有同时满足以下条件才算完成：

- 本阶段交付物已进入版本库；
- 数据库迁移可以正向执行，并有明确回滚或恢复方案；
- 新增核心逻辑有自动化测试；
- 对固定评测样本执行过回归，结果已记录；
- 不把 fake、硬编码或手工数据库操作当作正式实现；
- 已知问题有严重级别、影响范围和后续安排；
- 相关文档与实际行为一致；
- 阶段验收人确认通过。

若某阶段验收失败，应优先修复该阶段的阻断问题，不带着数据一致性、标签越界、重复写入或安全问题进入下一阶段。
