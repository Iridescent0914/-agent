# KP—主属节映射修复记录（含题目标签约束）

日期：2026-11-10

后续口径（2026-11-11）：下文八维限制是本次映射修复时的状态。当前正式目录、组卷、评分及雷达图已统一为 HTML 九项，保留“空间观念”和“数据观念”，不接受“数据意识”别名；见[阶段三记录23](../../阶段三-画像与个性化题目/lin/23_九维素养评分与组卷画像统一记录.md)。前两章21个正式 KP 的入库范围不变。

## 问题与来源

《上海市五四制初中数学知识图谱.html》的 `SECTION_BY_KP` 按章节内 KP 顺序明确给出主属节，是节—KP 对应的**唯一依据**。原来 `data/seed/rational_knowledge_tree.json` 的 13 个 KP 和 `data/seed/expr_knowledge_tree.json` 的 8 个 KP 都没有 `section` 字段。种子导入器读取缺失字段时会将 `KnowledgePoint.section` 写成 `NULL`；修复前，本地数据库这 21 个 KP 的节字段确实全部为空。

按 HTML 映射、两份知识树的 KP 名称及顺序、`data/interim` 中 180 道现有题的节字段交叉核对，21 个 KP 的映射数量和内容均一致。特别是“有理数的运算律及其简化运算的作用”属于 `1.2 有理数的加法与减法`，按 HTML 原映射写入，不按 KP code 或题意另行猜节。

原设计允许题目分别填写主属 KP 和主属节，容易出现两者冲突。现在**题目只选择主属 KP**；章、年级、主属节由该 KP 在正式图谱中的记录自动确定。数据库的 `questions.chapter_code/chapter_name/grade/section` 仍保留供现有筛选、画像和快照使用，但只是派生字段，不是教师可独立编辑的标签。HTML 是图谱维护来源，运行时读取由 HTML 导出的 `data/knowledge_graph_catalog.json`，不要求后端打开 HTML。

进一步复核发现，HTML 也为每个 KP 指定了**一组核心素养**，可能不止一项。首批 21 个正式 KP 的素养集合均在系统八维内；现有 180 道题的 `core_literacy` 与各自主属 KP 集合完全一致，但旧编辑页和接口仍允许单独修改，未来会产生冲突。因此现在连同核心素养一起按主属 KP 派生，按图谱顺序用 `、` 连接并存入现有 `questions.core_literacy` 字段。

## 修复内容

1. 两份种子知识树逐个 KP 增加正式节名，共 21 条。导出脚本从 HTML 生成全量 JSON；知识树生成脚本和种子导入器读取该 JSON，校验章节、KP 名称、顺序和已有元数据。知识树若与 JSON 不一致则停止导入；题目原始章、年级、节即使写错，种子导入时也统一按主属 KP 派生。
2. `0026_backfill_pilot_kp_sections.py` 曾补齐前两章 21 个 KP 的节名。新增 `0027_enforce_graph_kp_question_labels.py`：迁移时先锁定并检查数据库全部 KP；只要有 code 不在正式 JSON 中就**报错并停止迁移**，绝不静默保留、删除或猜测替换旧 KP。通过检查后，覆盖现有 KP 的正式元数据，再把全部现有题目的章、年级、节改成其主属 KP 对应的值，包括已归档题目。题干、答案、作业和既有快照不改。
3. 种子导入不再遇到未知 KP 就自动创建占位知识点；题库编辑接口拒绝 JSON 外 KP，且只接收教师选定的主属 KP，忽略旧客户端传来的章、年级、节。前端编辑器把年级和主属节显示为只读派生值。题库目录和画像目录也必须从正式 JSON 找 KP，移除了对旧 KP 节字段、题目节字段的回退。
4. 全量 JSON 包含 41 章、345 个 HTML KP；目前只有前两章 21 个 KP 已分配正式 code 并导入数据库，其余 324 个保留在目录中但不可用于正式入库。S0 局部快照已移除。后续章节开放时，先为其 KP 分配稳定 code、扩展种子树并导入，再允许题目选择。
5. 新增 `0028_derive_question_literacy_from_kp.py`：把已有题目的核心素养归一为其主属 KP 的完整集合。种子导入与题目编辑也按 KP 派生核心素养；旧客户端传入的 `core_literacy` 仅为兼容字段，不参与保存。知识点接口返回正式素养集合，编辑页只读展示。若某 KP 的 HTML 素养含系统八维暂不支持的名称，正式入库会被阻断，不能删掉该维度或暗中改名。

## 验证结果

- 本地数据库已升级到 `0028 (head)`。全库检查：21 个已有 KP 均在正式 JSON 中，**图谱外旧 KP 为 0**；所有现有题目的章、年级、节、核心素养都与其主属 KP 的 JSON 记录一致。`0027` 对其他数据库也会执行相同检查，遇到旧 KP 即中断并列出 code。
- `scripts/export_knowledge_graph_catalog.py --check` 对照 HTML 和前两章种子树检查 41 章、345 KP 及正式 21 个 KP 的名称、节、素养等元数据；不会依赖已移除的 S0 局部快照。
- 后端 `pytest -q`：**236 passed**；覆盖旧 KP 迁移阻断、素养迁移、种子入库时派生题目标签、题库编辑时忽略手填节/年级/素养、目录和画像读取正式 KP，以及现有题目一致性。
- 前端 `npm run build` 通过；`git diff --check` 通过。

## 部署与边界

已有环境执行 `alembic upgrade head`，由 `0027` 检查所有 KP 并归一章、年级和节，由 `0028` 归一核心素养；新环境迁移后再运行 `python -m scripts.seed_database --chapter all`。运行时 JSON 位于已挂载的 `data` 目录；HTML 只在更新图谱目录时由导出脚本读取。迁移不重导 180 道题。

如果某环境已经有图谱外旧 KP，迁移会失败并保持原事务不落库。须先人工核对这些 KP、其题目及学生历史引用，制定明确的映射或数据修复迁移，再重新执行；不能把不明旧 KP 自动删除或按名称猜配。正式 JSON 尚未分配 code 的 324 个 HTML KP 也不能作为已导入 KP 使用。HTML 全量九项素养与系统八维有名称差异，现有 21 个正式 KP 不受影响；后续章节开放前须明确映射。日后若调整 HTML 中已入库 KP 的归属或素养，须重新导出 JSON 并增加数据迁移，同步已存题目的派生字段；仅替换 JSON 不会自动重写数据库。`0026`～`0028` 的 downgrade 不尝试还原先前不可靠的题目标签值。
