# S2 重试响应的小题字段兼容

## 现场

批次 `c76953f6-58bf-44af-b279-ea3ea6667013` 的第 9–11 页第一次调用返回 `[]`；再次调用返回了完整的根对象和 10 道题，但小题条目使用 `{original_number, question_text}`。原解析器只接受小题字符串、`{key, text}`、`{number, text}` 或 `{label, text}`，因此报告 `INVALID_MODEL_OUTPUT`。这次响应为 HTTP 200、`finish_reason=stop`，不是额度错误。

## 处理

- 将 `{original_number, question_text}` 作为小题的另一种明确等价表示，继续禁止未知字段；保留原题号和文字。
- 校验失败信息增加字段位置，方便区分题目内容缺失与字段命名不一致。
- 不修改 S2 提示词版本或页段检查点。重试同一批次时，工作器先重新解码已保存的原始响应；现在第 9–11 页可以直接恢复，不会为该页段再次调用模型。其余未处理页段仍按原预算逐段调用。

## 后续防护：结构化输出

仅给解析器增加别名无法穷尽模型可能写出的字段。百炼的 JSON Object 模式只保证有效 JSON，不保证业务字段结构。官方文档列出 Qwen3.8-Flash 支持严格 JSON Schema 模式，因此 S2 请求现已使用 `response_format=json_schema`、`strict=true`，Schema 直接由当前 `ModelOutput` 校验模型生成，避免请求约束与本地解析器各写一套。根节点限定为对象，题目、小题、页码和待核对片段也有类型与字段限制。

提示词内容和 `PROMPT_VERSION` 未变化；已保存的旧响应仍由本地解析器解码，后续新调用使用更严格的输出格式。保留原始响应存档和本地校验：严格 Schema 能降低格式漂移，不能证明题目识别正确，也不能保证服务端永不产生异常响应。未知结构仍明确报错并保留原始数据，不把猜测映射悄悄写入题库。

本地 MockTransport 测试确认 PDF 请求携带严格 Schema，且已保存的第二次响应仍能离线恢复。由于未发起新的付费请求，PDF 输入与严格 Schema 在实际百炼服务上的组合尚待下一次正常调用验证。
