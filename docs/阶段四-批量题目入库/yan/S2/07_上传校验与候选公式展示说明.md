# 上传校验、题图线索与候选公式展示

日期：2026-11-13。

## 上传后的状态

“文件已保存，等待校验”对应 S1 批次阶段 `files_saved`，尚未调用百炼。上传接口已经做了第一轮预检：文件大小与批次大小、PDF 文件头/结构/加密状态/页数，或 DOCX 的 ZIP 结构、必要文件、宏和异常压缩内容。异步 worker 随后重新读取私有落盘文件，核对实际字节数与 SHA-256；通过后变成“文件已校验，等待 S2 解析”。这一步检查传输与存储完整性，不判断题目内容、公式或图像识别质量。DOCX 转 PDF 在后续 S2 执行。

## 题图线索

`diagram_clues` 是 S2 模型给出的图形文字描述，如“本题含数轴”。它保存在候选题的提取辅助信息中，并触发“题图尚未裁剪”的复核提示。它不是独立图片、裁剪结果或教师确认过的图题关联，不能代替 S3 的图片提取与核对。

## 公式展示修复

原候选题列表直接把 `question_text` 和选项作为普通文字显示，导致模型输出的 `$...$` LaTeX 分隔符和 `\times` 等命令原样出现在页面。本次复用现有 `RichQuestionText`/`ReadOnlyMath` 显示候选题，并让通用富文本组件识别行内 `$...$`、块级 `$$...$$`（保留已有 `\(...\)`、`\[...\]` 支持）。这只改变页面显示，不修改候选题原文、模型响应或原题中的填空线。页面会把示例中的 `\times`、指数按数学排版显示，`___` 仍表示原题空格。

前端 `npm run build` 通过；使用给定的两段 `$...$` 示例确认分隔符能识别为两个行内公式。S1 文件校验逻辑和 S2 模型请求未修改，也没有新增百炼调用。
