# S2：PDF 识别与切题工程实现记录

日期：2026-11-13。阶段定位：内部技术试验。S2 工程链路已实现，已用两份单页材料完成 Flash 初步人工文本对照；跨页、扫描页、更多题图及账单验收仍待办。

## 目标与边界

承接 S1 的 `uploaded / awaiting_s2` 批次，仅在页面上由人明确点击启动后调用百炼。S2 只处理题目文件；题答同文件或分文件的答案关联、题图裁剪、正式 KP 标签属于 S3。识别结果保存在 `question_import_items` 候选区，仍无正式题库提交接口。模型不能决定批次 ID、教师决定、主属 KP、难度或必做标记。

## 已实现

1. 在后端镜像安装 LibreOffice Writer 与中文字体。DOCX 保留原件，在私有批次目录转换 PDF；检查转换结果可读取、页数仍在 50 页试点上限内，原 DOCX 含嵌入图片而 PDF 不含图片时拒绝。空白页记为人工复核提示，不误判为文件损坏。公式和绘图的视觉一致性仍需人工对照，不将程序检查解释为视觉质量验收。
2. 题目 PDF 按 `QUESTION_IMPORT_S2_PAGES_PER_UNIT` 分成连续核心页段，只在每段后方保留 `QUESTION_IMPORT_S2_OVERLAP_PAGES` 页重叠，以减少重复解析费用。每次只发送当前页段的 PDF 字节；模型返回的页码映射回原文件页码。重复的“文件、原页、题号、题干和选项”只生成一条候选。原有批次若已保存页段计划，续跑时沿用其原计划；新批次使用单侧重叠。
3. 使用百炼 OpenAI 兼容 Chat Completions、仅允许 `qwen3.8-flash`、请求体内 `file_data` Base64 传输私有 PDF。服务端配置模型、工作空间地址、密钥、内部操作口令、超时、回答 Token 上限、页段、调用次数和价格参数。默认关闭 S2；没有密钥、操作口令和 HTTPS 工作空间地址时不能启动。提示词版本为 `question-import-s2-v3`。开始与失败重试都校验操作口令，百炼密钥不传给浏览器。
4. 模型输出使用独立的 Pydantic 契约校验；输出不完整、其他字段多出、页码越界或被截断均失败。真实试验发现子题可能返回字符串、`key/text`、`number/text` 或 `label/text` 对象，现均严格校验并归一化为候选题中的编号文本。候选只接收题号、题干、选项、子题、公式片段、图形线索和原页证据。S2 不请求或记录模型区域坐标；若模型额外返回该字段，保存前丢弃，避免再次付费重试。无法确定的片段保存在页段检查点中；空结果也提示人工核对。
5. 每个页段的模型响应及用量保存在私有批次目录；即使响应校验失败，也先原子保存原始响应，供定位和已付费响应的重新校验。处理进度、原文件 SHA-256、模型/提示词版本、响应 ID、调用次数、耗时、解析页数、Token 和估算费用保存在数据库检查点。worker 在单个页段提交候选与检查点；失败后重试跳过已完成页段。取消后不会写入迟到的模型结果，但已发出的请求仍可能计费。
6. 页面增加显式启动确认、单批费用阈值、页段状态、候选题与待核对内容。费用阈值依据已返回用量在下一次调用前暂停，**不是云端硬性消费封顶**；单次调用可能使实际费用越过阈值。缺少解析页数或 Token 用量时暂停后续调用，提示核对账单。

## 配置与试验步骤

在本地 `code/.env` 配置，不要把 API Key 提交到仓库或发到聊天：

```dotenv
QUESTION_IMPORT_S2_ENABLED=true
QUESTION_IMPORT_S2_API_KEY=<本地密钥>
QUESTION_IMPORT_S2_OPERATOR_TOKEN=<自设的随机长口令>
QUESTION_IMPORT_S2_BASE_URL=https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
QUESTION_IMPORT_S2_MODEL=qwen3.8-flash
QUESTION_IMPORT_S2_MAX_OUTPUT_TOKENS=16384
QUESTION_IMPORT_S2_PAGES_PER_UNIT=4
QUESTION_IMPORT_S2_OVERLAP_PAGES=1
```

地域和工作空间域名以百炼控制台实际接入信息为准。默认每段 4 页主体、向后重叠 1 页，单次最终回答上限 16384 Token；这三个参数均可由 `.env` 修改。增大页段后仍需核对漏题、跨页题和输出截断。修改 `.env` 后执行 `docker compose up -d --force-recreate backend`，使 Compose 将变量传入新容器。打开“批量题目导入”，上传不含学生个人信息的 PDF 或 DOCX，等待文件校验完成；在页面输入自设的 S2 操作口令、确认本批预算，点击“开始 S2 识别”。建议先用 1～2 页小样本，再逐步扩大。所有调用与成本须回查百炼账单。

页段抽取规则：模型只提取题干起始于主体页的题；末尾重叠页仅用于补全主体页开始的跨页题。重叠页新起的题交给下一页段，不应因此令 `complete=false`。服务端再次过滤模型误输出的重叠页新题，并继续拒绝 `complete=false` 的页段。没有下一页段接手的文件尾页会归入最后一段主体页，避免漏题。旧版 v2 批次若因带重叠页的页段返回 `INCOMPLETE_MODEL_OUTPUT`，重试时升级到 v3；已完成页段和费用检查点保留，失败响应留存为 `.prior.json` 供排查。

前端不再展示批次和页段的估算费用；仍显示模型调用次数，并保留启动 S2 所需的单批调用预算阈值。后端继续用估算值控制续跑预算，检查点也继续记录该值。估算值按返回用量和配置单价计算，未计入缓存折扣、免费额度及活动优惠；实际费用以百炼账单为准。

`INCOMPLETE_MODEL_OUTPUT` 的人工“重试”现在会自动调整失败页段：多页主体先拆成较小的主体页段，并给每段至少两页后续上下文；若已缩至单页仍不完整，则每次增加两页上下文。已完成页段不重新调用，失败响应仍单独留存，新增调用继续受批次预算和调用次数上限约束。前端在重试前提示可能发生新费用；预算暂停时提示调整预算，调用次数已达上限时提示联系管理员。若单页已看到文件末尾仍无法完整提取，系统改报 `S2_REVIEW_REQUIRED`，前端不再提供无效重试，而是提示检查原页、重新上传清晰文件，或复制批次号联系管理员；已完成候选仍可查看。系统不会把模型自报不完整的结果当作完整题目入库。

29 页实际批次 `e3e5bec0-7edc-4006-80d4-2f20c217fefb` 在第 9–13 页因第 13 页新题尚未结束而失败；按上述规则续跑后 7 个页段全部完成。第 13 页跨页的第 8 题由 13–17 页段提取至第 14 页，最后一段将第 29 页作为主体页并录入 4 道在该页起始的题。最终 118 道候选题、0 条未归属片段；只读重叠去重审计返回 0 对，原页与题号组合也没有重复。共 8 次模型调用（含失败和重试），检查点估算费用 1.191832 元，实际费用仍以百炼账单为准。

费用估算使用本批配置的单价快照：

```text
估算费用 = 实际解析页数 × PDF每页价格
         + 输入Token / 100万 × 输入单价
         + 输出Token / 100万 × 输出单价
```

默认单价仅为北京地域 `qwen3.8-flash` 的试算参数（输入 0.8、输出 2.7 元/百万 Token，PDF 解析 0.02 元/页），可能随地域、优惠和计费政策变化；试验前应与控制台核对。重叠页被再次发送时可能再次计入解析量。接口依据：[百炼 PDF 理解](https://help.aliyun.com/zh/model-studio/pdf-understanding)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)、[模型价格](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)。PDF 等多模态输入的 JSON Schema 可能降级，因此本项目使用 JSON Object 并在后端严格校验。

## 验证与限制

- 定向测试覆盖页段重叠、原页映射、模型响应越界/不完整/多余字段、私有 Base64 请求、费用计算、操作口令、显式启动与重试、空白页复核提示，以及逐段续跑和重叠页去重。容器内 LibreOffice 可转换最小 DOCX；最终测试数量见下方最终验证记录。
- 已完成两份单页真实模型调用，但样本量不足以推断整体切题准确率、公式准确率或账单成本。一次早期失败响应未保留用量，实际总费用须从百炼账单核对。
- 现有系统没有可信教师登录身份。S2 操作口令仅限制付费启动与重试，不等同于多教师身份隔离。为避免私有原 PDF 被未认证请求读取，S2 不提供原件在线查看接口。候选保留源文件 ID 和原页码；目前需用本地原件人工核对。补充可信身份与访问控制后再实现站内原件回看。
- 对已发出的模型请求，进程崩溃或网络失败可能导致重试产生额外费用；失败提示要求先核对百炼账单。临时原件、转换 PDF 和页段响应文件遵循 S1 的 72 小时清理规则，候选题与审计检查点继续保留。
