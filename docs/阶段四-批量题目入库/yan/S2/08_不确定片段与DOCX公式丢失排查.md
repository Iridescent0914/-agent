# S2 不确定片段与 DOCX 公式丢失排查

## 现象与原因

- 批次 `a75ba2ad-49f0-41ca-9d28-9044f026877e` 的第 14 题出现“模型报告不确定片段；请人工复核”。
- S2 将模型返回的 `uncertain_fragments` 非空视为需复核，并生成上述通用警告。此字段由模型报告，并非校验器判定原文件缺字。
- 该题原始 DOCX 的 `word/document.xml` 中有一个 `m:oMath` 公式对象：负号加分数 `1/2`，即 **−1/2**。直接拼接 XML 中的文本会得到 `-12`，不能把它理解为负十二。
- LibreOffice 转换后的 PDF 第 2 页无该公式；检查 PDF 文本层和渲染页面均确认缺失。模型只接收转换后的 PDF，因而识别到“有理数的倒数为……”缺少数值，并将该处列为不确定片段，没有自行补写。

## 本次调整

- 候选题界面直接展示 `extraction.uncertain_fragments` 的具体内容，替换重复的通用警告显示。后端仍保留通用警告字段，兼容已有数据和 API。
- 不自动补写该题：需核对原始 DOCX 后再修订候选题。此处应为 **−1/2**，不是 `-12`。
- 本次排查没有重新调用百炼模型，不产生新增模型费用。
- 前端执行 `npm run build` 通过。当前 Docker Compose 的前端服务挂载源码目录，开发页面刷新后即可看到新的提示。

## 后续处理

### 2026-11-14 进一步定位与修复

- 原始 DOCX 包含 1 个内联 OMML 分数公式。旧后端镜像只有 `libreoffice-writer`，未安装 `libreoffice-math`。将原文件转成 ODT 后，正文对应位置已为空，ODT 内公式对象数为 0；说明丢失发生在 LibreOffice 导入 DOCX 时，早于 PDF 导出和 Qwen 识别。
- 在运行中容器安装 `libreoffice-math` 后，同一原文件转成 ODT 出现 1 个公式对象；转成 PDF 后，第 2 页的布局文本可见负号、分子 `1` 与下一行的分母 `2`。普通 PDF 纯文本提取会把竖排分数压成 `−12`，不能用普通提取结果判断公式含义，应查看页面渲染或布局。
- `backend/Dockerfile` 增装 Math 组件，并把 Debian 软件源改为 HTTPS，避免本次 HTTP 下载时遇到的 500 / unexpected EOF。加入含内联 OMML 分数的 DOCX→PDF 回归测试。
- 转换缓存文件名加入 `libreoffice-math-v1`。相同 DOCX 重新上传会建立新批次，避免复用旧的缺公式 PDF；旧批次若已有 S2 页段，继续重试会被阻止，须重新上传并完整重跑。重跑 S2 会重新调用模型并产生相应费用。
- 这项修复只解决已确认的“缺 Math 组件导致 OMML 公式静默消失”。其他 Word 公式、特殊字体或复杂排版仍需老师核对原件和 PDF；少量异常可在候选题审核时人工修订。
- HTTPS 源的后端镜像构建成功，本地 Compose 后端已重建并启动；在新容器中运行 `tests/test_question_import_s2.py`，14 项测试全部通过，含 OMML 分数转换与旧批次防混用测试。验证过程未调用百炼模型。

### 后续补充：另一份真实 DOCX 暴露了未覆盖的结构

以上结果来自 `测试用.docx`。后来上传的 `2026年中考数学真题知识点分类汇编之有理数（二）.docx` 是另一份文件，公式位于 `w:r` 内部；安装 Math 组件后直接转换仍丢失。旧测试只覆盖段落直属的 `m:oMath`，未覆盖此结构。进一步修复及验证见 [13_嵌套OMML公式转换修复.md](13_嵌套OMML公式转换修复.md)。
