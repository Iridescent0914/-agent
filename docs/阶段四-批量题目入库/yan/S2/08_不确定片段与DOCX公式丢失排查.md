# S2 不确定片段与 DOCX 公式丢失排查

## 现象与原因

- 批次 `a75ba2ad-49f0-41ca-9d28-9044f026877e` 的第 14 题出现“模型报告不确定片段；请人工复核”。
- S2 将模型返回的 `uncertain_fragments` 非空视为需复核，并生成上述通用警告。此字段由模型报告，并非校验器判定原文件缺字。
- 该题原始 DOCX 的 `word/document.xml` 中有一个 `m:oMath` 公式对象：负号加分数 `1/2`，即 **−1/2**。直接拼接 XML 中的文本会得到 `-12`，不能把它理解为负十二。
- LibreOffice 转换后的 PDF 第 2 页无该公式；检查 PDF 文本层和渲染页面均确认缺失。模型只接收转换后的 PDF，因而识别到“有理数的倒数为……”缺少数值，并将该处列为不确定片段，没有自行补写。

## 本次调整

- 候选题界面直接展示 `extraction.uncertain_fragments` 的具体内容，替换重复的通用警告显示。后端仍保留通用警告字段，兼容已有数据和 API。
- 不自动补写该题：需核对原始 DOCX 后再修订候选题。此处应为 **−1/2**，不是 `-12`。
- 本次排查没有重新调用百炼模型，不产生新增模型费用。
- 前端执行 `npm run build` 通过。当前 Docker Compose 的前端服务挂载源码目录，开发页面刷新后即可看到新的提示。

## 后续处理

DOCX 转 PDF 目前只会检测“原文件有图片但 PDF 完全没有图片”等明显失败；无法保证每个 Word 公式对象均正确转换。本例说明公式完整性仍须人工核对。后续可以考虑对 DOCX 内的 OMML 公式增加专门的转换或逐项校验，再决定能否可靠地自动修复。
