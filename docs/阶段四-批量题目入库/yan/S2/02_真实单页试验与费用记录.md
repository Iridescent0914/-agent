日期：2026-11-13。用途：内部小样本验证，不代表整批资料的识别准确率。两份样本均为现有资料各提取 1 页；未在本文记录 API Key、操作口令或完整业务空间地址。

## 样本 A：基础篇例题

- 来源：`校本/题/L7基础篇1-10讲例题.pdf` 第 1 页，提取为单页临时 PDF，按“只有题目”场景创建批次。原页文本层有 4 道例题、10 个子题，没有学生个人信息；该页无嵌入图片。
- 模型：北京地域 `qwen3.8-max`；PDF 通过请求体内 Base64 `file_data` 发送。批次估算费用阈值设为 1 元；这不是云端硬性封顶。
- 测试批次 ID：`2e1a513e-3e55-4cfd-9f28-f90731fdf8fd`。最终状态 `review_pending / s2_completed`，生成 4 道非正式候选题，来源页均为第 1 页；未提交到正式题库。

## 样本 A 的两次调用与修复

| 次数 | 结果 | 本地费用记录 |
| --- | --- | --- |
| 第一次 | 模型返回字段未通过契约校验，批次停在 `s2_failed`。当时实现尚未保存失败响应，无法确认具体字段和用量。 | **未知**；可能已计费，须查百炼账单。 |
| 第二次 | 返回 4 道题；模型把 `subquestions` 输出为 `key/text` 对象，旧契约只接受字符串，因而再次停在 `s2_failed`。原始响应和用量已在私有批次目录保存。 | 用量可估算，见下节。 |

针对真实响应，代码现在允许严格的字符串子题或 `key/text` 对象子题，并归一化为带编号的候选文本。随后从第二次已保存的响应恢复处理，**没有发起第三次模型调用**。失败响应先保存原文与用量，失败检查点记录可估算费用；相同响应恢复成功时不重复计费。新请求校验失败后，人工点击重试可重新调用模型。

## 样本 A 第二次响应的用量与费用

- 响应 ID：`chatcmpl-5f1db57f-9902-9380-a120-36e9466e073b`；请求耗时 **138.141 秒**。
- PDF 解析页数 **1**；输入 **2,598 tokens**，其中报告缓存命中 **2,304 tokens**；输出 **6,788 tokens**，其中思考 **5,785 tokens**。总计 **9,386 tokens**。
- 按当前程序配置的北京地域目录价、全部输入按普通输入价格计算：`1×0.02 + 2598×12/1000000 + 6788×36/1000000 = 0.295544 元`。这是该次响应的**保守估算**，程序显示的批次估算也是此数；它不包含第一次未知费用。
- 如果缓存命中的 2,304 个输入 Token 均按目录中的缓存命中价 1.5 元/百万 Token 计，第二次调用的参考估算为 `0.271352 元`。优惠、免费额度与实际账单仍以百炼控制台为准。价格依据：[PDF 解析计费](https://help.aliyun.com/zh/model-studio/pdf-understanding)、[qwen3.8-max 模型价格](https://help.aliyun.com/zh/model-studio/qwen3-8-max)。

**样本 A 两次调用的实际总费用目前未知。** 首次响应没有留下用量，不能用第二次费用推定其实际费用。下一步应在百炼控制台按调用时间或响应 ID 对账。
