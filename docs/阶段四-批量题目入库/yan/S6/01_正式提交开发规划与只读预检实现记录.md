# S6：正式提交开发规划与只读预检实现记录

日期：2026-11-28。当前状态：S6-A 只读提交预检已实现；S6-B 正式入库事务、S6-C 页面接入与全链路验收待开发。

## S5 交给 S6 的数据

S5 保存候选题版本、有效的题目审核事件、直接入池时独立的答案审核事件、S4 查重决定及 `library_only / direct_pool` 入库意向。S5 审核不会创建正式 `Question`，也不会修改自动组卷池。S6 提交请求必须明确选中候选题，并同时携带候选版本和当前题目审核事件 ID；不能仅凭候选题的 `teacher_decision=approved` 建题。

## S6-A：已实现的只读预检

新增 `POST /api/v1/question-imports/{batch_id}/s6/preflight`，请求 `items` 中每项包含 `item_id`、`expected_revision` 和 `question_event_id`，同一请求最多 200 题且不可重复。服务端逐题检查：

- 候选题仍可用、版本未变化；S5 题目审核仍有效且事件 ID 与请求一致。直接入池审核的答案事件有效性由 S5 有效审核判定覆盖。
- 正式题库是否已出现新的精确重复题、该候选是否已有正式入库记录；本次选中集合内是否有精确重复题。
- 候选无法计算精确指纹，或正式题库仍有未建立指纹的题时给出提醒，不把它表述为“确认无重复”。

响应逐题返回路径、阻断项和提醒项，并汇总两条路径的可提交数量。预检只读，不写入正式题库，也不锁定提交时的题库状态；任何“可提交”结果都必须在 S6-B 的写入事务内重新计算。

验证：后端 S4/S5/S6 定向回归 47 项通过，其中 S6-A 新增 3 项，覆盖无有效审核、审核事件和候选版本变化、新出现的正式精确重复题、选中集合内重复及 HTTP 响应。此验证不代表正式入库已可使用。

## S6-B：下一项开发

1. 定义正式提交请求的幂等键及结果记录；同一请求重试只返回原结果，另一请求不能再次导入已入库候选。
2. 锁定批次和候选，并对不同批次的正式建题执行数据库级并发保护。在同一事务内重跑 S6-A 核心校验、S5 审核与答案校验、标签目录核对和正式题库精确查重；任一选中题阻断则整组选中集合不写入。
3. 将已确认题图晋级为不受临时文件保留期影响的正式资产，建立正式题目、来源与审核审计记录；仅题目入库保持 `raw_answer_only`。直接入池复用现有答案审核服务的校验和晋级规则，写入独立答案审核事件，成功后为 `machine_ready`。失败时数据库不得留下半批题，正式题图也不得留下无引用的副本。
4. 已提交部分题目时保留批次其余候选继续审核；批次最终完成时清理未被正式题目引用的临时图。正式题库列表可追溯批次和候选来源。

## S6-C：页面与验收

接入正式提交前预览、逐题阻断说明和明确确认动作，展示两条路径数量、未选及待处理数量。验证重复提交、跨批并发、版本冲突、答案直接入池、题图过期与晋级、失败回滚、服务重启和三种文件方式。甲方真实试运行前仍需完成 S2/S3 模型质量与费用核对、S4 人工标注查重评测及服务端身份和批次归属校验。
