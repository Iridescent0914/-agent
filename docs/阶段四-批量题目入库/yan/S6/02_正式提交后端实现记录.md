# S6-B：正式提交后端实现记录

日期：2026-11-28。状态：正式提交后端核心流程已实现；页面接入与批次最终收尾仍待后续步骤。

## 接口与提交语义

新增 `POST /api/v1/question-imports/{batch_id}/s6/commit`。请求包含 `operation_id`（UUID）和 1～200 条 `items`，每条必须带 `item_id`、`expected_revision`、`question_event_id`。只接受同一批次内已经获得当前有效 S5 教师审核的候选题。`library_only` 建正式题并保持 `raw_answer_only`；`direct_pool` 复用现有答案审核提升服务，成功后变为 `machine_ready`。

同一批次、同一 `operation_id` 和同一题目清单重复调用，返回首次提交的题目 ID 与 `replayed=true`；同一操作编号对应不同清单返回 `OPERATION_CONFLICT`。已入库候选题不能以新操作编号再次入库，数据库还对 `questions.import_item_id` 设置非空唯一索引。

## 事务与数据落点

提交先锁定批次及选中候选题，再锁定正式题表写入，与其他正式建题操作串行地重算 S6 预检。任何选中题被阻断时整组拒绝，不产生正式题。校验通过后，将题目内容、正式知识点、来源文件和原题号写入 `questions`，同时记录批次、候选题、S5 题目审核事件与提交操作编号。答案审核提升以及逐题 `commit` 审计事件与题目创建处于同一数据库事务。

已关联题图从批次临时目录复制到正式 `assets/teacher/` 目录，正式题只引用持久化副本。提交失败时回滚数据库并删除本次新建的图片副本。图片文件名根据批次与临时图 ID 确定，已有同名文件必须有相同内容。

题库详情的选项组件现已识别批量候选题使用的 `{key, text}` 选项结构，正式入库后按选项字母和正文展示。公式标记沿用现有题库编辑接口的判断规则。

本次新增迁移 `0044_question_import_s6_commit.py`，创建 `question_import_commits` 幂等记录表和 `questions.import_item_id` 唯一索引。开发数据库已升级至 0044。
