# S3：同文件一次提取与资料答案保守关联

> 历史开发记录：本文中的早期同文件版本和旧批次兼容说明已不适用于当前数据库；当前版本见 [提示词版本与历史兼容清理](../S2/14_提示词版本与历史兼容清理.md)。

日期：2026-11-15。状态：S3 第一批工程实现，**不是 S3 完成验收**。

## 决策

题答同文件的新批次在 S2 的每个 PDF 主体页段调用中，同时返回两类独立结果：`questions` 和 `source_answers`。长文件仍按原页段处理，不把整份 50 页文件塞进一次回答。答案部分只转录资料明确给出的标准答案、题号、小题号和原页；不提取解析步骤，不由模型计算答案，不要求模型在调用内决定题答归属。

这避免 S3 默认再次向百炼发送整份题目文件。题答分文件时，S2 仍只读取题目文件；后续 S3 应只处理答案文件。只有题目的批次不请求资料答案。旧版已付费的同文件 S2 批次保留原 `question-import-s2-v3` 合同，不会自动重新调用模型；其答案仍待后续按答案页处理。

## 本批实现

- 新增 `question-import-combined-v1` 输出合同。`source_answers` 必须单独列出原题号、可选小题号、答案文本、相对页码与不确定片段；页码由服务端校验并映射为原文件页码。无题目的答案页可以只返回答案候选。
- 同文件新批次启动 S2 时冻结新提示词版本；有旧检查点的批次沿用其原版本。页段原始响应、费用和恢复机制继续沿用 S2，不因 S3 关联再次付费。
- 每段来源答案保存在私有批次的 `checkpoint.s2.units[*].source_answers`，重叠页中新起的答案交给下一主体页段；来源文件 ID 和原页一并记录。
- 同页段题答一起输出可能增加回答长度。若模型明确截断，多页主体在显式重试时先拆小页段；单页仍截断时要求拆分资料或调整上限，不重复付费请求相同单页。
- 新增 `POST /api/v1/question-imports/{batch_id}/s3/reconcile-source-answers`。只有原题号在本批候选中**唯一**、候选尚未被编辑且尚无答案时，才创建 `source_extracted` 答案版本。关联结果仍是 `teacher_confirmed=false`、`selected_answer_id=null`、`teacher_decision=pending`；不会进入正式题库或自动组卷池。
- 缺题号、找不到题、题号重复、同一答案位置重复、候选已编辑等情况进入 `checkpoint.s3.source_answer_reconciliation.unassigned_answers`，带原因保留。后续 v3 对账会把满足严格跨页重复条件的无题号记录另列为 `overlap_duplicate_answers`，详见 [04_跨页重复答案与公式漏读治理.md](04_跨页重复答案与公式漏读治理.md)。接口重复调用返回原结果，不重复增加答案或候选修订。
- 批次页展示关联数量、待认领答案及候选的待确认资料答案。

## 验证与边界

- 新增测试覆盖同一 PDF 请求输出题目与答案、严格输出结构、答案页码越界，以及重复题号和缺题号不猜配、唯一题号只建立待确认来源答案、重复执行幂等、同页段保存和截断后的页段拆分。
- Python `compileall` 和 `git diff --check` 通过。Docker 容器内 S2/S3 定向测试 **26 passed**；后端全量回归 **289 passed**；前端 `npm run build` 通过，保留原有 MathLive 分包体积提示。沙箱内直接启动容器命令曾因 `read cap_sid file` 失败，改用自动审批的容器执行权限后完成上述复验。
- 新输出合同尚未用百炼真实同文件样本验证。严格 JSON Schema 可约束结构，不能证明答案转录和题答关系正确。真实调用前仍须核对文件无学生身份信息、显式预算和实际账单。
- 题号唯一是保守的初步关联条件，不能代替讲次、小题和原页核对；任何来源答案都仍需教师确认。已有候选题不会因代码更新自动补出答案。

## S3 下一批

1. 对分文件场景只解析答案文件；对旧同文件批次仅定位并处理答案页，不重复发送整份题目 PDF。
2. 补充讲次、小题号与来源证据匹配，冲突预审，以及资料、生成、教师答案的独立版本与待认领处理。
3. 从原 PDF/转换 PDF 提取或裁剪真实题图，保留原页和裁剪证据；关键图片未归属时阻断确认。
4. 从正式 KP 白名单生成标签建议，派生年级、章、节和完整素养集合；补齐字段证据、单题重试和真实样本质量评测。

本批仍没有正式入库接口；S3 完整验收应按[阶段开发计划](../阶段开发计划.md)执行。
