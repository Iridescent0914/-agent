# S3：独立标签建议任务

日期：2026-11-17。

## 流程与范围

S2 切题完成后先做整批去重。同文件资料在去重后关联来源答案；分文件资料在去重后识别答案文件并关联来源答案。上述任务完成后，教师在导入页单独启动标签建议。只有题目文件的批次在去重后即可启动。新建任务按最多 **12 题、24,000 字符和 12 张图**分组，达到任一上限就开始下一组；单题超过字符或图片上限则提示先人工整理。每组发送当前候选题的题干、选项、小题及已关联题图，调用一次已配置的百炼 Flash 模型。答案不用于决定 KP。

模型只返回题型、1～5 星难度、主属 KP、最多两个备选 KP，以及必要的不确定说明；**不再要求或展示“模型依据”**。主属 KP 为空时必须说明无法判断的原因。KP 必须在正式 JSON 目录中开放且已入数据库；章、节、年级和完整素养集合由主属 KP 派生。`is_required` 初始保持 `false`，模型不能修改。首次生成和普通失败续跑沿用已有手动修改保护；教师主动点击“全部重新打标签”后，该轮及其失败续跑会对所有未删除候选题应用模型新结果，直接覆盖题型、难度、主属 KP 和派生标签，包括之前教师手动修改或明确清空的值。必做标记保留；原本已通过的题目重新回到待审核，已拒绝或跳过的决定保留。教师手动核对时按年级、章、主属知识点的顺序选择，后两级仅显示上一级范围内的选项；节和核心素养作为派生标签展示。内部仍以正式 KP code 保存和关联，并由服务端按该 KP 写入一致的年级、章、节和素养字段。

迁移 `0030` 删除旧候选题 `label_suggestion.reason`、旧批次标签任务建议中的 `reason`，并从已归档的标签模型响应摘录中移除该字段；无法安全解析的摘录会删除，调用用量和响应 ID 保留。候选题 Schema 不再接受 `reason`。去重判断和答案核对各自使用的原因字段不受影响。

每组保存候选 ID、版本和内容指纹；模型返回必须逐题覆盖且全部通过白名单校验。付费调用前再次核对版本和内容指纹，排队后已变化的题目跳过并记录，不发送旧内容。题干或题图变化后，已有标签和标签建议保持原样，不自动标记过期或重新生成。已完成任务可由教师点击“全部重新打标签”，把整批候选按当前上限重新分组并再次发送模型；题目显示新结果，题型、难度和主属 KP 的旧手动修改不再保留。原分组移入调用审计，累计费用保留。单题重新建议接口和按钮已移除。教师也可直接调整题型、难度、KP 和必做；手动 KP 调整仍由现有服务重新派生关联标签。

## 费用和失败处理

启动需 S2 操作口令和本批标签任务预算。任务保存组进度、调用次数、用量、估算费用及响应 ID。已收到但标签不合法的响应，若用量可读则记入累计费用；当前代码也会保存有上限的原始响应摘录。只有错误码为 `S3_LABEL_OUTPUT_INVALID`、且失败组至少有 2 题时，教师显式重试才将该组折半：12 题拆成 6＋6，其中 6 题组再失败则拆成 3＋3；不足 12 题的实际组按当时题数折半。当前规则内已完成组不重发，调用次数与费用累计。请求失败、用量缺失或执行中断导致费用未知时暂停重试，须先核对账单。续跑预算须高于已记录费用；预算阈值在每组调用前检查，单次调用仍可能越过阈值。不会自动重试付费调用。

迁移 `0031` 停用旧批次的 8/4 活动分组：原分组及已发生的模型调用进入 `s3.label_group_audit`，活动 `groups` 清空。已完成的旧任务保留审核结果，不自动重新调用模型；未完成且费用已知的旧任务标记为需要重试，教师显式重试时按当前上限重新处理**整批**候选题，包括此前已成功的题目，因而会增加调用费用。费用未知的任务仍须先核对账单。旧分组不会继续执行，也不会作为失败组再拆成 4＋4。历史调用记录仅用于审计，不参与组卷或标签建议。

## 验证与待办

自动测试覆盖分组、标签白名单、题图请求、去重及答案前置条件、乱序响应、派生标签、教师修改保护、整批重打和已知用量的非法响应。导入页对缺少完整标签（正式题型、1～5 星难度、主属 KP 及派生标签）的题目显示“无标签，请人工打标签”，并显示缺标签题数；人工表单无需先取得模型建议。所有题具备完整标签是正式入库的必要条件。S5 教师最终审核和 S6 正式提交仍待实现；S6 服务端提交事务必须再次核验整批标签，不能仅依赖前端提示。已有真实付费标签调用，但标签准确率、题图理解效果和实际账单仍待人工核对；检查点费用只是估算。

2026-11-17 修正：正式目录的 21 个已有 KP 未逐项写 `available_for_import`，此前标签筛选把缺失字段当作 `false`，导致启动时报“当前没有可入库的正式知识点”。现在与现有题库标签校验保持一致：有正式 code、数据库中存在且未明确标记为不可入库的 KP 可以用于建议。运行中数据库只读核对结果为 21 个可用 KP；新增回归测试覆盖缺失该字段的情况。

后续代码复核发现：旧版重试不会替换未手动修改的旧标签；排队后改题仍可能外发旧内容；一个仍显示“处理中”的批次会挡住其他排队批次；标签任务部分失败时，未取得建议的题目没有手动标签入口。上述行为已修正。请求提示词明确列出本组题数和全部候选 ID，返回条数必须与发出题目数相同，且每个候选 ID 恰好出现一次。

2026-11-17 本地历史记录中曾发生 8＋8 分组及一次“未逐题返回或引用了错误候选”的失败调用。该错误表明返回的候选 ID 集合或条数与请求不一致；当时未保存可解析的响应正文，无法继续判断具体原因。迁移只保留这类真实调用审计，不再沿用其分组执行。未替用户发起付费重试。
