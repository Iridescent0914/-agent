# S3：题图提取与原页裁剪暂存

日期：2026-11-16。承接分文件答案识别。本次只处理题目文件中的题图，仍属于内部审核链路。

## 已实现

- S2 完成的批次可在导入页分别执行“扫描整份 PDF 嵌入图”或“只保存选区”，不调用百炼。前者用 PyMuPDF 按 PDF 中位图的实际出现位置生成独立 PNG；后者只渲染操作员框选的原页区域，适合矢量绘图、数轴和位图与文字混排的题图。框选无需先扫描，扫描也不由框选自动触发。DOCX 使用 S2 已校验的转换 PDF。
- 图片记录题目文件 ID、原页码、实际使用的归一化裁剪框、PNG SHA-256 与尺寸。界面列出自动提取图片所在页及每页数量；原页用绿色框标出自动提取区域、蓝色框标出手工框选区域，两类缩略图均直接显示。候选题的模型题图线索和已关联图片数供操作员对照，但模型线索不能保证检出所有未提取的题图；不根据题号或邻近文字自动指定归属。
- 操作员核对图片后，可显式关联同文件且来源页覆盖该图的候选题，也可取消关联。服务端检查来源页和候选 `revision`；普通候选题修改接口不能伪造 `asset_ids`。关联仍保留“须核对原页和图片完整性”的提示，不代表教师已确认。
- 原页和题图只通过批次 API 返回，响应禁止缓存，不设公开静态 URL。图片与原文件同属 72 小时临时资料，清理时一并删除；原文件过期后不能继续裁剪或预览。
- 对 PDF 图像/渲染设置像素上限和单批 500 处图片上限，超限明确失败。首次扫描会保留此前已保存的框选图；重复扫描沿用已暂存结果。

## 与“一次模型调用”的关系

题答同文件时，S2 已在同一 PDF 页段调用中提取题目和来源答案。当前 Flash 实测没有返回可靠题图坐标，S2 已取消坐标字段。模型无法通过现有结构化文本响应直接产出可审计的裁剪文件；本次由本地 PDF 渲染生成图片。后续可用标注过的含图题试验在一次模型响应中增加图片区域**建议**，由服务端按原页裁剪并人工核对，不能用未经验证的模型坐标直接确定题图归属。

## 尚未完成

- 当前图片仍是临时资产。S5/S6 须在文件到期前经教师审核并晋级为正式题库图片，保留历史试卷引用；不能把暂存 `asset_id` 直接当正式图片路径。
- 模型辅助的图片区域定位、图片与题目自动关联建议及真实含图资料准确率评测尚未实现。现有人工关联只限候选来源页段内；跨页或来源页码错误时须先修正题目证据。
- 正式多教师试用前仍需服务端可信身份及批次归属校验；当前批次 API 仅用于隔离内部演示。

## 验证

- 受控 PDF 同时包含嵌入红色位图和矢量线圆，验证只框选时仅产生一张选区图、之后整份扫描仍保留选区图，以及嵌入图清单、真实像素、原页渲染、幂等提取、版本冲突、非法裁剪框、私有访问与 72 小时清理。
- 未调用付费模型；真实含图 PDF 的提取完整率与图片归属率仍待人工标注评测。
