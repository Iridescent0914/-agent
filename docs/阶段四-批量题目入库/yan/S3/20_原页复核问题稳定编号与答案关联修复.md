# 原页复核问题稳定编号与答案关联修复

## 发现的问题

- 原页复核中的待认领答案使用 `answer:0`、`answer:1` 等数组位置作为问题编号。答案关联后数组缩短，旧复核结果可能显示在另一条答案上，并误报“候选内容已变化”。
- 手动启动整批模型去重后，程序曾继续自动调用原页模型复核待认领答案。这产生额外调用，也让“去重”与“原页复核”的操作边界不清楚。
- 再次计算来源答案关联时，已由原页模型关联的答案可能重新进入未归属清单。一个题目因而同时显示“经原页模型复核关联”和“归属待确认”。
- 原页复核页段行仅列可批量发送的未复核问题，原界面没有区分问题类型、已复核结果和候选题数。

## 当前行为

1. 整批去重模型读取候选题的文字、选项、题号和来源页码；题答同文件时也接收来源答案摘录作为判重上下文。它只输出重复候选建议。去重结束后，程序按规则计算来源答案关联；不会顺带调用原页答案复核模型。
2. 题答同文件在整批去重完成时计算答案关联；题答分文件在答案文件识别完成时计算。题答同文件的原页复核若删除了重复题，会再次计算。保留的恢复接口也可显式触发重新计算。
3. 答案复核问题改用来源文件、页码、题号、小题号和原文答案组成的稳定标识。旧的序号复核记录仍保存在批次中；仅当旧记录的完整问题指纹仍匹配时，才将其显示到当前问题。
4. 已关联的同一来源答案不会重新列为待认领，也不会在再次计算时覆盖教师修改。当前批次的页面清单根据候选题里的实际答案版本过滤旧统计记录；不会自动改写历史批次数据。
5. “按问题复核原页”按答案归属、未确定片段、疑似重复题分类，分别显示待复核数和已有结果数。页段行明确区分问题数与涉及的候选题数。

- 前端 TypeScript 与生产构建通过。
