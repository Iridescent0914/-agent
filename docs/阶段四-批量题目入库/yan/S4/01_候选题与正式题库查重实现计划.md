# S4：候选题与正式题库查重实现计划

日期：2026-11-20。状态：第一步精确查重、第二步索引近邻召回，以及第三步的证据和决定持久化已实现；人工样本校准、正式提交前复查和并发保护待开发。实现细节见 [02_精确查重第一阶段实现记录](02_精确查重第一阶段实现记录.md)、[03_索引疑似召回与差异展示实现记录](03_索引疑似召回与差异展示实现记录.md)和[04_查重证据与教师决定持久化实现记录](04_查重证据与教师决定持久化实现记录.md)。

## 1. 范围和前置条件

- **S3 负责本次导入任务内部的整批去重。S4 只比较 S3 保留的有效候选题与已有正式题库。**不重复调用 S3 的整批去重模型，不在 S4 删除候选题，也不自动修改正式题。
- 输入：`global_dedupe=completed` 的批次中未删除、未被 S3 去重移除的候选题；读取题干、选项、关键题图及候选 `revision`。标签可辅助排序，答案用于发现冲突，但都不作为题目精确指纹的一部分。
- 输出：每道候选题对应的正式题匹配列表、匹配类别、证据、检查版本及待教师处理状态。正式入库仍由 S5/S6 决定；`exact_in_batch` 只表示 S3/历史批内状态，S4 不重新计算。
- 不默认调用付费大模型。优先使用确定性指纹和数据库索引；疑似匹配阈值须以真实重复题、合法变式和含图题样本校准。
- 教师在 S3 去重后新增或修改候选题时，自行确认不会与本批其他题重复。系统不保证再次发现或阻断由这些修改产生的批内重复；S4 的编辑后重查和 S6 的提交前复查都仅针对正式题库。

## 2. 分步实施

### A. 固定匹配规则与评测样本

1. 收集一小组“候选题—正式题”人工标注对，覆盖完全相同、题号/空格/全半角不同、公式排版不同、数字或单位改变、选项顺序改变、相同题干但图不同、同题答案冲突和合法变式。分别记录应判“精确”“疑似”还是“不匹配”。
2. 区分两种结果：**精确重复**要求内容等价且关键题图一致；**疑似重复**只提示教师核对，不能直接当作同题。`resolved_variant` 必须对应教师对具体已有题的决定及理由。
3. 冻结可审计的规范化版本。只去掉可信的题号前缀及排版差异，保留数字、正负号、指数、分数、比较符号、单位、选项值与顺序。不能对数学文本盲目做 NFKC 后把 `10⁸` 变成 `108`；如要合并 `10⁸` 与 `10^8`，先识别指数结构再规范化。

### B. 精确匹配与题库指纹迁移

1. 规范化题干和选项后，结合关键题图的内容哈希计算版本化 SHA-256；不用临时 `asset_id`、文件路径或展示顺序代替图片内容。图片缺失、只提供描述或两侧关键图不能可靠比较时，不给出“精确重复”结论。
2. 当前 `questions.content_fingerprint` 已有索引，但旧规则仅规范化题干空白和全半角，选项、资产仍按原结构序列化。新规则须先确定版本化存储及迁移方式，回填历史正式题；所有正式题新建和内容编辑路径改用同一计算函数。回填期间允许旧指纹为空或不一致，但不得把“查不到”解释为“确认不重复”。
3. S3 保留的每道候选题用指纹走 B-tree 索引查询正式题库；同一指纹有多个历史正式题时全部返回，并核对规范化内容，避免哈希或旧数据造成误判。不遍历全库逐题比较。
4. 题目内容相同、答案不同仍视为题目重复，并另给“答案冲突”提示；新答案、解析或图片只形成补充建议，绝不自动覆盖已有题。

### C. 疑似题召回与精排

1. 为规范化检索文本建立 PostgreSQL `pg_trgm` 等索引，按索引召回少量 Top-K 候选，再比较题干、选项、数学量和图片，返回可理解的差异。题型、年级、章、KP 可用于优先排序，不作为跳过跨标签相似题的硬条件。
2. 对含图题使用内容哈希确认相同图；需要识别改尺寸或轻微裁剪的近似图时，再加入感知哈希。图不同、图缺失或图像相似但题目数据不同，只能进入疑似列表。
3. 用标注样本评估中文题干、公式和图片题的召回与误报。阈值、Top-K 和高/中疑似分级以测得结果确定，不直接采用计划中的示意数值；记录真实题库的查询计划和耗时。

### D. 结果、教师决定和失效规则

1. 保存每条匹配的候选 `item_id`/`revision`、规范化版本及指纹、正式 `question_id`、匹配类型、相似度、关键差异、正式题内容快照标识、检查时间和教师决定。建议用独立匹配记录承载一对多结果；现有 `duplicate_status` 仅作候选汇总，不能覆盖 S3 的批内问题线索。
2. 提供批次查重与结果查询接口。S4 先返回可核对的匹配信息；S5 再完成并排比较、跳过旧题、确认独立变式及理由录入。精确重复默认建议跳过，但不伪造教师确认，不自动删除候选或合并答案。
3. 候选题干、选项或题图变化后，旧结果失效并重新查重；正式题内容变化后，依据正式题快照识别失效。标签或答案变化不改变精确指纹，但答案变化可更新冲突提示。
4. S6 正式提交时对选中题重新查库，并在同一事务内使用按指纹串行化的锁或等价的唯一约束方案防止两个批次并发插入同一道题。现有历史重复题使直接给 `questions.content_fingerprint` 加全表唯一约束不可行，须先处理历史重复或采用兼容它们的保护方案；所有建题入口必须遵守同一规则。

## 3. 交付顺序与验收

1. **第一步：**规范化规则、真实样本基线、题库指纹迁移和精确匹配；先保证数字、符号、指数、单位、选项与关键图不同的题不会误判精确。
2. **第二步：**有索引的疑似召回、精排、图片近似比较、结果接口和批次耗时记录；验证历史多条精确重复题均可见，查询不会退化为逐题全表扫描。
3. **第三步：**候选编辑后的失效与重查、教师决定契约、S6 提交前复查及并发保护；S5 的完整审核界面依赖这些结果。
4. 自动化验证覆盖规范化边界、相同题不同答案、缺图/异图、历史重复、候选和正式题编辑、版本失效、并发提交。用人工标注对报告精确匹配误报、疑似召回漏报及查询耗时；没有样本时不宣称疑似题阈值已验收。

## 4. 与现有代码的衔接

- `Question.content_fingerprint` 及其索引已存在；`question_import.content_fingerprint`、历史迁移 `0029_question_import_s1.py`、正式题编辑与种子导入分别写过指纹。S4 实现时须统一版本和回填，避免同题因写入路径不同而得出不同指纹。
- `QuestionImportItem.payload.duplicate_status` 现有 `none / exact_in_batch / exact_in_catalog / suspected / resolved_variant` 契约。S3 的重叠题与整批去重状态继续保留；S4 的一对多“候选—正式题”关系要有独立证据记录，不能只靠该单值字段表达。
- 正式题图片与导入暂存题图的资产形式不同。比较时读取实际内容哈希；正式入库的图片晋级与持久化仍需在 S5/S6 完成，S4 不把临时图片 ID 当正式资产。
