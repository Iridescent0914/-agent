# S4 第二步：索引召回题库相近题

日期：2026-11-20。状态：只读召回与展示已实现；人工标注校准、结果持久化、教师决定和提交保护待开发。

> 2026-11-21 调整：根据教师核对需求，移除视觉特征距离计算与展示。题干文字相同而题图文件不同的相近题，直接提示人工对照，并提供正式题详情入口。以下原始记录中的视觉距离描述仅反映 2026-11-20 的实现，当前行为以本注释及代码为准。

> 2026-11-22 调整：文字近邻增设暂定的 **30% 展示门槛**（`s4-near-v3`）。仍先通过索引取前 32 道，精确命中另外保留；只有文字相近度达到门槛的非精确题才进入最多 6 道的新近邻核对列表。低于门槛的新近邻不再逐条要求教师作决定；已由教师作过决定且双方内容未变的历史近邻继续保留，避免重查抹去“跳过旧题”等决定。没有展示匹配时只表示“本次未检出需要核对的正式题，可按新题候选继续审核”，不表示已证明与题库所有题不同，也不自动完成教师审核。该门槛尚未经真实样本校准，后续小规模检查时复核；旧检查记录需重新执行 S4 才会使用新门槛。

## 实现

- 迁移 `0039` 启用 PostgreSQL `pg_trgm`，为未归档正式题的“题干 + 选项”建立 GiST 表达式索引。每道有效候选题通过 `<->` 索引查询至多 32 道相近正式题，不用逐题遍历整库。
- 新增只读接口 `GET /api/v1/question-imports/{batch_id}/s4/catalog-matches`，沿用 S4 精确匹配前置条件，返回精确匹配、最多 6 道相近题、候选版本、正式题审核版本、索引相近度、文字/数字/选项/题图差异和耗时。当前分数用于展示筛选与排序，不自动将相近题判为重复。
- 题图使用原始字节哈希识别完全相同的文件。双方各有一张但文件不同的图片时，额外给出 64 位视觉特征距离；距离没有经过真实图片题校准，仅供教师核对，不作为“同图”结论。缺图或无法读取的图仍显示无法可靠比对。
- 导入页的“检查题库重复”同时展示精确结果和可展开的相近题；编辑候选后按 `revision` 提示重新检查。接口不保存教师决定，也不改正式题、候选题或 S3 去重状态。

## 验证

- 本地数据库迁移到 `0039` 成功。定向测试验证数字变式不被判精确重复、可在相近题中找到、查询计划使用 GiST 索引，以及同一视觉图片的 PNG/BMP 文件得到相同视觉特征：`pytest -q tests/test_question_import_s4_exact.py tests/test_question_import_s3_images.py`，11 项通过。
- 前端 `npm run build` 通过。
- 对本地一批已完成 S3 去重的 22 道候选题做只读试跑，整批约 2.4 秒，数据库近邻查询合计约 0.21 秒。数字仅代表该本地题库和该批次，不是 200 题上限下的性能承诺。

## 验收边界与下一步

- 当前使用暂定 30% 文字相近度门槛过滤低分近邻；仍可能展示无关题，也可能漏掉文字差异较大但数学内容等价的题。需要少量真重复、合法变式、公式改写和含图题样本，复核该门槛对教师工作量与漏检的影响；未做检查前不宣称查重效果已验收。
- 视觉特征只比较双方各一张图，裁剪、转码和不同图形的距离效果尚需样本核对；多图题仍由教师逐图检查。
- 查重结果仍是点击时的只读快照。正式题在查询后编辑、候选再次修改，以及两批并发提交同题的防护，须由后续持久化记录、教师决定和 S6 事务内复查实现。
