# S5：教师审核工作台开发规划

日期：2026-11-22。状态：开发规划，尚未实现 S5 审核闭环。

## 1. 目标与边界

S5 让教师在一个工作台内完成候选题复核、问题处理、逐题决定和提交前检查，并保存可供 S6 使用的审核数据。S5 **不创建正式 `Question`，不晋级自动组卷池，也不保证检查后题库不会变化**；S6 必须在正式入库事务中重新校验并防止并发重复建题。

S4 的小规模人工查重检查按当前资源安排暂缓，不作为启动 S5 的前置条件。S5 可以展示 S4 精确命中和索引近邻，但不得把“没有命中”写成“确认没有重复”，也不得根据相近度自动批准。甲方真实试运行和宣称召回效果前，再执行该检查并记录结果；具体待办见 [S0 评测标注与验收准备](../S0/评测标注与验收.md)。

## 2. 当前基础与缺口

| 已有能力 | S5 需要补齐 |
| --- | --- |
| 三种文件方式、S2/S3 任务进度、候选题列表 | 按批次进度进入审核工作台，汇总可审、阻断和待处理数量 |
| 逐题编辑题干、选项、答案、标签和题图 | 题目审核与答案审核的独立确认记录，保存时绑定候选版本 |
| S3 错配答案、未确定片段、疑似漏题和待认领图片的展示 | 稳定的问题处理状态与必要的人工认领操作，避免仅在页面上“看过”就消失 |
| S4 精确匹配、索引近邻、匹配决定和失效提示 | 候选题与已有题并排核对；S4 决定纳入提交前检查 |
| `teacher_decision`、`commit_intent` 等候选字段 | 服务端审核动作、逐题阻断原因、批量选择规则和只读提交预检 |

沿用现有 `QuestionImportPage`、候选题 API、正式 KP 目录、S3 问题清单和 S4 查重记录，逐步抽出工作台组件；不重建上传和识别流程。现有原文件是私有且可能在 72 小时后清理。S5 展示已保存的来源页码、摘录和题图；证据已不可访问且影响核对时明确阻断相应确认，不把缺失证据伪装成已核对。

## 3. 教师操作流程

1. **选择批次并查看概况**：显示识别阶段、真实/测试候选数、已审/待审、精确命中、索引近邻、答案及图片待认领数。只有 S3 必要任务完成的真实候选题可进入审核。
2. **逐题核对**：左侧可筛选候选列表，右侧展示题干、选项、题图、来源页码和原文摘录、标签建议与正式 KP、答案各版本和来源、S4 匹配及教师理由。教师先保存修改，再确认审核；编辑不会隐式代表已确认。
3. **处理问题**：集中处理待认领答案/图片、疑似漏题、答案错配、模型失败和题库重复。支持有证据的认领或显式保留待处理；对无法判断的问题显示原因。题干所需的关键图片未确认时阻断题目审核。S3 完成后人工新增或修改的题目仍由教师核对批内重复；本阶段不声称系统自动重查批内重复。
4. **逐题作决定**：可拒绝无效候选题、跳过已有题，或确认题目。确认题目时明确选择“拟仅题目入库”或“拟题目与答案同时入池”。后一种还要单独核对选定答案的来源、逐小题/空结构和判分规则；模型文本及 `selected_answer_id` 本身不构成答案确认。
5. **提交前预览**：展示选中题的两条路径数量、已跳过和仍待处理数量，逐题列出阻断项与提醒项。S5 可保存审核决定和选择集合；“正式提交”入口须等 S6 事务性入库完成后才开放。

列表至少支持待审、已确认仅入库、已确认拟直接入池、已拒绝、已跳过、精确命中、索引近邻、查重过期、缺标签、缺答案、答案待确认、题图待认领、来源问题等筛选。重复题详情并排展示候选和正式题的题干、选项、题图及主要差异；相近度只作为检索排序线索。

## 4. 服务端审核契约

### 4.1 决定与版本

- `teacher_decision` 仍使用 `pending / approved / rejected / skipped_duplicate`；`approved` 同时保存 `commit_intent=library_only / direct_pool`。`skipped_duplicate` 只能由 S4 的证据绑定决定产生。`rejected` 与“删除候选题”区分：拒绝保留候选和原因，删除仍是显式操作。
- S5 审核动作落地时，通用候选题 `PATCH` 不再允许客户端直接写入 `approved / rejected` 或切换已确认题的 `commit_intent`；这些状态必须由绑定版本和审核证据的服务端动作产生，避免绕过审核记录。
- 新增服务端逐题审核动作，以 `item_id + expected_revision` 防并发覆盖。题目确认须保存审核时的候选版本、内容/标签/题图签名、决定、意向和时间；直接入池还须保存选定答案版本、结构化答案及审核时签名。审核日志追加保存，当前有效决定可在候选摘要中读取。
- 第一版采取保守失效规则：题干、选项、题图、标签、答案选择或答案内容发生修改后，相关审核确认失效并需重新确认；仅页面筛选、展开、查看不改变审核状态。服务端核对版本和签名，不能只靠前端按钮禁用。
- 内部试点仍使用现有 `internal-demo` 范围；不把客户端填写的姓名当作可信教师身份。多教师真实试用前，必须接入服务端身份与批次归属校验，并将审核事件绑定可信身份。

### 4.2 审核校验与预检

- 题目审核检查：真实非 fake 候选、题干/选项有效、题图完整、题型不是 `unknown`、难度 1～5、主属 KP 属于当前开放白名单且在数据库存在，批次冻结的标签目录仍有效；年级、章、节和完整核心素养从正式目录派生，不能由客户端独立覆盖。
- S4 检查：候选题必须有当前有效的查重记录；精确命中须跳过，索引近邻的每条展示匹配须有教师决定；`keep_variant` 保留理由。S4 只召回有限近邻，预检不得将其解释为全库无重复。最终复查留给 S6。
- 仅题目入库允许无答案，但需要明确提示后续答案待审核。直接入池仅面向当前日常池支持的选择、填空、判断题，并必须有教师确认的选定答案、`answer-units-v1` 结构和现有答案审核规则所需字段；复用或抽取现有 `question_review` 服务的纯校验能力，不复制一套不同的晋级标准。校验失败不得自动改成仅题目入库。
- `POST /question-imports/{batch_id}/s5/preflight` 建议为**只读预检**，输入选中题 ID 与各自预期版本，返回逐题 `blockers / warnings / route` 和汇总数量。预检不写题库、不冻结题库、不代替 S6 的事务校验。错误码沿用现有 `REVISION_CONFLICT`、`TAG_CONFLICT`、`CONTENT_INCOMPLETE`、`ASSET_UNASSIGNED`、`DUPLICATE_DECISION_REQUIRED` 等语义。

### 4.3 问题处理与批量操作

- 为待认领答案、图片和疑似漏题保留稳定标识、来源证据、处理决定和理由。人工认领要校验目标候选、批次及版本；忽略和延后须显式选择，不改变原始提取证据。被延后的非关键资料可留在批末；关键题图缺失不能靠“延后”绕过。
- 批量操作只作用于明确选中的候选题，并逐条校验预期版本。可批量拒绝或设为仅入库的候选，前提是每题已独立完成相应核对；不能对未审题一键批准，也不能把一题的答案确认套用给整批。
- 问题决定、审核决定和批量操作保留审计；刷新页面后应从服务端恢复。批量请求若有一条版本冲突，第一版整组回滚并返回逐题冲突，避免页面显示部分成功却难以追踪。

## 5. 前后端实现顺序

1. **S5-A：审核状态和只读预检**。定义响应字段与阻断规则；抽取题目/答案审核校验；实现逐题有效性和批次汇总查询。用固定候选数据先验证标签、图片、重复和答案分支。
2. **S5-B：逐题审核与问题决定**。新增版本绑定的审核动作、审核日志及问题处理记录；接入必要的答案/图片人工认领。修改候选后验证确认失效、版本冲突和刷新恢复。
3. **S5-C：工作台界面**。将现有导入页拆为概况、候选列表、单题详情/并排查重、问题清单和提交前预览；复用已有上传、编辑、标签和 S4 操作，不改变原入口路径。
4. **S5-D：批量操作与联调**。仅对已核对的选中题执行批量决定，展示两条意向路径；完成三种文件方式的受控端到端流程，给 S6 固定提交输入契约。

## 6. 验收与交给 S6 的条件

受控测试至少覆盖：页面刷新后决定仍在；并发编辑返回版本冲突；修改题干/题图/标签/答案后旧确认失效；未知 KP 和不完整派生标签阻断；缺图阻断；精确重复不能确认新建；近邻待决定阻断；仅入库可无答案；直接入池缺结构化答案或教师确认时阻断；fake 候选不可批准；未认领的非关键资料可保留且不被错挂。

S5 交给 S6 的是：选中候选的 ID、预期版本、有效题目审核记录、可选的独立答案审核记录、明确的入库意向、S4 决定引用，以及逐题预检结果。S6 必须重新读取和校验这些数据，在同一事务内做最终题库查重、并发保护、正式题图资产晋级、建题和审计；S5 的预检成功不保证随后提交一定成功。

## 7. 暂缓事项

- S4 小规模人工标注检查按当前资源安排推迟到甲方真实试运行前；届时优先使用现有题目构造少量可确定的正反例，再复核少数真实相近题。未完成前不报告真实召回率、误报率或“已通过”阈值。
- 暂不增加向量相似度检索。只有后续标注案例显示现有文字召回确有明显漏检时，再评估作为补充召回通道。
- 资料答案的独立模型冲突预审仍为可选需求，不作为 S5 主链路前置条件。
