# S5-B：逐题审核与问题处理实现记录

日期：2026-11-22。状态：服务端 S5-B 已实现；工作台界面与批量确认分别留给 S5-C、S5-D，正式入库留给 S6。

## 审核动作

- 新增 `POST /api/v1/question-imports/{batch_id}/s5/items/{item_id}/decision`。请求包含 `expected_revision`、`decision=approved/rejected/pending`；批准时必须指定 `route=library_only/direct_pool`，直接入池还需逐题提交 `answer_review_items`。拒绝必须填写理由。接口锁定批次与候选、核对版本，批准时重新执行 S5-A 预检；阻断时不保存决定。
- 确认会单独写入题目审核事件；直接入池还会写入同一次操作对应的答案审核事件，记录答案来源版本 ID、结构化答案、标准化规则和候选版本。事件保留当时的内容与 S4 决定签名。`GET /api/v1/question-imports/{batch_id}/s5/reviews` 返回当前有效决定、历史最新决定与失效状态。读取时重新检查版本、签名及当前预检；旧记录只用于追溯，不能作为 S6 的有效确认。
- 通用候选题 `PATCH` 已不接收 `teacher_decision` 或 `commit_intent`。修改题干、选项、标签、所选答案或答案文本会退回待审；题图关联或上传也会退回待审。仅查看和预检不修改状态。S4 的“跳过已有题”仍由 S4 匹配决定产生，并保留其正式题引用和理由。
- 批次汇总的已批准、已拒绝数量改按**有效审核记录**计算，另报失效记录数量。仅题目入库继续允许暂缺答案；直接入池继续复用正式答案审核的结构与自动判分规则。以上都是 S5 审核意向，不会创建正式题。

## 问题处理

- `GET /api/v1/question-imports/{batch_id}/s3/review-issues` 现为每个问题返回稳定 `key`、证据 `signature` 和最近一次处理状态。未认领题图以 `image:{asset_id}` 纳入清单；来源答案、疑似漏题、跨页重复和答案配对提醒继续沿用原有清单。
- `POST /api/v1/question-imports/{batch_id}/s5/issues/decision` 保存 `acknowledged/deferred/ignored/pending` 及理由。忽略或延后须写理由。处理事件与证据签名绑定；源证据变化后显示失效，必须重新判断。与候选题相关的跨页重复问题阻断题目确认；答案关联提醒阻断直接入池确认，直到有有效的人工处理决定。关键题图缺失仍由预检阻断，不能通过“延后”绕过。
- `POST /api/v1/question-imports/{batch_id}/s5/issues/claim-answer` 将当前未认领的来源答案关联到指定候选，要求问题签名、候选版本和批次来源文件一致，并防止同一来源答案重复认领。认领会创建未审核的来源答案版本、更新候选版本、撤销旧确认；之后仍须单独审核答案。题图认领沿用 S3 已有的题图关联/上传接口。
- `POST /api/v1/question-imports/{batch_id}/s5/items/{item_id}/confirm-answer-source` 供教师确认当前选定答案确实属于该题。它保存来源关联决定并更新候选版本，但**不代表答案内容正确**；直接入池仍需提交独立的结构化答案审核。冲突或未匹配的来源须填写人工关联理由。

## 数据和验证

迁移 `0041_question_import_s5_audit.py` 新增追加式 `question_import_audit_events`，保存审核、答案认领与问题决定。当前试点仍以服务端 `internal-demo` 范围记录事件；它不是可信的教师个人身份。多教师使用前需要接入身份与批次权限。

定向测试覆盖审核记录刷新读取、并发版本冲突、修改后失效、阻断不能批准、题目与答案分别记录、拒绝理由、待认领答案防重复、问题证据失效、未认领图片处理及 HTTP 契约。正式题入库、批量确认、跨批次并发查重和题图晋级均由后续阶段处理。
