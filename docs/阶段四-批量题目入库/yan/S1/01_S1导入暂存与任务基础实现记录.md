# S1 导入暂存与任务基础实现记录

日期：2026-11-11。阶段定位：**内部开发基础**，尚不向教师开放正式批量入库。本文记录本轮代码实现和已完成的验证；S2 解析、S3 模型处理、S4 查重、S5 审核工作台及 S6 正式提交均不在本轮范围。

## 1. 本轮实现

### 数据库与来源追溯

- Alembic `0029_question_import_s1.py` 新增 `question_import_batches` 和 `question_import_items`。批次记录场景、目录快照 SHA-256、文件清单、状态、检查点、错误、租约、心跳、尝试次数和过期时间；候选题记录原始 payload、版本和 fake 标记。
- `questions` 新增 `content_fingerprint`、`import_batch_id`、`import_item_id`。迁移对历史题目回填 SHA-256 规范化指纹，不设全表唯一约束，也不删除或合并历史重复题。现有题库编辑和种子导入后会同步计算指纹。S4 再利用索引实现批内及题库内查重。
- 同一服务端工作区内，同一文件内容、文件角色、场景和目录版本在临时文件仍保留期间重复上传，返回已有批次；取消批次后可以重新上传。同一工作区创建批次时使用 PostgreSQL 事务锁序列化，避免并发绕开去重和七批上限。

### 文件上传与保留

- `POST /api/v1/question-imports` 接受 `questions_only`、`combined`、`separate` 三种场景。前两种上传一份题目文件，分文件场景上传题目和答案两份文件。
- 文件按服务端 UUID 重命名，保存在 `data/uploads/question_imports` 私有目录；不挂载到 `/assets`，也不提供文件下载接口。数据库只保存受控文件 ID、原文件名、角色、实际类型、大小、PDF 页数与 SHA-256。
- 服务端检查真实 PDF/DOCX 文件头、PDF 加密与页数、DOCX 必要 OOXML 结构、宏/加密/异常压缩。单文件 30 MB、单批 60 MB、最多 2 文件、PDF 最多 50 页由配置控制。DOCX 正文 10 万字符和最多 200 道候选题分别由 S2 解析后校验；当前 S1 的候选题暂存入口已限制 200 条。
- 上传原件最多保留 72 小时；当前内部工作区最多保留最近 7 批的临时文件。第 8 批上传时优先清理最早的已完成或已取消批次；失败批次保留供重试。若没有可清理批次，则返回冲突。到期后维护任务清理文件，并将未完成批次标记为 `FILE_EXPIRED`。文件元数据和审核记录仍留在数据库。

### 任务与候选题 API

| 接口 | S1 行为 |
| --- | --- |
| `GET /api/v1/question-imports`、`GET /{batch_id}` | 查询批次状态、阶段、文件摘要和失败原因 |
| `POST /{batch_id}/cancel`、`POST /{batch_id}/retry` | 显式取消和失败批次重试；过期或已清理文件的批次须重新上传 |
| `GET /{batch_id}/items`、`PATCH /{batch_id}/items/{item_id}` | 查询候选题及按 `expected_revision` 乐观锁修改；修改不允许独立写入章、年级、节和素养 |

后台 worker 从数据库领取 `files_saved` 批次，设置租约和心跳，逐文件校验保存后的 SHA-256 和大小，并把已通过的文件写入检查点。重启或租约超时后可以继续未完成文件；连续 3 次超时进入失败状态，显式重试会重置尝试次数。通过校验后批次停在 `uploaded / awaiting_s2`，**不生成真实题目**。确定性 fake 候选题构造器仅供测试/联调，候选题另有 `is_fake` 持久标记；当前没有正式提交接口，因此 fake 内容无法写进正式题库。

### 前端

新增 `/question-imports` 页面和导航。教师可以选择三种文件场景、选择 PDF/DOCX、查看上传进度与批次状态、重试失败批次或取消批次。页面明确说明当前仅保存和校验文件，等待 S2 解析。

## 2. 当前身份边界

现有系统没有可信的教师登录身份。S1 使用**服务端固定的单一内部工作区**管理上传计数和批次归属，不接受客户端传来的 `operator_name` 作为权限凭据。这个实现仅适合当前内部开发环境；对外多教师试用前，须把工作区与服务端认证身份绑定，并验证批次读取、修改、清理的隔离规则。该要求在 S6 前必须完成。

## 4. 运行与 S2 接口边界

在其他环境部署或复验时，从 `code` 目录依次执行：

```powershell
docker compose build backend
docker compose up -d backend
docker compose exec -T backend python -m alembic current
docker compose exec -T backend python -m pytest -q tests/test_question_import_s1.py
docker compose exec -T backend python -m pytest -q
docker compose exec -T frontend npm run build
```

运行中的前端入口为 `/question-imports`，API 基址下的批次入口为 `/api/v1/question-imports`。服务端环境变量示例见 `.env.example` 中的 `QUESTION_IMPORT_*`；私有上传目录位于 `data/uploads/question_imports`。无需重新导入题库种子。

### S2 接口边界

S2 从 `uploaded / awaiting_s2` 批次读取受控文件 ID，校验目录快照及文件仍在保留期内，再按 PDF/DOCX 的页、段、表格和图片证据生成候选题。候选题写入 `question_import_items` 时沿用批次 ID、目录哈希、来源文件 ID 和 `revision=1`；模型建议不能写入教师审核决定，`is_required` 初始为 `false`。S2 需要补上 DOCX 正文字符数、候选题量以及真实资料切题的验收。

当前 7 份 PDF 可直接用于 S2 试解析；页级 CSV 不是题级金标准。扫描页、题答同文件和明确错位答案仍需取得样本后补测。
