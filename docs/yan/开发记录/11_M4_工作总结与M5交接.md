## 1. 已完成范围

M4 已把 M3 发布试卷与 M2 可重放画像连接成内部闭环：教师可以在批改工作台选择已发布学生试卷，逐题录入答案或标记留白；首次录入会锁定题库中当时已发布且可机判的标准答案，因此录入前完成的答案修订会直接用于首次评分，不确定项进入人工复核。教师确认、改判、修正学生答案或撤销确认后，系统追加 `AttemptRevision`。只有题库答案在提交后再次修订并发布时，教师才需要显式重新评分已有提交；新评分依据保存在修订中，原 `PaperInstanceItem` 发布快照不变，并在同一事务中全量重放该学生当前有效证据、持久化 `StudentMastery`。

本阶段没有接入 OCR、VLM、打印答题区、分值或步骤给分。

## 2. 判分内核

新增模块：

```text
app/services/grading/contracts.py
app/services/grading/normalize.py
app/services/grading/numeric.py
app/services/grading/engine.py
```

统一入口为 `grade_answer(...) -> GradeResult`，规则版本为 `m4-grading-v1`。支持：

- `choice`：全角、大小写和首尾空白按快照规则处理；
- `exact`：只执行快照显式配置的有限文本归一化；
- `numeric`：使用受限 Python AST 和 `Fraction` 精确有理数计算；
- `latex_exact`：相同的规范 LaTeX 源码自动确认，不同写法进入人工复核；
- `group`：按 `item_id` 对齐小题，保留逐项结果，整组仍对应一个 Attempt。

numeric 禁止变量、函数、属性访问、字符串和任意代码执行，对输入长度、AST 节点、括号深度、指数和结果位数设有上限。解析失败、除零或超限进入 `needs_review`，不记为错误。`1/2`、`0.5`、`2/4` 是否等价严格服从发布快照中的格式开关。

## 3. 数据库与迁移

新增迁移：

```text
0011_add_m4_grading_guards.py
0012_add_attempt_revision_operator.py
```

新增字段：

- `Submission.request_fingerprint`：保存 M4 请求规范化 SHA-256；
- `Attempt.grading_details`：保存引擎版本、自动结果、原因码、规则和小题结果。
- `AttemptRevision.operator_id`：保存新 M4 修订的规则引擎或教师操作人；历史种子记录允许为空。

新增或补强约束：

- `needs_review` 必须对应 `is_correct=null`；
- 确认状态必须对应布尔结果；
- OCR 置信度若存在必须位于 0～1；
- Submission 学生必须属于 PaperInstance；
- Attempt 的 Submission、Student、PaperItem 和 Question 必须一致；
- Attempt 当前 `revision_no` 必须存在对应 AttemptRevision；
- AttemptRevision 禁止更新和删除。

历史 15 个种子 Submission 和 150 个 Attempt 兼容迁移，历史 `request_fingerprint` 允许为空。

## 4. 提交与复核事务

主要模块：

```text
app/services/submission_workflow.py
app/schemas/submissions.py
app/api/routes/submissions.py
```

首次提交固定流程：

```text
锁 Student
→ 锁 PaperInstance
→ 校验 active published 和学生归属
→ 校验完整答案集合
→ 计算 request_fingerprint
→ 幂等检查
→ 创建 Submission / Attempt / revision 1
→ load_context + persist_mastery
→ 请求成功后统一 commit
```

教师复核支持：

- `confirm`：确认或改判为正确/错误；
- `correct`：修正原始录入，重跑自动判分后保存教师最终结论；
- `reopen`：撤销确认，恢复 `needs_review + null`。

所有复核请求必须携带 `expected_revision_no`。陈旧请求返回 409；当前状态未变化时返回 no-op，不增加 revision。`answered_at` 始终保留原作答时间，教师操作只更新 `reviewed_at` 和 revision 时间。

GET   /api/v1/submissions/{id}

M3 的 `GET /paper-instances/by-code/{instance_code}` 继续负责精确版本定位。失效版本不能创建新 Submission，但在有效期间已经创建的 Submission 仍可查看和继续复核。

## 9. M6 接入约束

M6 只需把图片识别结果转换为 M4 的答案合同，并复用同一判分服务。不得改变：

```text
精确 paper_instance_id / instance_code 绑定
PaperInstanceItem 发布快照永久不变
首次录入使用当时题库中已发布且可机判的答案，并冻结本次评分依据
提交后题库再次修改时，必须由教师显式重新评分，历史结果不得静默漂移
一份试卷一个 Submission
一题一个 Attempt
AttemptRevision 追加式审计
expected_revision_no
teacher_confirmed 不被识别重跑覆盖
同一事务中的画像重算
```

图片附件、识别状态和 OCR/VLM 自报置信度在 M6 作为增量字段和流程接入；识别失败不能写成答错。

## 10. 当前边界

- 当前仍使用固定操作人 `demo_teacher`；
- 没有 Class 实体和真实权限系统；
- 小题组只展示答对项数，不做分值或部分掌握度；
- numeric 只支持有限有理数算术，不处理变量代数式；
- 公式键盘负责可靠录入表达式，不代表已经支持任意代数等价；`latex_exact` 仍按规范 LaTeX 精确匹配，复杂等价判断可在后续引入 CAS/受控模型复核；
- 未实现批量图片上传、打印、二维码和 VLM；
- 前端主包仍有既有体积提示，M5 可进行路由懒加载。
