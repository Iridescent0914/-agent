# M5 工作总结与 M6 交接

> 完成日期：2026-09-29  
> 阶段状态：班级学情、作业进度、固定演示场景、路由拆分和 M5 质量保障已实现；尚未开始 M6 打印答题区、图片上传和 VLM 识别。

## 1. 已完成范围

M5 将 M0～M4 的内部业务闭环整理为可解释、可下钻、可重复演示的教师工作台。系统默认进入“班级学情”，教师可以查看考点正确率、掌握度参考均值、证据覆盖、未评估状态、作业进度和待处理事项，并从班级考点下钻到学生画像、具体 Attempt 和批改页面。

M5 没有修改 M4 的判分与画像语义，没有增加数据库迁移，也没有接入 OCR/VLM。Alembic head 仍为 `0012`。

## 2. 后端聚合

新增：

```text
app/schemas/analytics.py
app/services/class_analytics.py
app/api/routes/analytics.py
```

新增 API：

```text
GET /api/v1/analytics/classes
GET /api/v1/analytics/class-overview
GET /api/v1/analytics/classes/exam-points/{exam_point_code}/students
GET /api/v1/analytics/assignments/{assignment_id}
```

聚合服务直接复用 `load_context()` 和 `mastery_items()`，与个人画像共享以下语义：

- 只有 `auto_confirmed`、`teacher_confirmed` 的有效当前修订进入正确率和 mastery；
- `needs_review` 只进入待复核数量，不进入正确率分母；
- 历史考点来自 `PaperInstanceItem.exam_point_snapshot`；
- 未评估学生不按 0 或 0.5 参与班级均值；
- 班级均值同时返回证据学生数和稳定证据学生数；
- 异常证据显式计数，不静默当成正常记录；
- 同一 Assignment 每名学生只统计当前有效已发布版本；旧版单独进入历史作废计数；
- 如果同一学生存在两个当前有效发布版本，聚合拒绝任选其一并返回冲突。

当前 Demo 继续使用 `Student.class_name` 表示班级，没有提前引入不完整的 Class / Membership 模型。

## 4. 固定演示场景

新增：

```text

```

场景：

- `m5_start`：5 份有效已发布试卷均未提交，用于从录入开始演示完整闭环；
- `m5_showcase`：同时包含完成、待复核、未提交、错题和教师错改对历史，用于直接展示教师工作台。

场景使用固定 `as_of`、稳定学生编号、seed key 和 idempotency key，不保存数据库 UUID。构造过程调用正式组卷、发布、提交和复核服务，不直接插入 Attempt 绕过业务守卫。

`prepare_m5_demo.py` 幂等但不会删除审计记录。重复恢复初始状态使用独立数据库 `math_agent_m5_demo`；PowerShell 重置脚本要求显式确认，并精确检查数据库名，不会删除默认 `math_agent` 开发库，也不会关闭 AttemptRevision 保护触发器。

## 5. 前端工程质量

所有页面改为 `React.lazy` 路由级加载，默认入口改为 `/analytics`。Vite 安全拆分结果：

```text
ClassAnalyticsPage       12.89 kB（gzip 4.82 kB）
vendor-react            165.07 kB（gzip 53.93 kB）
vendor-zrender          176.90 kB（gzip 59.22 kB）
vendor-echarts          342.60 kB（gzip 118.51 kB）
最大通用共享块          364.34 kB（gzip 119.22 kB）
vendor-mathlive         818.33 kB（gzip 225.83 kB）
```

ECharts 与 zrender 已从页面代码和通用共享块中拆出，构建没有循环 chunk 告警。MathLive 本身是单模块大包，但只被需要公式录入的懒加载路由引用；构建仍如实保留大于 500 kB 的提示，没有调高告警阈值。

M5 学情页在 1440×1000 和 390×844 下均有自动测试；图表提供 aria-label 和完整表格替代，状态不只依赖颜色表达。

## 7. `verify_m5.py`

脚本只读检查：

- 班级学生与考点目录；
- `correct + incorrect = confirmed`；
- `evidence + unassessed = student_count`；
- 无分母指标必须为 null；
- 聚合结果与逐学生有效证据独立计数一致；
- `StudentMastery` 与 replay 一致；
- Assignment × Student 不存在两个当前有效发布目标；
- 所有非历史 Assignment 均可无歧义聚合。

当前库没有准备固定 M5 场景时只输出 warning，不作为数据错误；隔离演示库应先运行 `prepare_m5_demo.py` 再验收。

## 8. 当前边界

- 仍为一个 `六年级 Demo 班`，使用 `Student.class_name`；
- 聚合为实时计算，适合当前 5 名学生；大规模班级后再设计批量加载和缓存；
- mastery 是透明 EMA 组卷参考值，不是标准化能力测评分；
- 没有教师确认的能力维度映射，因此不展示能力雷达；
- 小题组仍按整组一个 Attempt 统计；
- 没有真实权限和教师账号，操作人仍使用 Demo 标识；
- MathLive 懒加载块仍较大；
- 未实现打印、图片上传、二维码、OCR/VLM 和真实图片效果评估。


M6 必须继续保证：识别失败不算错、模型置信度不等于判分概率、重新识别不覆盖教师确认、重复上传不重复更新画像。
