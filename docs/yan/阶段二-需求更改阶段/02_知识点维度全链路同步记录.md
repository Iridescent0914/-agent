# 知识点维度全链路同步记录

## 1. 调整目标

新版题库已经不再采用旧 Word 的“考点”，因此本次继续检查并同步以下链路：

`题目稳定 ID → 当前正式知识点 → 学生作答证据 → 学生画像 → 班级学情 → 推荐组卷 → 草稿试卷 → 已发布历史快照`

对教师和学生展示的概念统一为“知识点”。数据库与接口中原有的 `ExamPoint`、`exam_point_*`、`tracking.*` 名称暂时保留，作为兼容既有画像、推荐、组卷代码的一对一内部跟踪键，不再代表旧 Word 考点。

## 2. 审计结论

### 2.1 已经正确的部分

- 当前 139 道未归档题目的主关联均已指向新版知识点对应的 `tracking.*` 节点。
- `questions.main_knowledge_point_id` 与主跟踪节点所属的正式 `KnowledgePoint` 完全一致，错配数为 0。
- 学生画像通过稳定 `question_id` 将已发布历史快照中的旧考点映射到题目当前知识点，再重放 EMA；不会继续生成旧考点画像。
- 班级学情与学生画像共用同一套证据加载和掌握度重放逻辑。
- 新建推荐和组卷只读取当前仍被未归档题目引用的知识点目录；旧考点不会出现在可选范围中。

### 2.2 本次发现并修正的问题

1. 判断题已经进入自动组卷池，但画像证据校验仍只接受选择题和填空题，会把判断题作答误判为非法证据。现已加入 `true_false`。
2. 班级学情统计待复核数量时曾直接读取不可变历史快照中的旧 ID。现改为读取已经映射后的 `effective_main`，与个人画像保持一致。
3. 学生掌握度筛选接口现支持旧链接中的 ID 自动映射到当前知识点，返回值和计算仍使用当前知识点。
4. 推荐理由和校验错误中的“考点”文案已改为“知识点”。
5. 既有作业范围、生成配置、草稿试卷知识点快照和草稿推荐审计中仍有旧 ID，现已通过 `0022` 数据迁移转换。
6. 从旧已发布试卷创建新版本时，新草稿会刷新为题目当前知识点，不再复制旧知识标签。
7. 教师试卷页、学生试卷页和批改页会按稳定题目 ID 展示当前知识点；底层已发布快照仍保持不可变，以保留历史审计证据。

## 3. 历史快照处理原则

已发布试卷及其题目快照不能直接改写。否则当时发给学生的内容和事后看到的审计记录会不一致。

本次采用以下规则：

- **当前统计**：通过题目稳定 ID 映射到当前正式知识点后计算。
- **当前教学页面**：展示题目当前正式知识点。
- **历史证据详情**：仍可查看当时保存的原始快照。
- **草稿和作业配置**：属于可操作数据，直接迁移到当前知识点。
- **已发布快照**：保持不可变，不作为旧口径继续统计。

## 7. 运行命令

在 `D:\desktop\math-agent\code` 中执行：

```powershell
docker compose up -d --build
docker compose exec backend alembic upgrade head
docker compose exec backend python -m scripts.seed_database
docker compose exec backend python -m scripts.rebuild_mastery
docker compose exec backend python -m scripts.verify_m1
docker compose exec backend python -m scripts.verify_m5
```

说明：后端容器启动时本身会执行 `alembic upgrade head`。已有数据库只需重新构建并启动即可执行 `0022`；`seed_database` 是幂等的，`rebuild_mastery` 用于显式重建学生掌握度物化结果。
