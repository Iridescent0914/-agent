# 组卷错误提示下移与提示清单记录

日期：2026-10-28

## 问题

组卷页的全局错误提示原本位于页面顶部、教学范围标题区之后。教师在页面下方点击“预检全部学生”或“确认并生成草稿”时，错误虽然已经出现，但可能处于当前视口之外，容易被误认为按钮没有响应。

## 修改

- 将全局错误 `Alert` 从页面顶部移动到整个组卷配置与预检结果的末尾。
- 未生成预检结果时，错误显示在组卷配置卡片下方。
- 已生成预检结果时，错误显示在预检结果及“确认并生成草稿”按钮下方。
- 增加浏览器回归断言，校验错误提示的纵向位置位于组卷配置卡片下方。

涉及文件：

- `frontend/src/pages/AssignmentCreatePage.tsx`
- `frontend/tests/m3.spec.ts`

## 当前可能出现的提示

全局提示的标题统一为“操作失败”，其具体原因不只有“请选择个性化模块的知识点”。当前前端主动产生的原因包括：

- 请先完成作业标题、班级、年级和章节选择
- 请选择至少一个年级和章节
- 请设置至少 1 道必做题
- 请选择个性化模块的知识点
- 请选择所选知识点对应的主要能力
- 历史回顾作业无效，请重新选择

表单字段下方还可能单独显示“请选择班级”“请选择至少一个年级”“请选择至少一个章节”“请选择至少一个知识点”“请选择主要能力”等字段级校验信息。

接口请求失败时，同一个全局错误提示还会显示后端或网络返回的原因。和当前组卷流程直接相关的后端业务提示包括：

- 个性化知识点不存在
- 个性化知识点不属于所选章节
- 主要能力不属于所选知识点
- 历史回顾作业不存在
- 历史回顾作业不属于当前班级
- 历史回顾作业尚未全部批改完成
- 历史回顾作业不在当前班级最近五次可回顾作业中
- class not found
- class has no active students

服务器不可访问或返回非业务错误时，也可能显示 `Failed to fetch` 或按 HTTP 状态生成的请求失败信息。

## 验证

- `npm run typecheck`：通过。
- Playwright：`required filters use catalog grades and required-only inventory`（desktop）通过；该用例包含错误提示位于配置卡片下方的回归断言。

测试过程中曾用未加入后端跨域白名单的临时前端端口执行依赖真实接口的用例，出现 `Failed to fetch`；改用完全模拟接口的目标用例后通过。该失败与本次页面修改无关，也进一步确认了网络异常会复用同一个全局错误提示。
