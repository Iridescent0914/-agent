# 历史回顾组卷接入记录

> 日期：2026-10-26  
> 实施人：yan  
> 范围：教师指定历史作业、逐学生错题回顾、缺口诊断与选择审计

## 1. 实现范围

教师可以从当前班级最近五次全部批改完成的作业中明确选择一份历史来源。系统不根据“昨天”等相对时间自动猜测来源，也不会把尚未批改完成的作业作为候选。

选择来源后，预检与正式生成会按每名学生自己的最终错题结果追加历史回顾题。没有符合条件错题的学生不生成历史题。

## 2. 历史来源与逐学生选题

### 2.1 可选来源

“最近已完成作业”现在表示：

1. 属于当前所选班级；
2. 没有草稿试卷；
3. 至少有一份当前有效的已发布试卷；
4. 每份有效试卷的每道题均存在最终判定，不能仍为 `needs_review`。

接口仍为：

```http
GET /api/v1/assignments/recent-completed?limit=5&class_id=<class_id>
```

系统不根据“昨天”自动推断来源，教师选择的 `assignment_id` 同时进入请求指纹、作业配置和审计。

### 2.2 逐学生选题

对每名学生独立读取所选来源作业：

1. 只读取 `source_module = required`，或旧审计中带有 `required_question` 原因码的必做题；
2. 使用 Attempt 当前最终结果，只处理已确认且错误的题；
3. 只处理难度为一至三星的错题；
4. 每道符合条件的错题请求一道同知识点、同难度的题；
5. 候选题不受本次年级和章节限制，直接按来源错题的知识点和难度匹配，并且必须未归档、可机判、已审核；
6. 排除原错题、当天必做题和已经选中的其他历史题；
7. 候选池按 `original_qid / question_id` 稳定排序，保证预检与正式生成一致；
8. 没有符合条件的错题时，该学生不生成历史回顾题。

库存不足时保留实际选中题目，并返回 `insufficient_history_inventory`，不会换知识点或跨难度补齐。

## 3. 审计

推荐结果和试卷题目选择审计新增：

```text
source_module = required | history | personalized | legacy_recommendation
```

历史题还记录来源错题 Attempt 与修订号，原因码包含：

```text
history_review
source_required_wrong
same_knowledge_point
same_difficulty
```

因此可以从生成后的题目回溯到所选历史作业中的具体错误证据。

## 4. 尚未实现的周规则

以下规则本轮没有伪装成已完成：

- 同一知识点连续错两次后的“是/否”状态；
- 周五按每个“否”知识点生成两道题；
- 周总结再次错误后标记“弱”。

继续实现前需要先确定：哪些作业属于日常作业或周总结、连续两次是否跨教师选定来源、周五使用哪个时区和校历、状态是实时计算还是持久化。确定合同后再增加状态表、迁移和周任务选题逻辑。
