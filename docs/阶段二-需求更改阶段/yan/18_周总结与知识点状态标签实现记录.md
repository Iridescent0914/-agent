# 周总结与知识点状态标签实现记录

> 完成日期：2026-10-29
> 范围：独立周总结组卷、连续错题标签、库存短缺草稿、前端入口与画像展示
> 后置：按知识点正确率动态确定周总结难度

## 1. 最终业务口径

周总结不是周五自动附加到当天作业中的模块，而是一份独立作业。教师可以在普通作业之外单独创建、预检、调整、发布和批改周总结。

连续错两次采用可追溯的业务链路：

```text
必做题答错
→ 后续历史回顾题由该错题生成
→ 历史回顾题再次答错
→ 知识点标“否”
```

因此周总结不会把任意两道同知识点错题误判为连续错两次，只认 `source_module = history` 的最终确认错误。

周总结中每个“否”知识点出两道题。当前动态难度尚未实现，统一使用三星；周总结两题中任一题最终确认错误时标“弱”，全部正确时标“是”。

## 2. 来源作业选择

需求同时出现“最近五次”和“最多选择六个”。当前采用能同时支持多选上限的口径：

- 查询当前班级最近六次已全部批改完成的普通作业；
- 来源作业必须包含必做题；
- 教师选择一至六份；
- 周总结作业不会进入下一次来源列表；
- 不依赖自然日、周五、节假日或校历自动判断。

后端请求合同：

```json
{
  "class_id": "uuid",
  "source_assignment_ids": ["uuid", "uuid"]
}
```

创建请求另外包含 `title` 和 `idempotency_key`。

## 3. 逐学生“否”知识点

教师选择的来源作业对全班相同。系统逐学生读取这些来源作业中当前有效发布试卷的最终 Attempt，只保留：

- `source_module = history`；
- `grade_status = auto_confirmed | teacher_confirmed`；
- `is_correct = false`。

同一学生同一知识点在多个来源作业中再次答错时只生成一组周总结题，但选择审计保留全部触发 Attempt 及其修订号。没有“否”知识点的学生显示“无需回顾”，不创建空的无目标试卷。

## 4. 周总结选题

每个“否”知识点请求两道题，候选必须：

- 主知识点相同；
- 当前固定三星；
- 未归档；
- 可机判；
- 来源已审核；
- 不属于该学生所选来源作业中的任何题目；
- 不与本次周总结已经选中的题目重复。

候选按 `original_qid → question_id` 稳定排序。选择审计使用：

```text
source_module = weekly_summary
reason_codes = weekly_summary、knowledge_status_no、fixed_difficulty_3
```

## 5. 库存不足

每名学生独立计算：

```text
requested_count = 否知识点数量 × 2
selected_count = 实际选中题数
shortfall = requested_count - selected_count
```

库存不足时不跨知识点、不跨难度、不重复来源题。系统在预检中显示缺口，但创建接口仍生成草稿。某学生存在“否”知识点但完全没有可用三星题时，也会生成 `item_count = 0` 的空草稿，用于保留缺口审计；发布接口继续拒绝空试卷。

## 6. “是 / 否 / 弱”状态

迁移 `0024` 新增 `student_knowledge_statuses`：

- 主键：`student_id + knowledge_point_id`；
- 状态：`yes | no | weak`；
- 保存触发状态的 Attempt ID 与修订号。

状态不是只增不减的缓存。手动提交、图片识别确认、教师改判和重新判分后都会从当前有效发布试卷重新回放：

- 历史回顾正确：`yes`；
- 历史回顾错误：`no`；
- 周总结同知识点任一题错误：`weak`；
- 周总结同知识点全部正确：`yes`。

学生画像接口与页面新增“回顾标签”列，显示“是 / 否 / 弱”。`scripts.rebuild_mastery --all` 同时重建掌握度和知识点状态，可用于迁移后的历史数据回填。

## 7. 前端与接口

作业列表 `/assignments` 的“创建作业”旁新增“创建周总结”，进入：

```text
/assignments/weekly-summary/new
```

页面包含：

- 周总结标题；
- 班级；
- 最近六次已批改作业多选；
- 班级学生数、需生成试卷人数、涉及知识点数、库存不足人数；
- 逐学生“否”知识点、计划题数、已选题数和短缺；
- 缺题仍生成草稿入口；
- 全班无人需要周总结时明确提示“未生成学生草稿”；只有部分学生需要时显示生成与跳过人数，空周总结详情页也会解释原因。

后端接口：

```text
POST /api/v1/assignments/weekly-summary/preview
POST /api/v1/assignments/weekly-summary
```

周总结 Assignment 使用 `assignment_type = weekly_summary`，在普通作业列表中用“周总结”标签区分。

## 8. 验证

自动化测试覆盖：

1. 历史回顾再次答错后知识点为 `no`；
2. 每个 `no` 知识点生成两道三星题；
3. 周总结与来源整卷去重；
4. 周总结草稿、发布、手动提交和教师改判完整链路；
5. 周总结任一题错误后知识点变为 `weak`；
6. 学生画像返回 `learning_status = weak`；
7. 完全无库存时仍生成带完整短缺信息的空草稿；
8. 前端生产构建通过。
