# 题库种子与阶段一旧演示兼容移除记录

> 日期：2026-10-29  
> 范围：题库初始化、阶段一旧演示数据兼容移除、默认开发库清理后的防回灌保护

## 1. 背景

阶段二调整了创建作业的筛选和组卷规则，阶段一固定生成的 Demo 班、S001～S005、历史作业、试卷和作答已经不适合作为当前学生画像与班级学情的数据来源。

数据库中的旧业务数据已经清理，保留：

- 21 个知识点；
- 180 道题目；
- 题目审核状态、结构化答案和题目资源；
- Alembic 迁移状态。

原 `seed_database` 会在导入题库时无条件重新创建 5 名学生，并在导入有理数题库时创建三次阶段一历史作答。若不修改脚本，重新导入题库会把已经清理的旧数据再次写回数据库。

## 2. 最终规则

默认种子导入只允许处理：

```text
knowledge_points
questions
```

默认导入不得创建或修改：

```text
school_classes
students
assignments
paper_instances
paper_instance_items
submissions
attempts
attempt_revisions
student_masteries
student_knowledge_statuses
recognition_runs
recognition_items
```

阶段一旧演示数据不再提供任何导入入口。题库种子服务只接受题库和知识点数据，当前演示数据统一由 `scripts.prepare_current_demo` 构造。

`import_seed_data` 已删除以下阶段一兼容内容：

- `DEMO_STUDENTS` 中的 S001～S005；

### 3.3 阶段一固定演示

阶段一固定 M5 场景服务、配置、构造命令、重置脚本和专用测试均已删除。依赖旧固定数据的 `verify_m1.py`、`verify_m2.py` 也已删除；正式业务能力继续由当前自动化测试和仍适用的只读一致性脚本覆盖。

### 3.4 运行说明

README 的首次运行和题库更新命令已经改为仅导入题库。空业务库不再执行 `rebuild_mastery --all`；只有存在学生和有效作答、并且确实需要重建画像时才单独执行。

## 6. 协作者数据库清理命令

数据库内容不会通过 Git 同步。其他协作者拉取代码后，先只读预览自己当前连接的数据库：

```powershell
docker compose exec backend python -m scripts.cleanup_business_data
```

确认输出中的数据库名、保留表和待清理数量后，显式执行：

```powershell
docker compose exec backend python -m scripts.cleanup_business_data --confirm --expected-database math_agent
```

安全约束：

- 不传 `--confirm` 时只读；
- `--confirm` 必须同时提供完全匹配的 `--expected-database`；
- 只清理由代码固定列出的业务表；
- 保留 `questions`、`knowledge_points`、`alembic_version`；
- 不使用 `CASCADE`；
- 发现未知公共表时拒绝执行，避免遗漏未来新增业务表；
- 清理与复核处于同一事务，失败自动回滚；
- 清理后所有业务表必须为 0，题库、知识点和迁移状态必须保持不变。
