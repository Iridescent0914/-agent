# 题库种子与旧演示数据解耦记录

> 日期：2026-10-29  
> 范围：题库初始化、阶段一旧演示数据兼容入口、默认开发库清理后的防回灌保护

## 1. 背景

阶段二调整了创建作业的筛选和组卷规则，阶段一固定生成的 Demo 班、S001～S005、历史作业、试卷和作答已经不适合作为当前学生画像与班级学情的数据来源。

数据库中的旧业务数据已经清理，保留：

- 21 个知识点；
- 180 道题目；
- 题目审核状态、结构化答案和题目资源；
- Alembic 迁移状态。

原 `seed_database` 会在导入题库时无条件重新创建 5 名学生，并在导入有理数题库时创建三次阶段一历史作答。若不修改脚本，重新导入题库会把已经清理的旧数据再次写回数据库。

## 2. 最终规则

默认种子导入只允许处理：

```text
knowledge_points
questions
```

默认导入不得创建或修改：

```text
school_classes
students
assignments
paper_instances
paper_instance_items
submissions
attempts
attempt_revisions
student_masteries
student_knowledge_statuses
recognition_runs
recognition_items
```

阶段一旧演示数据仅为兼容旧版 M1～M5 隔离演示环境保留，必须通过显式参数启用，不能用于默认开发库或正式环境。

## 3. 实现调整

### 3.1 导入服务

`import_seed_data` 新增两个默认关闭的参数：

```python
include_demo_students=False
include_demo_history=False
```

旧历史作答依赖旧学生；如果只启用 `include_demo_history` 而没有启用 `include_demo_students`，服务直接拒绝执行。

### 3.2 命令行入口

默认安全导入：

```powershell
docker compose exec backend python -m scripts.seed_database --chapter all
```

显式生成阶段一旧演示数据：

```powershell
docker compose exec backend python -m scripts.seed_database --chapter rational --include-legacy-demo
```

`--chapter expr --include-legacy-demo` 无效，因为旧演示历史只基于有理数题库；脚本会返回参数错误。

### 3.3 隔离 M5 环境

`scripts/reset_m5_demo.ps1` 已显式增加 `--include-legacy-demo`，并补齐画像重算所需的 `--all` 参数。因此只有原本就带数据库名、环境和确认开关保护的隔离 M5 重置流程会继续生成旧场景。

### 3.4 运行说明

README 的首次运行和题库更新命令已经改为仅导入题库。空业务库不再执行 `rebuild_mastery --all`；只有存在学生和有效作答、并且确实需要重建画像时才单独执行。

## 5. 后续演示数据原则

新的六年级 Demo 班和 5 名学生不复用阶段一固定历史。后续应单独实现符合当前阶段二筛选、必做题、历史回顾、周总结和阶段三画像规则的演示数据构造器，并明确记录每份作业的来源、生成配置和作答证据。

## 6. 协作者数据库清理命令

数据库内容不会通过 Git 同步。其他协作者拉取代码后，先只读预览自己当前连接的数据库：

```powershell
docker compose exec backend python -m scripts.cleanup_business_data
```

确认输出中的数据库名、保留表和待清理数量后，显式执行：

```powershell
docker compose exec backend python -m scripts.cleanup_business_data --confirm --expected-database math_agent
```

安全约束：

- 不传 `--confirm` 时只读；
- `--confirm` 必须同时提供完全匹配的 `--expected-database`；
- 只清理由代码固定列出的业务表；
- 保留 `questions`、`knowledge_points`、`alembic_version`；
- 不使用 `CASCADE`；
- 发现未知公共表时拒绝执行，避免遗漏未来新增业务表；
- 清理与复核处于同一事务，失败自动回滚；
- 清理后所有业务表必须为 0，题库、知识点和迁移状态必须保持不变。
