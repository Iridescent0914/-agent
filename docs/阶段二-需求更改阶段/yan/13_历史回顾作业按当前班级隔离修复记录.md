# 历史回顾作业按当前班级隔离修复记录

日期：2026-10-28

## 需求

组卷页“历史回顾”下拉列表只能展示当前所选班级最近 5 次已全部批改的可回顾作业，其他班级的作业不得出现。

## 问题原因

后端已有按 `class_id` 查询的能力，前端请求也会携带该参数，但仍存在两个隔离薄弱点：

1. `class_id` 在最近作业接口中是可选参数，调用方漏传时可能得到跨班级结果。
2. 教师切换班级后，前端会等新请求返回再替换列表。在这段时间内，旧班级的历史作业仍会短暂保留；如果新请求失败，旧列表还会继续存在。

## 修复内容

### 前端

- 所选班级发生变化时，立即清空历史作业列表和已经选择的历史作业，不再等待新请求返回。
- 请求仍显式携带当前 `class_id`。
- 对接口响应再次按照当前 `class_id` 过滤，防止异常响应中的其他班级作业进入下拉列表。

### 后端

- `/api/v1/assignments/recent-completed` 的 `class_id` 改为必传参数。
- `list_recent_completed_assignments` 服务也改为必须显式传入 `class_id`，避免后续代码误用无班级范围的查询。
- 原有预检和生成阶段的“历史作业必须属于当前班级”校验继续保留，形成列表、接口和组卷三层约束。

## 测试

- 后端目标测试通过：`1 passed`。
  - 验证接口结果全部属于请求班级。
  - 验证不传 `class_id` 时返回 `422`。
- 前端 Playwright 目标测试通过：`1 passed`。
  - 模拟接口同时返回当前班级和其他班级作业。
  - 验证“其他班级作业”不会出现在历史回顾下拉列表。
- `npm run typecheck`：通过。
