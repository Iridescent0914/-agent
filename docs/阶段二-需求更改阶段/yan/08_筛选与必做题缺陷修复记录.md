# 筛选与必做题缺陷修复记录

> 日期：2026-10-27  
> 实施人：yan  
> 范围：创建作业筛选页面、必做题请求合同、候选库存和诊断信息  
> 不包含：个性化后端组卷、连续错题标签和周总结

## 1. 修复背景

阶段二已经完成筛选界面和必做题基础链路，但代码复查和浏览器回归发现以下问题：

1. 必做题总数为 1 时，会被旧推荐参数的知识点占比校验拒绝；
2. 必做题知识点选择器显示的是全部可机判题数量，不是实际必做题库存；
3. 年级选项混入班级管理中的自由文本年级，可能与题库年级不一致；
4. 必做题未选择知识点时，后端会回退到旧推荐字段并被其静默限制；
5. 教师修改必做题数量后切换到个性化模块，必做题控件卸载，提交时数量恢复默认值；
6. 年级和章节重复时的后端中文错误信息乱码；
7. 必做题筛选诊断把“超过教师题量而未选中的正常题”错误计入可机判过滤阶段。

本次按上述顺序修复，并增加后端单元、数据库集成和桌面/移动端浏览器回归。

## 2. 单道必做题不再被旧占比校验阻塞

### 2.1 原因

新必做题按教师设置的各难度数量确定性取题，不使用旧推荐算法的单知识点占比限制。但创建页面仍会提交旧版 `RecommendationRequest`，默认：

```text
max_knowledge_point_ratio = 0.5
```

旧校验要求：

```text
floor(总题数 × max_knowledge_point_ratio) >= 1
```

总题数为 1 时结果为 0，因此请求在进入必做题逻辑前被拒绝。

### 2.2 修复

- 删除请求模型中“向下取整后必须至少为 1”的前置拒绝；
- 旧推荐算法真正计算知识点上限时使用：

```text
max(1, floor(总题数 × max_knowledge_point_ratio))
```

这样既保留原有占比语义，也允许合法的单题请求。新必做题算法仍按教师设置的难度数量执行，不应用旧知识点占比。

## 3. 必做题选择器改用真实必做库存

### 3.1 原因

原 `available_question_count` 统计条件为：

```text
未归档 ∩ 可机判 ∩ 来源已审核
```

但必做题候选还要求：

```text
Question.is_required = true
```

因此页面显示的“某知识点 N 题”可能大于实际必做题库存，甚至显示 1 题但必做库存为 0。

### 3.2 修复

知识点目录接口新增：

```text
required_available_question_count
```

统计条件与必做题候选池一致：

```text
is_required = true
∩ 未归档
∩ 可机判
∩ 来源已审核
```

前端现在维护两套知识点选项：

- 必做题使用 `required_available_question_count`，并隐藏必做库存为 0 的知识点；
- 个性化配置继续使用全部 `available_question_count`，不受必做标记限制。

“全部知识点”和“本章全部知识点”也分别按各模块自己的候选知识点展开，避免必做题重新混入零库存知识点。

该调整只增加响应字段，不需要数据库迁移。

## 4. 年级选项只来自题库目录

### 4.1 原因

原页面把班级的 `grade` 和题库章节的 `grades` 合并为组卷年级选项。班级年级是自由文本，默认示例为“六年级”，而当前题库使用“六年级上册”。后端按字符串精确匹配，教师显式选择“六年级”时会得到空候选池。

### 4.2 修复

组卷年级选项现在只来自题库章节目录中的真实题目年级。

班级年级继续用于班级管理和展示，但不再直接成为题库过滤值。这样页面能够提交的年级一定来自实际题库。

## 5. 空知识点范围不再回退旧字段

### 5.1 正式语义

新筛选合同规定：

```text
filter_config.required.knowledge_point_codes = []
```

表示在教师所选年级和章节内不限制知识点。

### 5.2 原问题

后端曾使用：

```text
新必做题知识点范围 or 旧 recommendation_parameters.new_knowledge_point_codes
```

因此新字段为空时，旧字段仍可能静默缩小必做题范围。

### 5.3 修复

- 候选池过滤只读取 `filter_config.required.knowledge_point_codes`；
- 空列表直接表示不限知识点；
- 不再使用旧推荐字段参与必做题候选过滤；
- 选出候选池后，将实际覆盖的知识点写入有效推荐参数和审计；
- 原始空列表仍保存在 `filter_config`，可以还原教师当时的“不限知识点”选择。

## 6. 切换模块后保留教师设置的题量

### 6.1 原因

创建页面原先使用条件渲染，只挂载当前展开模块的表单控件。教师修改必做题数量后，必须打开个性化模块完成必填配置；此时必做题控件被卸载。

虽然代码为未挂载字段提供了默认值，但只能恢复默认“二星 6 道”，不能保留教师实际输入。例如教师设置二星 1 道，切换模块后提交仍会变回 6 道。

### 6.2 修复

三个模块的表单控件现在始终保持挂载，仅使用 `hidden` 控制显示状态。由此保证：

- 切换模块不会删除表单字段；
- 教师修改的各难度数量持续保存在表单中；
- 预检和正式生成读取同一组最新值；
- 个性化必填校验仍然有效。

浏览器回归覆盖了“二星从 6 改为 1，再切换到个性化并提交”的完整过程。

## 7. 错误文案和诊断阶段修复

### 7.1 中文文案

修复两条乱码提示：

```text
章节不能重复
年级不能重复
```

### 7.2 必做题诊断

必做题诊断现在分别记录：

```text
teacher_scope
→ grading_readiness
→ difficulty_filter
→ selection_limit
```

各阶段含义为：

- `teacher_scope`：教师年级、章节、知识点、核心素养和必做标记范围；
- `grading_readiness`：移除不可机判或未审核题；
- `difficulty_filter`：只保留当前处理难度；
- `selection_limit`：候选充足时按教师题量截取。

超过教师设置数量而未被选中的正常题现在计入 `selection_limit`，不再错误显示为判分准备度问题。

## 9. 新增回归覆盖

本次新增或加强以下场景：

1. 总题数为 1、占比为 0.5 时仍可选出 1 道题；
2. 必做题诊断分别统计范围、可机判、难度和题量截取；
3. 必做题知识点为空时不受旧知识点范围影响；
4. 知识点目录同时返回全部可机判库存和必做题库存；
5. 创建页面只显示题库真实年级，不显示班级自由文本年级；
6. 必做题知识点显示必做库存而非全部库存；
7. 修改必做题数量后切换模块，提交值保持不变；
8. 桌面端和 390px 移动端执行相同筛选回归。

## 11. 当前结论

修复后，必做题筛选满足以下口径：

```text
年级和章节来自真实题库
∩ is_required = true
∩ 可选知识点
∩ 可选核心素养
∩ 未归档
∩ 可机判
∩ 来源已审核
```

教师可以合法设置 1～30 道必做题；页面显示真实必做库存；不选知识点时覆盖所选年级和章节；切换三个筛选模块不会丢失教师输入；预检、正式生成和审计继续使用同一确定性规则。
