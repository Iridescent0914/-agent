# 历史回顾缺陷修复记录

> 日期：2026-10-27  
> 负责人：yan  
> 范围：基础历史回顾的来源作业校验、草稿换题与选择审计  
> 不包含：连续错两次标签、周总结、个性化后端组卷

## 1. 修复背景

基础历史回顾已经能够完成以下正常流程：

1. 教师从当前班级已批改作业中选择一份来源作业；
2. 系统逐学生读取来源作业中一至三星的必做错题；
3. 每道错题选择一道同知识点、同难度的替换题；
4. 没有符合条件错题的学生不生成历史题；
5. 库存不足时返回 `insufficient_history_inventory`。

本轮审查发现，正常组卷路径虽然可用，但在教师换题和来源作业接口约束方面仍有缺陷。

## 2. 必做题换题后仍可被历史回顾识别

### 2.1 原问题

教师在草稿中替换必做题时，换题逻辑会用普通推荐结果重建 `selection_audit`。普通推荐结果的默认模块是：

```text
source_module = legacy_recommendation
```

原题的 `source_module = required` 和 `required_question` 原因码因此丢失。该试卷发布并批改后，即使学生答错，历史回顾也会把这道题当成非必做题并跳过。

### 2.2 修复

换题时保留原题所属模块：

```text
required -> required
history -> history
personalized -> personalized
legacy_recommendation -> legacy_recommendation
```

对于必做题，换题后同时确保原因码仍包含：

```text
required_question
teacher_replacement
```

必做题的替换候选也增加 `Question.is_required = true` 限制，防止教师把必做题槽位替换成普通题。

## 3. 历史回顾题支持严格换题

### 3.1 原问题

阶段二组卷会把旧版 `review_knowledge_point_codes` 清空，而通用换题接口过去使用该字段查找历史题候选。因此历史回顾题通常得到空候选列表，与“生成后可继续编辑的草稿”不一致。

另外，如果只简单放开候选，还可能选回原错题，或选择不同难度的题目，破坏历史回顾规则。

### 3.2 修复后的候选规则

历史回顾题换题现在直接以当前历史题及其证据为准。候选必须：

- 不受本次作业所选年级和章节限制；
- 与当前历史题知识点相同；
- 与当前历史题难度相同；
- 题目处于未归档、已审核、可机器判分状态；
- 不是当前试卷中已经存在的题目；
- 不是历史证据 Attempt 所对应的原错题。

历史题换题不再错误套用旧回顾知识点列表、知识点占比上限或旧近期作答过滤。

### 3.3 保留历史证据

历史题替换后继续保留：

- `source_module = history`；
- 来源错题 Attempt ID；
- Attempt 修订号；
- `history_review`、`source_required_wrong`、`same_knowledge_point`、`same_difficulty` 等原因码；
- 原历史回顾原因说明。

并增加 `teacher_replacement` 原因码，明确记录教师执行过换题。

因此换题不会破坏历史题到来源错题的可追溯关系。

## 4. 后端强制限制最近五次来源作业

### 4.1 原问题

前端下拉框只展示最近五次已批改作业，但预检和创建接口过去只校验：

- 作业存在；
- 作业属于当前班级；
- 作业已经全部批改完成。

手工构造请求或长时间未刷新的页面仍可提交更早的作业 ID，后端没有执行与前端一致的“最近五次”约束。

### 4.2 修复

新增统一的可回顾来源解析逻辑。来源作业必须同时满足：

1. 类型为普通练习作业；
2. 属于当前班级；
3. 所有当前有效试卷均已完成最终批改；
4. 当前有效试卷中至少存在一项可识别的必做题审计；
5. 按作业创建时间排序后位于最近五次之内。

最近作业下拉接口和历史回顾预检/创建接口使用同一套来源资格语义。

缺少 `required` 或 `required_question` 审计的旧版作业不会再占用下拉框的五个名额，因为系统无法可靠判断其中哪些题属于必做题。

若请求提交不在最近五次之内的作业，返回：

```text
历史回顾作业不在当前班级最近五次可回顾作业中
```

## 5. 同时修正的换题边界

- 多章节作业换题使用完整的 `chapter_codes`，不再只检查第一个章节；
- 配置了年级时，替换题必须属于所选年级；
- 知识点占比计数只统计与目标题相同的推荐桶，历史题不会错误占用必做题换题额度；
- 换题审计的 `replaces` 中补充原题的 `source_module`。

## 6. 主要修改文件

### 后端服务

- `backend/app/services/recommendations.py`
  - 增加可审计必做题检查；
  - 增加最近五次可回顾来源解析；
  - 历史错题读取时执行服务端最近五次校验。

- `backend/app/services/paper_workflow.py`
  - 最近已完成作业列表复用统一资格语义；
  - 历史题换题采用同知识点、同难度规则；
  - 从历史证据排除原错题；
  - 换题后保留模块标记、原因码和历史证据；
  - 必做题替换候选限制为必做题。

### 回归测试

- `backend/tests/test_m3_workflow.py`
  - 验证历史题存在可用替换候选；
  - 验证候选与原题同知识点、同难度；
  - 验证候选不包含原错题；
  - 验证历史题换题后证据和模块标记不丢失；
  - 验证必做题换题后仍保持必做属性；
  - 验证第六份及更早作业被后端拒绝；
  - 验证无必做审计的旧作业不会进入最近五次来源。

## 8. 当前结论

本轮修复后，基础历史回顾满足以下闭环：

- 来源只能由教师从当前班级最近五次有效已批改作业中选择；
- 只读取一至三星的最终必做错题；
- 一道来源错题对应一道同知识点、同难度且非原错题的题目；
- 历史题可以在不破坏规则和证据链的前提下继续换题；
- 必做题经教师换题后仍能在下一次历史回顾中被正确识别；
- 旧版无必做审计作业不会作为伪可用来源展示。

连续错两次标签、周五周总结和知识点“弱”标记仍按阶段二范围暂不实现。
