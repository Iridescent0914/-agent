# 必做题候选池过滤修复记录

> 日期：2026-10-27  
> 范围：创建作业时的必做题候选池

## 1. 需求口径

“必做题”不仅表示同一次作业中全班学生使用同一套题，还必须使用题库自身的“是否为必做题”标记。

必做题候选池现统一要求：

```text
所选年级
∩ 所选章节
∩ 题库 is_required = true
∩ 可选知识点范围
∩ 可选核心素养范围
∩ 未归档
∩ 可机判
∩ 来源已审核
```

知识点和核心素养仍是两个相互独立的可选条件；两者都选择时取交集，两者都不选择时覆盖所选年级和章节中的全部必做题。

## 2. 修复内容

`backend/app/services/recommendations.py` 的 `required_question_candidates` 查询新增：

```python
Question.is_required.is_(True)
```

因此，题目即使满足年级、章节、知识点、核心素养、审核状态和可机判条件，只要题库字段 `is_required` 为 `false`，就不会进入必做题预检或正式生成结果。

历史回顾的既有语义不变：系统仍从教师选定的已完成作业中读取当时以 `source_module = required` 发布的必做题，并根据学生最终错题结果选择同知识点、同难度的替换题。

## 3. 回归测试

`backend/tests/test_m3_workflow.py` 新增回归用例：

1. 选取一条已审核且可机判的必做题；
2. 在测试事务中把它的 `is_required` 改为 `false`；
3. 重新加载相同年级和章节的必做题候选池；
4. 确认该题不再出现在候选结果中。

测试事务结束后回滚，不修改正式题库数据。

## 4. 不在本次范围内

- 个性化固定 3 道题的后端组卷算法；
- 连续错两次后的“是/否”知识点状态；
- 周五周总结及周总结错误后的“弱”标签；
- 历史回顾规则的其他调整。
