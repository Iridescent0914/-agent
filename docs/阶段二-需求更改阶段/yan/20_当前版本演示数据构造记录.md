# 当前版本演示数据构造记录

> 日期：2026-10-29  
> 范围：阶段二筛选、必做题、历史回顾、周总结和知识点状态的可同步演示场景

## 1. 目标

数据库 volume 不通过 Git 同步。项目通过版本化场景配置和幂等构造器，使每名协作者都能在自己的数据库生成一致的当前版本演示数据，同时不再依赖阶段一旧 S001～S005 固定历史。

## 2. 文件

- `data/seed/current_demo_scenario.json`：班级、学生和场景合同；
- `backend/app/services/current_demo.py`：演示数据构造服务；
- `backend/scripts/prepare_current_demo.py`：命令行入口；
- `backend/tests/test_current_demo.py`：完整性与幂等性测试。

## 3. 场景内容

演示班级：

```text
名称：六年级 Demo 班
年级：六年级
学年：2026-2027
教师：演示教师
学生：DEMO-S001 ～ DEMO-S005，共 5 人
```

演示链路：

```text
2 份已全部批改的全班统一必做题作业
→ 选定最近来源作业
→ 当前筛选合同生成 1 道全班必做题和逐学生历史回顾题
→ 历史回顾答对标“是”，再次答错标“否”
→ 以历史回顾作业创建独立周总结
→ 周总结答错标“弱”，答对回到“是”
```

最终保留可展示的差异：

- `DEMO-S001`：至少一个“弱”；
- `DEMO-S002`：保留周总结草稿，至少一个“否”；
- `DEMO-S004`、`DEMO-S005`：至少一个“是”；
- `DEMO-S003`：所选来源作业没有错题，因此没有历史回顾题。

周总结当前仍按固定 3 星规则生成。题库库存不足时保留短缺并生成可用草稿；发布部分短缺试卷时由演示构造器显式记录确认原因。

## 4. 数据真实性边界

- 必做题、历史题和周总结题均来自当前题库；
- 历史回顾通过当前 `create_assignment` 组卷服务生成；
- 周总结通过当前 `create_weekly_summary` 服务生成；
- 试卷通过当前发布服务冻结快照；
- 作答通过手动提交、确定性判分和教师复核服务进入 Attempt；
- 画像和“是 / 否 / 弱”由当前作答证据回放，不直接写最终分数或标签；
- 个性化后端尚未实现，因此场景只保存个性化筛选配置，不伪造个性化题。

## 5. 使用方法

全新或已清理的数据库：

```powershell
docker compose exec backend python -m alembic upgrade head
docker compose exec backend python -m scripts.seed_database --chapter all
docker compose exec backend python -m scripts.prepare_current_demo
```

需要删除现有业务数据后重建：

```powershell
docker compose exec backend python -m scripts.cleanup_business_data
docker compose exec backend python -m scripts.cleanup_business_data --confirm --expected-database math_agent
docker compose exec backend python -m scripts.seed_database --chapter all
docker compose exec backend python -m scripts.prepare_current_demo
```

`seed_database` 已不再提供阶段一旧演示兼容参数，不能重新导入 S001～S005 或旧固定历史。

## 6. 幂等与冲突处理

- 班级、学生、作业和提交均使用稳定名称、编号、种子键或幂等键；
- 重复运行不重复创建数据；
- 同名班级的年级、学年或教师不一致时拒绝覆盖；
- 演示学生编号已被其他班级或真实学生占用时拒绝覆盖；
- 整个命令由调用方在单一数据库事务中提交，失败时回滚。
