# 组卷模块切换表单状态修复记录

> 日期：2026-10-28  
> 负责人：yan  
> 范围：创建作业页“个性化 → 历史回顾”模块切换与请求组装  
> 不包含：个性化后端出题算法、历史回顾选题规则调整

## 1. 现象

教师先在个性化模块选择知识点和主要能力，再切换到历史回顾模块选择来源作业。点击预检时页面提示：

```text
操作失败
请选择个性化模块的知识点
```

这说明教师已经完成的个性化配置没有进入预检请求。

## 2. 根因

### 2.1 运行中的 Vite 缓存仍返回旧版页面

源码已经将必做题、个性化、历史回顾三个面板改为常驻挂载，但运行约 26 小时的 Docker 前端容器仍在返回旧的转换结果：

```text
activeModule === "personalized" && <Card ...>
activeModule === "history" && <Card ...>
```

旧实现切换模块时会卸载前一个模块的 `Form.Item`，导致个性化知识点和主要能力从本次提交值中消失。

重启前端容器后，Vite 实际返回内容恢复为：

```text
<div hidden={activeModule !== "personalized"}>...</div>
<div hidden={activeModule !== "history"}>...</div>
```

三个模块现在都保持挂载。

### 2.2 模块按钮存在悬停与点击竞争

模块按钮过去同时执行：

```text
鼠标悬停：激活模块
鼠标点击：若已激活则收起，否则激活
```

用户把鼠标移到历史回顾按钮时，悬停已经激活历史模块；紧接着点击又可能把它收起，交互状态不稳定。

### 2.3 预检只依赖提交回调中的可见值集合

预检过去直接使用 `onFinish(values)` 提供的值。为了防止隐藏或曾经卸载的字段被遗漏，预检和正式生成都应从 Ant Design Form 的完整 Store 读取配置。

## 3. 修复

### 3.1 三个模块常驻

必做题、个性化和历史回顾继续使用常驻面板，仅通过 `hidden` 控制显示。表单显式设置：

```text
preserve = true
```

切换模块不会卸载字段。

### 3.2 模块只通过点击激活

移除 `onMouseEnter` 自动切换。模块按钮点击后只负责激活对应模块：

```text
onClick={() => setActiveModule(module)}
```

需要收起时使用面板右上角的“收起”按钮，避免悬停与点击互相抵消。

### 3.3 预检和生成读取完整 Form Store

预检与正式生成统一使用：

```text
form.getFieldsValue(true)
```

`true` 表示读取完整表单 Store，而不仅是当前可见或当前参与提交的字段。

因此请求会同时包含：

```json
{
  "personalized": {
    "knowledge_point_codes": ["..."],
    "primary_competency": "...",
    "question_count": 3
  },
  "history": {
    "assignment_id": "..."
  }
}
```

## 4. 运行环境处理

已重启 Docker 前端容器，使 Vite 清除旧转换缓存并重新加载当前源码：

```text
docker compose restart frontend
```

重启后检查 Vite 实际返回的模块，确认已经包含三个 `hidden` 常驻面板，不再返回旧条件渲染代码。

## 5. 回归测试

扩展 `frontend/tests/m3.spec.ts`，覆盖完整操作链：

1. 配置必做题数量；
2. 进入个性化模块选择知识点；
3. 选择对应主要能力；
4. 切换到历史回顾模块；
5. 选择最近已批改来源作业；
6. 点击预检；
7. 断言请求同时保留个性化配置与历史来源 ID。

定向 Playwright 结果：

```text
1 passed
```

前端类型检查：

```text
npm run typecheck 通过
npm run build 通过
```

## 6. 旧作业说明

此前已经生成的“数学作业”在数据库中保存的是：

```json
{"history": {"assignment_id": null}}
```

该旧作业不会因为前端或算法修复而自动重算。教师需要重新创建作业、选择历史来源、重新预检并生成草稿。

## 7. 当前结论

教师现在可以按“个性化配置 → 历史来源选择 → 预检/生成”的顺序操作。模块切换不会再丢失个性化知识点或主要能力，最终请求会同时携带个性化筛选配置和历史来源作业 ID。
