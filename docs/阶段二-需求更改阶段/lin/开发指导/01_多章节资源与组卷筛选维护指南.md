# 多章节资源与组卷筛选维护指南

> 适用范围：题库资源接入、创建作业筛选页、必做题组卷链路
> 当前基线：2026-10-24（提交 `c722e57`）
> 维护人：lin

## 1. 文档目的

本指南用于约束后续章节接入和组卷筛选功能的开发方式，重点保证：

1. 不同章节的原始资源、Web 资源和资源清单彼此隔离；
2. 前端“全部”选项只作为界面选择标记，提交 API 前必须展开为真实代码；
3. 必做题筛选条件在前后端使用同一份合同；
4. 预检与正式生成使用相同参数，保证预检结果可复现；
5. 已实现能力与预留模块边界清晰，避免把尚未接入的筛选项误认为已经参与出题。

## 2. 多章节资源约定

### 2.1 目录与 URL

每个正式章节独占一组资源目录和资源清单：

```text
data/
├── assets/
│   ├── rational/              第一章原始图片、公式资源
│   └── expr/                  第二章原始图片、公式资源
└── web/
    ├── rational/
    │   └── asset_manifest.json
    ├── expr/
    │   └── asset_manifest.json
    └── teacher/               教师上传资源
```

对应的公开路由为：

```text
/assets/rational/<filename>
/assets/expr/<filename>
/assets/teacher/<filename>
```

环境变量必须指向资源根目录，而不是某个具体章节：

```dotenv
PUBLIC_ASSET_BASE_URL=http://localhost:8000/assets
WEB_ASSET_DIR=/app/data/web
```

### 2.2 题目资源路径

导入题目的资源路径使用 POSIX 风格相对路径：

```text
assets/rational/<filename>
assets/expr/<filename>
assets/teacher/<32位十六进制UUID>.png
```

新增章节时，不应继续把资源放入 `rational`；需要为该章节设置稳定的目录短名，并同步扩展：

- 构建脚本的 `ASSET_DIR_NAME`；
- `scripts/convert_seed_assets.py` 的章节配置；
- FastAPI 静态目录挂载；
- `QuestionAssetInput` 的路径白名单；
- `backend/app/services/assets.py` 的章节白名单与 manifest 路由；
- 对应章节验收脚本的 manifest 路径。

### 2.3 转换与解析原则

执行：

```powershell
python scripts/convert_seed_assets.py
```

转换脚本按章节读取完整题库中间库，并分别生成 Web 文件与 `asset_manifest.json`。manifest 中的 `web_path` 必须保留章节前缀，例如：

```text
expr/q.math.g6.expr.school.001_rId11.png
```

后端解析流程为：

```text
题目 source_path
→ 从 assets/<chapter>/... 识别章节
→ 读取 data/web/<chapter>/asset_manifest.json
→ 检查 converted 状态与实际文件
→ 拼接 PUBLIC_ASSET_BASE_URL + web_path
```

为兼容资源拆分前已经入库的数据，后端可读取形如 `assets/rational/q.math.g6.expr.*` 的旧路径，并转查第二章 manifest。该逻辑只是读取兼容层；重新构建和重新入库时仍应写入正式的 `assets/expr/...` 路径。

## 3. 创建作业筛选合同

创建作业请求同时保留旧版 `recommendation_parameters` 和新版 `filter_config`。新版界面应提交：

```json
{
  "class_id": "...",
  "student_scope": "all_class",
  "student_ids": [],
  "filter_config": {
    "grade_codes": ["六年级上册"],
    "chapter_codes": ["math.g6.rational", "math.g6.expr"],
    "required": {
      "knowledge_point_codes": ["..."],
      "core_literacies": ["运算能力"],
      "difficulty_counts": {"1": 0, "2": 6, "3": 0, "4": 0, "5": 0}
    },
    "personalized": {
      "knowledge_point_codes": [],
      "primary_competency": null,
      "question_count": 3
    },
    "history": {
      "assignment_id": null
    }
  },
  "recommendation_parameters": {
    "chapter_code": "math.g6.rational",
    "chapter_codes": ["math.g6.rational", "math.g6.expr"],
    "grade_codes": ["六年级上册"],
    "new_knowledge_point_codes": ["..."],
    "review_knowledge_point_codes": [],
    "new_count": 6,
    "review_count": 0
  }
}
```

关键校验规则：

- 年级和章节至少各选一项，且不能重复；
- 必做题各难度键只能为 `1`～`5`；
- 每个难度数量必须是非负整数；
- 必做题总量为 1～30；
- 个性化模块当前固定预留 3 道；
- 全班范围使用 `student_scope = all_class`，并提交 `class_id`，不再提交指定学生列表。

## 4. “全部”选项的交互规则

“全部年级”“全部章节”“本年级全部章节”“全部知识点”和“本章全部知识点”都是前端哨兵值，只用于保持选择框简洁，不能直接发送到后端。

当前哨兵值包括：

```text
__all_grades__
__all_chapters__
__all_grade_chapters__:<grade>
__all_knowledge_points__
__all_chapter_knowledge_points__:<chapter_code>
```

实现时遵守以下顺序：

1. 表单中保留紧凑选择，例如只显示一个“全部章节”标签；
2. 章节改变后，清除已经不属于当前章节范围的知识点选择；
3. 页面摘要使用展开后的真实知识点数量；
4. 预检或生成前，把所有哨兵值展开为真实年级、章节和知识点代码；
5. 分组全选与单项重复时进行去重，避免后端唯一性校验失败。

不要把所有真实项直接回填到选择框，否则会重新出现大量标签、选项难以撤销以及“全选后再取消单项”状态不一致的问题。

## 5. 必做题筛选与生成语义

### 5.1 候选池过滤

必做题候选池依次受以下条件约束：

```text
年级范围
∩ 章节范围
∩ 知识点范围（为空则不限）
∩ 核心素养范围（为空则不限）
∩ 未归档题目
∩ 可机判且来源已审核
```

知识点来自题目的主知识点关联；核心素养来自 `Question.core_literacy`。核心素养字段支持使用 `、`、中英文逗号、中英文分号、`/` 或 `|` 分隔。知识点和核心素养可以分别选择；两者同时存在时按交集筛选。

### 5.2 确定性选题

必做题按难度从低到高处理，每个难度池按以下顺序稳定排序：

```text
original_qid
→ question_id
```

再按教师设置的星级题量截取。这样同一筛选条件与题库状态下，预检和正式生成得到相同的必做题集合。

当前必做题是班级统一题：系统先生成一次模板，再复制给班级中的每名学生。库存不足时不跨难度补题，而是返回 `insufficient_difficulty_inventory` 和对应缺口，交由教师放宽范围或减少题量。

### 5.3 配置留痕

正式生成时，展开后的推荐参数和完整 `filter_config` 同时保存到：

- `Assignment.teaching_scope`；
- `Assignment.generation_config`；
- 各试卷的推荐审计快照。

请求指纹包含筛选配置。同一个幂等键如果搭配不同筛选条件，会按冲突处理，不能静默复用旧作业。

## 6. 当前功能边界

| 模块 | 当前状态 | 说明 |
|---|---|---|
| 必做题 | 已接入预检与生成 | 全班同题，支持年级、章节、知识点、核心素养和星级题量 |
| 个性化 | 仅保存配置 | 固定预留 3 道，尚未合并进本轮题目集合 |
| 历史回顾 | 仅保存来源作业 | 可选择最近 5 次已完成作业，尚未抽取回顾题 |

“最近已完成作业”要求作业存在学生试卷、没有草稿试卷，且至少有一份有效已发布试卷。必须由教师明确选择，不根据“昨天”等相对时间自动猜测。

## 7. 后续扩展步骤

### 7.1 接入新章节

1. 生成章节完整题库、种子题库和知识树；
2. 将原始资源输出到 `data/assets/<chapter>/`；
3. 在资源转换脚本和后端白名单中登记章节短名；
4. 转换资源并检查章节独立 manifest；
5. 导入数据库，确认题库目录接口返回年级、节、知识点和核心素养；
6. 在创建作业页使用“本章全部知识点”和单项组合进行预检；
7. 回归已有章节，确认 URL 和旧路径兼容行为不受影响。

### 7.2 接入个性化与历史题

后续实现时，应在必做题模板之外分别生成个性化题和历史题，并明确：

- 三类题目的去重顺序；
- 每类题量及总题量上限；
- 个性化是否按学生分别生成；
- 历史题按作业快照还是当前题库版本读取；
- 短缺诊断如何区分必做题、个性化题和历史题；
- 审计快照中如何记录每道题的来源模块。

在这些规则确定前，不应仅凭已保存的筛选配置宣称两个模块已经完成出题。

## 8. 建议验收清单

### 8.1 资源

- 第一章和第二章 manifest 均可独立读取；
- manifest 的 `source_path` 与章节目录一致；
- `web_path` 带章节前缀；
- `/assets/rational/...` 与 `/assets/expr/...` 均能访问；
- 旧第二章 `assets/rational/q.math.g6.expr.*` 数据仍能解析；
- 缺失文件不会被标为 `converted`。

### 8.2 筛选交互

- 默认只显示“全部年级”和“全部章节”紧凑标签；
- 全选、分组全选、单项选择组合不会产生重复代码；
- 切换章节会剔除越界知识点；
- 知识点和核心素养可独立选择，并在同时选择时取交集；
- 表单摘要显示展开后的真实知识点数量；
- 发送给 API 的载荷不包含任何 `__all_*` 哨兵值。

### 8.3 组卷

- 预检不写数据库；
- 同一条件重复预检得到相同必做题；
- 全班学生的必做题 ID 与顺序一致；
- 不可机判或未审核题不进入必做题池；
- 某星级库存不足时返回明确缺口，不跨星级静默补题；
- 预检后正式生成的题目与预检一致；
- 作业配置和推荐审计中可追溯原始筛选条件。
