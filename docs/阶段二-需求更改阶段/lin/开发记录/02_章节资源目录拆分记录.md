# 章节资源目录拆分记录

> 日期：2026-10-21
> 对应提交：`6eba60e`（分离 asset 与 web 章节图片公式存储）
> 操作人：lin

## 1. 修改背景

第二章“简单的代数式”最初复用了第一章的 `assets/rational` 和 `data/web/rational` 目录，两个章节的原始资源、转换产物和 manifest 混在一起。继续沿用该结构会带来以下问题：

- 资源目录名称与实际章节不一致；
- 单个 manifest 同时承担多个章节的索引，后续扩章困难；
- URL 无法直接反映资源归属；
- 第二章验收脚本只能依赖第一章目录；
- 重建某个章节时容易影响其他章节的清单和产物。

本次将第一章和第二章资源改为按章节独立存储和发布。

## 2. 目录调整

调整后的正式结构：

```text
data/assets/rational/        第一章原始资源
data/assets/expr/            第二章原始资源
data/web/rational/           第一章 Web 资源和 manifest
data/web/expr/               第二章 Web 资源和 manifest
data/web/teacher/            教师上传资源
```

第二章构建脚本的资源目录从 `rational` 改为 `expr`，已有第二章 WMF、PNG 原始资源和转换产物迁入对应章节目录；第二章完整题库、种子题库和审计表中的资源引用同步更新。

## 3. 转换脚本调整

`scripts/convert_seed_assets.py` 从“读取两个章节、生成一个共享 manifest”改为按章节循环转换：

```text
rational_all.json → data/web/rational/asset_manifest.json
expr_all.json     → data/web/expr/asset_manifest.json
```

每个章节独立维护：

- 题目数量；
- 资源引用数量；
- 唯一资源数量；
- 转换成功、失败和未解析数量；
- 源文件哈希；
- 带章节前缀的 `web_path`。

## 4. 后端资源服务调整

### 4.1 配置与静态路由

资源配置由具体章节目录上移到 Web 根目录：

```text
PUBLIC_ASSET_BASE_URL: /assets/rational → /assets
WEB_ASSET_DIR: data/web/rational → data/web
```

FastAPI 启动时分别创建并挂载：

```text
/assets/rational → data/web/rational
/assets/expr     → data/web/expr
```

教师资源仍使用独立的 `/assets/teacher` 路由。

### 4.2 manifest 解析

`backend/app/services/assets.py` 改为：

1. 从 `assets/<chapter>/...` 提取章节；
2. 按章节缓存对应 manifest；
3. 使用 manifest 中保留章节前缀的 `web_path` 生成 URL；
4. 检查实际文件时从 `WEB_ASSET_DIR` 根目录解析完整相对路径。

随后在组卷筛选改动中补充了旧数据兼容：数据库中如果仍保存 `assets/rational/q.math.g6.expr.*`，解析器会转查 `assets/expr/...` 对应项，避免必须先清库才能显示第二章资源。

### 4.3 输入校验与题干资源保留

题目资源路径白名单增加 `assets/expr/...`；题干清洗逻辑也允许保留第一章和第二章的导入资源标记，防止编辑题目时误删第二章图片引用。

## 5. 配套修改

- `scripts/build_expr_m0.py`：第二章资源目录改为 `expr`；
- `backend/scripts/verify_expr.py`：检查第二章独立 manifest；
- `.env.example`、`docker-compose.yml`：环境变量改为资源根目录；
- `README.md`：更新目录说明、后端启动变量和转换说明；
- 第二章题库产物：统一写入 `assets/expr/...` 路径。

## 7. 后续注意事项

1. 新章节必须建立独立资源目录和 manifest，不得继续复用 `rational` 或 `expr`。
2. `PUBLIC_ASSET_BASE_URL` 保持为 `/assets` 根地址，章节名由 manifest 的 `web_path` 提供。
3. 旧第二章路径兼容层只用于平滑读取；新数据必须写入 `assets/expr/...`。
4. 更新题库资源后重新运行转换脚本，并同时检查转换状态和实际文件是否存在。
5. 扩展章节白名单时，应同步修改构建、转换、后端解析、输入校验、静态挂载与验收脚本，避免只改其中一处。
