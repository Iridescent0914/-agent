# 组卷筛选与必做题逻辑改进总结

## 1. 本次目标

将原有“单章节、指定学生、新知识/回顾题量”的创建作业表单，调整为面向教师的分模块筛选流程：

```text
确定班级、年级和章节
→ 配置必做题、个性化、历史回顾模块
→ 预检全班学生
→ 查看统一必做题草稿与库存缺口
→ 确认生成作业草稿
```

本轮重点完成必做题全链路；个性化和历史回顾先完成界面、请求合同与配置留痕，为后续算法接入预留稳定结构。

## 2. 前端筛选界面改造

### 2.1 作业范围

创建页改为选择：

- 一个班级，学生范围固定为当前全班；
- 一个或多个年级；
- 一个或多个章节。

页面从题库目录接口读取章节对应的年级、节、知识点与核心素养元数据。章节变化时重新加载知识点，并清理已经越界的选择。

### 2.2 三个筛选模块

筛选区改为三个可展开卡片：

| 模块 | 本轮配置项 | 当前是否参与出题 |
|---|---|---|
| 必做题 | 知识点、核心素养、1～5 星题量 | 是 |
| 个性化 | 知识点、主要能力、固定 3 道 | 否，仅保存配置 |
| 历史回顾 | 最近 5 次已完成作业 | 否，仅保存来源 |

页面摘要实时展示必做题总数、展开后的知识点数量及其他模块配置状态。预检结果除逐学生题量外，还展示全班共用的必做题草稿；没有可用题时给出放宽筛选条件的提示。

### 2.3 “全部”选择交互

后续两次调整完善了批量选择：

- 年级增加“全部年级”；
- 章节增加“全部章节”和“本年级全部章节”；
- 必做题与个性化知识点均支持“全部知识点”和“本章全部知识点”；
- 默认值使用紧凑的“全部”标记，不在选择框中堆叠所有真实项；
- 同一分组全选后，移除组内重复的单项代码；
- 只有提交预检或生成请求时，才把标记展开为真实代码；
- 模块摘要按展开后的数量计算，不把一个“全部”标记误显示成一个知识点。

这样解决了全选后标签过多、分组选项与单项重复以及选择状态难以撤销的问题。

## 3. 前后端数据合同

新增 `AssignmentFilterConfig`，结构分为：

```text
grade_codes
chapter_codes
required
├── knowledge_point_codes
├── core_literacies
└── difficulty_counts
personalized
├── knowledge_point_codes
├── primary_competency
└── question_count = 3
history
└── assignment_id
```

后端校验包括：

- 年级、章节和两组知识点不能重复；
- 必做题难度键限于 `1`～`5`；
- 各难度数量必须是非负整数；
- 必做题至少 1 道、最多 30 道；
- 个性化预留题量固定为 3。

`RecommendationRequest` 同时扩展为支持多个 `chapter_codes` 和多个 `grade_codes`，并保留 `chapter_code` 作为旧链路和作业主章节字段，兼容原有请求。

题库筛选目录接口补充返回章节实际包含的：

- `grades`；
- `core_literacies`。

前端对应 TypeScript 类型同步更新。

## 4. 必做题组卷逻辑

### 4.1 候选题范围

必做题候选查询支持多年级、多章节，并可附加知识点和核心素养条件。最终只保留：

- 未归档；
- `grading_readiness = machine_ready`；
- `source_review_status = reviewed`。

知识点条件与核心素养条件相互独立：

- 只选知识点时，按主知识点过滤；
- 只选核心素养时，按题目 `core_literacy` 过滤；
- 两者都选择时，题目必须同时满足两类条件；
- 两者都不选时，覆盖所选年级与章节。

核心素养字段按 `、`、中英文逗号、中英文分号、`/` 和 `|` 拆分，兼容一道题标注多个素养。

### 4.2 全班统一与确定性

系统不再针对每名学生单独推荐必做题，而是：

1. 根据教师筛选条件构造一次候选池；
2. 按难度星级分别处理；
3. 每个难度内按 `original_qid`、`question_id` 稳定排序；
4. 按星级数量截取题目；
5. 将同一题目模板复制到全班每名学生的预览结果。

因此，同一作业内所有学生的必做题完全相同，预检结果也可稳定复现。

如果某个星级库存不足，系统不跨星级自动补齐，而是返回：

```text
status = insufficient_candidates
reason_codes = ["insufficient_difficulty_inventory"]
shortfall = 缺少题数
```

教师可据此减少该星级题量，或放宽年级、章节、知识点和核心素养范围。

## 5. 核心素养筛选修正

初版实现要求先选知识点，并从 `KnowledgePoint.core_competencies` 推导可选能力；这使核心素养不能独立筛选，也混淆了“知识点能力映射”和“题目自身核心素养标注”。

随后调整为：

- 前端核心素养选项使用固定的课程素养集合；
- 必做题核心素养不再依赖是否已选知识点；
- 个性化“主要能力”也可独立选择；
- 后端改读 `Question.core_literacy`；
- 知识点与核心素养同时存在时明确取交集。

该调整使两个筛选维度职责清晰，并与题库题目字段保持一致。

## 6. 历史作业入口

新增接口：

```http
GET /api/v1/assignments/recent-completed?limit=5
```

“已完成”定义为：

- 作业至少包含一名学生的试卷；
- 草稿试卷数为 0；
- 至少有一份未失效的已发布试卷。

前端只展示最近 5 次符合条件的作业，由教师明确选择来源，不根据“昨天”等相对描述自动推测。

本轮尚未从所选历史作业中抽题；`assignment_id` 仅写入筛选配置，等待后续回顾策略接入。

## 7. 预检、生成与审计一致性

预检仍保持只读，不创建 Assignment 或 PaperInstance。正式生成时重新使用相同的筛选配置，并将预检得到的有效推荐参数写入作业。

新增配置分别保存到：

- `teaching_scope.filter_config`；
- `generation_config.filter_config`；
- `generation_config.recommendation_parameters`；
- 试卷推荐审计。

请求指纹覆盖整个创建请求（不含幂等键本身）。如果相同幂等键被用于不同筛选请求，后端返回冲突，避免把旧作业误当成本次生成结果。
