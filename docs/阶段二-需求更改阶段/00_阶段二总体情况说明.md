## 1. 本阶段目标

本次需求变更聚焦创建作业页面和三类题目模块：

```text
教师填写作业标题并选择班级
→ 选择年级和章
→ 配置必做题
→ 配置个性化筛选条件
→ 选择历史回顾来源作业
→ 只读预检
→ 确认生成班级作业草稿
```

三类题目的本轮状态为：

| 模块 | 本轮目标 | 当前状态 |
| --- | --- | --- |
| 必做题 | 完成筛选、预检和正式组卷 | 已实现 |
| 历史回顾 | 按教师选定的历史作业和每名学生的错题组卷 | 已实现基础规则 |
| 个性化 | 只完成筛选界面、参数校验和配置留痕 | 后端组卷暂未实现 |
| 周总结 | 按多份来源作业中的历史回顾再错结果逐学生组卷 | 已实现 |

当前普通作业由三类题目组成：

```text
普通作业 = 全班一致的必做题
         + 每名学生不同的个性化题（当前仅保留配置，尚未实际出题）
         + 每名学生不同的历史回顾题
```

周总结是与普通作业相互独立的 Assignment。所谓“周五有两张卷子”，业务含义是教师可以同时创建当天普通作业和一份周总结，而不是把周总结题混入当天普通作业，也不是由系统根据自然日自动创建。

## 2. 最终保留的筛选项

创建作业页面只保留以下内容。

### 2.1 作业基本信息

- 作业标题；
- 班级。

学生范围固定为所选班级的全部在读学生，不再要求教师手工勾选全班学生。

### 2.2 年级和章

- 年级：必选、支持多选；
- 章：必选、支持多选。

年级和章是必做题与以后接入的个性化题的共同范围。历史回顾不受本次年级和章限制，因为教师已经明确选择来源作业；历史替换题由来源错题的知识点和难度决定。

### 2.3 必做题筛选

- 节（知识点）：可选；
- 核心素养：可选、支持多选；
- 1～5 星每个难度的题目数量：由教师分别设置。

各难度数量之和就是本次作业的必做题总数。

知识点和核心素养是两个独立筛选项：

- 两者都不选：在已选年级和章的全部必做题中选题；
- 只选知识点：按知识点筛选；
- 只选核心素养：按核心素养筛选；
- 两者都选：题目必须同时满足两个条件，即取交集。

### 2.4 个性化筛选

- 节（知识点）：必选，可选择一个或多个；
- 主要能力：必选；
- 题目数量：固定 3 道，不允许教师修改。

教师选择知识点后，界面显示这些知识点所对应的能力，教师从中任选一个作为主要能力。

本轮只保存个性化筛选配置，不把这 3 道题加入预检结果或最终试卷。页面必须明确提示“个性化待接入”，不能让教师误以为已经完成个性化组卷。

### 2.5 历史回顾筛选

- 展示当前班级最近五次已经全部批改完成的作业；
- 展示作业标题和完成时间；
- 由教师明确选择其中一份作为历史回顾来源；
- 允许教师不选择历史回顾作业。

系统不能仅根据自然日自动判断“昨天的作业”。教师昨天可能发布多份作业，而今天只想回顾其中一份，因此必须保留人工选择来源作业的入口。

## 3. 前端“全部”选项规则

为了避免多选框中出现大量标签，界面可以保留以下“全部”选择：

```text
全部年级
全部章节
本年级全部章节
全部知识点
本章全部知识点
```

这些值只允许作为前端交互哨兵，不能直接发送给后端。预检和正式生成前必须：

1. 展开成真实的年级、章节和知识点代码；
2. 删除重复代码；
3. 清除已经不属于当前章节范围的知识点；
4. 保证预检和正式生成使用完全相同的展开结果。

## 4. 必做题组卷规则

### 4.1 候选池

必做题候选必须同时满足：

```text
教师选择的年级
∩ 教师选择的章
∩ Question.is_required = true
∩ 可选知识点范围
∩ 可选核心素养范围
∩ 未归档
∩ 可机判
∩ 来源已审核
```

题目即使满足其他条件，只要题库中的“是否为必做题”为否，就不能进入必做题预检或正式组卷。

### 4.2 全班统一

必做题对班级内每名学生完全相同。系统只生成一次必做题模板，再复制给每名学生的试卷草稿。

### 4.3 按难度取题

系统分别处理 1～5 星候选池：

1. 按难度从低到高处理；
2. 同一难度内按 `original_qid → question_id` 稳定排序；
3. 按教师设置的该难度数量截取；
4. 某个难度库存不足时不跨难度补题；
5. 返回 `insufficient_difficulty_inventory` 和对应缺口，由教师减少题量或放宽筛选范围。

该确定性规则用于保证相同题库状态、相同筛选条件下，预检与正式生成得到同一套必做题。

### 4.4 审计

每道必做题的选择审计记录：

```text
source_module = required
reason_codes 包含 required_question 和对应难度
```

展开后的筛选条件和难度题量同时保存到作业配置和试卷推荐审计中。

## 5. 个性化题目后续规则

本节只记录以后实现时需要遵守的业务口径，本轮不开发后端组卷逻辑。

### 5.1 选题依据

个性化题按每名学生的素养能力画像分别生成。教师先选择知识点，再从对应能力中选一个主要能力，系统使用该主要能力的强弱确定基础难度。

### 5.2 固定三道题的难度

设学生在所选主要能力上的基础难度为 `d`，三道题的目标难度为：

```text
d、d + 1、d + 2
```

遇到五星上限时不超过 5 星：

- `d = 1`：1 星、2 星、3 星；
- `d = 2`：2 星、3 星、4 星；
- `d = 3`：3 星、4 星、5 星；
- `d = 4`：4 星、5 星、5 星；
- `d = 5`：5 星、5 星、5 星。

这三道题都是非必做题，并且按学生分别生成。知识点可能对应多个能力，教师必须从所选知识点对应的能力中选择一个作为主要能力；系统只使用这个主要能力的画像分数确定 `d`。

具体实现前仍需明确能力画像如何映射到基础难度，以及候选题不足时如何降级。本轮只保留界面和配置，不提前实现或伪造结果。其他文档中出现的主体题、挑战题、复习题比例不替代本文件的固定三道题规则。

## 6. 历史回顾组卷规则

### 6.1 来源作业

历史回顾来源必须满足：

1. 属于当前所选班级；
2. 位于最近五次已全部批改完成的作业中；
3. 没有仍处于草稿状态的学生试卷；
4. 至少存在一份当前有效的已发布试卷；
5. 每份有效试卷的每道题都已有最终判定，不能存在 `needs_review`。

来源作业由教师明确选择，系统不自动猜测哪一份是“昨天的作业”。

### 6.2 逐学生读取错题

系统对班级内每名学生分别处理所选来源作业：

1. 只读取来源作业中的必做题；
2. 使用 Attempt 的当前最终结果；
3. 只处理已确认且答错的题；
4. 只处理一星、二星、三星错题；
5. 学生没有符合条件的错题时，该学生不生成历史回顾题。

因此，同一班级中不同学生的历史回顾题数量和内容可以不同。

如果某名学生在教师选定的来源作业中没有符合条件的错题，则该学生当天没有历史回顾题；不能为了凑题量读取其他来源作业、其他学生错题或其他难度题目。

### 6.3 替换题规则

每道符合条件的历史错题生成一道替换题，替换题必须：

- 与原错题属于同一知识点；
- 与原错题难度相同；
- 不受本次教师所选年级和章限制；
- 与来源错题属于同一知识点、同一难度；
- 未归档；
- 可机判；
- 来源已审核；
- 不能是原错题；
- 不能与该学生在所选来源作业整张有效试卷中的任何题目重复；
- 不能与当天必做题重复；
- 个性化组卷接入后，不能与当天个性化题重复；
- 不能与该学生已选中的其他历史题重复。

候选池按 `original_qid → question_id` 稳定排序，保证预检和正式生成一致。

若某道错题找不到同知识点、同难度的替换题：

- 保留其他已经选中的历史题；
- 返回 `insufficient_history_inventory`；
- 不换知识点；
- 不跨难度补题。

### 6.4 审计

历史回顾题记录：

```text
source_module = history
reason_codes = history_review、source_required_wrong、same_knowledge_point、same_difficulty
```

同时保存来源错题的 Attempt ID 和修订号，使生成结果可以追溯到教师所选历史作业中的具体错误证据。

## 7. 连续错题标签与周总结

### 7.1 两次作答与标签

“连续错两次”按业务链路定义，不按任意两道同知识点题目计算：

```text
来源作业中的一至三星必做题答错
→ 下一次作业生成同知识点、同难度历史回顾题
→ 历史回顾题再次答错
→ 该学生的该知识点标“否”
```

历史回顾题答对则标“是”。周总结中同一知识点的两道题只要有一道最终确认错误，就标“弱”；两道均正确则标“是”。标签持久化到 `student_knowledge_statuses`，但每次提交、教师改判、重新判分或图片确认后都会根据当前有效发布试卷和最终 Attempt 结果重新回放，不能由旧标签覆盖教师的最终改判。

### 7.2 周总结不是固定周五任务

周总结与当天普通作业是两个独立 Assignment。系统不根据自然日或“周五”自动生成，教师从作业列表点击“创建周总结”。

由于“最近五次”与“最多选择六个”在数量上冲突，当前实现采用可执行口径：

- 列出当前班级最近六次已全部批改完成且包含必做题的普通作业；
- 教师可多选一至六份；
- 周总结自身不会再次进入来源作业列表。

全班使用同一组由教师选定的来源作业，因此“本周回顾范围”对全班一致；但每名学生在这些来源作业中的历史回顾结果不同，“否”知识点集合也不同，所以每名学生最终生成的周总结内容可以不同。

### 7.3 逐学生生成

系统只读取教师所选来源作业中的历史回顾题。历史回顾题最终确认错误表示该知识点经过“原必做题错 + 历史回顾再错”，因此进入该学生本次周总结的“否”知识点集合；历史回顾题最终确认正确则将该知识点标为“是”。

同一组来源作业对全班一致，但每名学生的历史回顾结果不同，所以每名学生的周总结题目可以不同。没有“否”知识点的学生不创建周总结试卷草稿。

### 7.4 题目与短缺

每个“否”知识点请求两道题：

- 当前固定难度为 3 星；
- 未归档、可机判、来源已审核；
- 不与该学生所选来源作业中的任何题目重复；
- 同一份周总结内不重复；
- 按 `original_qid → question_id` 稳定选择。

若库存不足，不跨知识点或跨难度补题。系统返回逐学生短缺数，但仍创建含当前可用题目的草稿；即使该学生所有目标题都短缺，也保留 `requested_count`、`selected_count = 0` 和 `shortfall` 的空草稿，且空草稿不能发布。

后续会把固定 3 星替换为“根据该学生在该知识点上的正确率确定难度”。在该动态难度规则正式实现并更新本文件前，3 星是唯一有效口径。

## 9. 验收清单

### 9.1 页面与请求

```text
□ 页面只保留作业标题、班级、年级、章和三个题目模块。
□ 年级和章均为必选、多选。
□ 必做题知识点和核心素养均可不选，也可独立选择或同时选择。
□ 必做题各难度数量之和正确显示为必做题总数。
□ 个性化知识点和主要能力必选，题量固定显示为 3。
□ 页面明确说明个性化后端组卷尚未接入。
□ 历史回顾只列出当前班级最近五次已全部批改完成的作业。
□ 所有“全部”哨兵在请求前展开，API 载荷中没有 __all_* 值。
```

### 9.2 必做题

```text
□ 候选题全部满足 is_required = true。
□ 知识点和核心素养同时选择时按交集过滤。
□ 全班学生的必做题 ID 和顺序完全相同。
□ 不可机判、未审核或已归档题目不会进入候选池。
□ 某个难度库存不足时返回明确缺口，不跨难度补题。
□ 同一条件下预检与正式生成的必做题一致。
□ 选择审计记录 source_module = required。
```

### 9.3 历史回顾

```text
□ 来源作业属于当前班级且已经全部批改完成。
□ 只读取来源作业中的必做题。
□ 只处理最终确认错误的一至三星题。
□ 一道来源错题对应一道同知识点、同难度替换题。
□ 无符合条件错题的学生不生成历史回顾题。
□ 历史题不与该学生所选来源作业中的任何题目重复。
□ 历史题不与当天必做题、当天个性化题（接入后）或其他已选历史题重复。
□ 库存不足时返回 insufficient_history_inventory，不跨范围补题。
□ 预检与正式生成结果一致。
□ 选择审计记录 source_module = history，并可追溯来源 Attempt 和修订号。
```

### 9.4 周总结

```text
□ 作业列表“创建作业”旁提供“创建周总结”入口。
□ 周总结与当天作业是两个独立 Assignment。
□ 只列出当前班级最近六次已全部批改且包含必做题的普通作业。
□ 教师可多选一至六份来源作业。
□ 只把来源作业中最终确认错误的历史回顾题对应知识点标为“否”。
□ 每名学生按自己的“否”知识点生成试卷，没有“否”知识点则不创建试卷。
□ 每个“否”知识点请求两道三星题。
□ 周总结题不与该学生所选来源作业中的任何题目重复，卷内也不重复。
□ 库存不足时显示短缺但仍生成草稿，不跨知识点或难度补题。
□ 周总结任一题最终确认错误后标“弱”，两题全对标“是”。
□ 教师改判后“是 / 否 / 弱”状态按当前最终证据重新计算。
□ 选择审计记录 source_module = weekly_summary，并可追溯触发“否”的历史 Attempt。
```

## 10. 一句话结论
