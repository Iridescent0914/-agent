# 数学教学 Agent Demo 开发步骤规划

> 版本：v0.4（2026-10-09 修订）  
> 对应文档：[需求分析](01_数学教学Agent_Demo需求分析.md)、[技术设计方案](02_数学教学Agent_Demo技术设计方案.md)  
> 当前目标：先完成手动录入与规则批改的内部闭环原型（M0–M4），再完成包含固定答题区图片识别的教师演示版（M0–M6）。  
> 开发原则：先稳定跑通确定性业务闭环，再接入 OCR/VLM 等 AI 增强能力。

---

## 1. 开发目标与边界

本 Demo 要演示的主流程如下：

```text
导入有理数题库
→ 创建虚拟学生及初始学习记录
→ 按学生画像生成个性化作业
→ 教师替题、调整顺序、发布
→ 学生作答（原型手动录入，教师演示版增加图片识别）
→ 规则自动批改 / 人工复核
→ 更新学生画像
→ 下一轮组卷体现新的薄弱点
```

本阶段不把以下内容作为完成前提：

- AI 自动出新题与验题；
- 证明题、复杂计算过程的自动批改；
- 整页手写 OCR 的稳定识别；
- 知识图谱数据库、复杂 RAG、多 Agent；
- BKT、IRT 等复杂教育测量模型；
- 真实学校账户、权限体系和真实学生数据接入。

## 2. 总体路线与里程碑

| 里程碑 | 阶段 | 主要结果 | 核心验收 |
|---|---|---|---|
| M0 | 数据摸底与题库小样本 | 30–50 道已核对题目、考点树、导入格式 | 每题可稳定判分且可追溯来源 |
| M1 | 工程骨架与基础数据 | 前后端、数据库、题库和虚拟学生 | 本地一键启动，可查看题目和学生 |
| M2 | 学生画像 | 掌握度、置信度、弱点和基础可视化 | 每个画像结论能回溯到作答记录 |
| M3 | 个性化组卷与发布 | Assignment、独立试卷、教师调整、编号和冻结 | 选题有依据，试卷版本可追溯 |
| M4 | 手动录入批改闭环 | 规则判分、复核、去重、改判重算 | 重复提交不重复计数，画像驱动下一轮选题 |
| M5 | 演示打磨与测试 | 图表、班级学情、演示数据、自动测试 | 可稳定完成一次完整演示 |
| M6 | 固定答题区与 VLM | 打印导出、真实图片提取、原图核对 | 拍照批改闭环可演示，失败可手动处理 |
| M6.1 | 独立答题卡与自动定位 | 固定模板、定位标记、逐题坐标、自动裁剪 | 答案与题号稳定对应，可用于更接近真实课堂的拍照采集 |

M0–M4 完成表示“内部闭环原型完成”；M5 完成演示打磨；M6 是教师演示版的必需阶段。不能以手动录入或模拟 OCR 代替图片识别需求的验收。二维码自动识别、自动裁剪、独立答题卡和多页批量处理后置。

## 3. M0：数据摸底与首批题库准备

### 3.1 目标

将已有“有理数”校本审核 DOCX 中的内容，整理为可用于自动组卷和批改的小规模结构化题库。

当前开发阶段只关注有理数章节。M0 和后续 M1 暂不抽象多章节通用导入流水线，不获取或处理其他章节数据；先基于有理数题库跑通完整 Demo 闭环，再决定是否扩展。

不要一开始尝试一次性完美解析整章题目。首批题目足以跑通闭环即可。

### 3.2 首批题目选择标准

优先选取 30–50 道题目，满足：

- 选择题或填空题；允许一组小题作为一个 `Question`，但组内答案必须逐项结构化；
- 覆盖低、中、高三档难度；
- 标准答案明确；
- 可明确关联一个主考点；
- 不依赖复杂图形、复杂排版或完整书写过程；
- 可通过确定性规则判分。

首批建议覆盖的考点不超过 8–10 个，例如：

```text
正数与负数
数轴
相反数
绝对值
有理数大小比较
有理数加减法
有理数乘除法
有理数乘方与混合运算
```

### 3.3 数据导入技术核对

“校本审核 DOCX”作为题目、标签和参考答案的权威来源，导入后统一记录 `source_review_status=reviewed`，不要求老师再次核对已有题库内容。开发侧只检查抽取和结构化是否正确：

- `original_qid` 能否回溯到原始 DOCX；
- 题干、题型、难度、知识点、考点是否成功抽取；
- 选择项、空位及小题编号是否能与参考答案逐项对应；
- 标准答案是否已转成确定性的 `correct_answer` 和匹配规则；
- 公式与图片资源是否成功关联，浏览器不支持的 WMF 是否进入转换队列；
- 题目是否适合进入首批自动判分种子库。

状态分为两层：

```text
source_review_status: reviewed
import_status: parsed / needs_technical_cleanup / excluded
grading_readiness: machine_ready / raw_answer_only
```

`raw_answer_only` 表示校本参考答案已经保存，但程序尚未可靠拆成逐项判分结构。这类题保留在全量中间库，由开发者完成答案拆分或资源转换；自动校验通过后再进入种子库，不转回老师重复审核。

### 3.4 首批题目数据格式

首批可先采用 JSON 或 CSV 作为种子数据，再由导入脚本写入数据库。单题示例：

```json
{
  "original_qid": "q.math.g6.rational.school.037",
  "chapter": "有理数",
  "section": "1.2 有理数的加法",
  "question_type": "choice",
  "difficulty": 2,
  "question_text": "……",
  "options": {"A": "……", "B": "……", "C": "……", "D": "……"},
  "correct_answer": "C",
  "answer_match_type": "choice",
  "answer_normalization_rule": {},
  "main_exam_point": "有理数加法",
  "related_exam_points": ["符号判断"],
  "solution": "……",
  "wrong_analysis": "……",
  "source_file": "rational_有理数_校本审核（黄）.docx"
}
```

### 3.5 M0 验收

- 至少 30 组题通过导入技术核对，且均为 `machine_ready`；
- 每组题都有标准答案、题型、难度、主考点和判分规则；
- 小题组保留为一个题库实体，组内答案项的 `item_id` 唯一且答案非空；
- 可定位回原始题库文件与 `qid`；
- 至少覆盖 5 个有理数考点；
- 可判分答案中不包含图片占位符，首批题目不依赖模型重新求解即可判分；
- `python scripts/validate_m0.py` 返回 0 个错误。

M0 已于 2026-09-23 按上述标准完成；实施结果见 `code/docs/04_M0_第一步工作总结与M1交接.md`。

```text
├── data/
│   ├── seed/
│   └── import_audit/
├── scripts/
├── docker-compose.yml
└── README.md
```

### 4.2 技术栈

```text
前端：React + TypeScript + Vite + Ant Design + ECharts
后端：FastAPI + Pydantic + SQLAlchemy
数据库：PostgreSQL
迁移：Alembic
本地部署：Docker Compose
数学判定：SymPy + 自定义归一化规则
```

### 4.3 首批数据库实体

```text
Question
KnowledgePoint
ExamPoint
QuestionExamPoint
Student
StudentMastery
Assignment
PaperInstance
PaperInstanceItem
Submission
Attempt
AttemptRevision
```

关键约束：

```text
1. published 状态的 PaperInstance 不可修改。
2. 同一学生在同一 Assignment 下的 version_no 唯一。
3. Attempt 必须关联 paper_instance_item_id。
4. PaperInstanceItem 保存题干、选项、答案和判分规则快照。
5. needs_review 状态的 Attempt 不得更新 StudentMastery。
6. instance_code 全局唯一且不复用，正文与答题区使用同一编号。
7. Submission.paper_instance_id 和 Attempt.paper_instance_item_id 各自唯一。
8. AttemptRevision 的 (attempt_id, revision_no) 唯一，人工确认不能被识别重试覆盖。
9. Submission、Attempt 的学生与试卷归属一致；未知判分使用 null 而非 false。
```

### 4.4 基础种子数据

创建至少 5 名虚拟学生。不同学生不应只靠手工设置不同 mastery，而应包含不同的历史 `Attempt`，以便系统能够解释画像与推荐原因。

建议准备的学生样例：

```text
S001：概念基础较弱，正负数、数轴错误较多
S002：计算较弱，有理数加减与符号判断不稳
S003：基础稳定，适合中等难度题目
S004：整体较强，可加入较高难度和综合题
S005：部分旧知识较久未练，最近回顾题出错，需要安排复习
```

### 4.5 M1 验收

- 前端、后端和 PostgreSQL 可在本地启动；
- 种子题库能被导入；
- 能查询、筛选题目；
- 能查看虚拟学生及其历史作答记录；
- 数据库迁移可从空库重复执行。

## 5. M2：学生画像与规则推荐基础

### 5.1 学生画像设计

画像的核心是 `StudentMastery`，按“学生 × 考点”保存：

```text
mastery                 0~1 的当前掌握度
confidence_level        low / medium / high（作答证据量分档）
attempt_count           有效作答次数
correct_count           答对次数
recent_wrong_count      最近错误次数
last_practiced_at       最近练习时间
```

冷启动规则：

```text
初始 mastery = 0.5
0~2 次有效作答：low
3~7 次有效作答：medium
8 次及以上有效作答：high
```

页面必须明确提示：这些阈值只是 Demo 的证据数量分档，不是统计置信概率。低证据量不代表学生能力弱；零次有效作答显示“未评估”，0.5 仅作内部初值。同时展示不同题目数与练习范围，重复上传不得计数。

### 5.2 掌握度更新规则

第一版使用透明的 EMA 更新：

```text
new_mastery = (1 - α) × old_mastery + α × correctness
α = 0.2
```

其中：

```text
correctness = 1  答对
correctness = 0  答错
```

仅 `auto_confirmed` 或 `teacher_confirmed` 的作答更新画像；`needs_review` 在教师确认前不更新。

M2 实现可重放的纯计算逻辑：从 0.5 开始，按 `(answered_at, id)` 稳定顺序计算有效作答及曲线，每个点可追溯 Attempt 与修订号；M4 接入提交、改判和事务处理。Demo 只更新题目快照中的主考点，关联考点用于检索及推荐。EMA 仅为选题参考，不是已校准的能力分数。

### 5.3 个性化选题规则

使用“候选过滤 + 加权打分 + 约束抽样”，不使用 LLM。

```text
score =
0.40 × weakness
+ 0.25 × recent_wrong
+ 0.20 × difficulty_match
+ 0.15 × forgetting
```

其中：

```text
weakness = 1 - mastery
```

约束规则：

- 不超出教师设置的章节与教学范围；
- 同一份试卷不重复题目；
- 短时间内避免重复同一道题；
- 控制同一考点的最大占比；
- 仅选择标记为“可自动判分”的首批题目；
- 新知识与已学回顾范围分别由教师设置；
- 各推荐分项先归一化至 0–1；久未练习仅提高回顾优先级，不直接判为已遗忘；
- 新学生、新考点采用教师设定的基础难度与诊断题，不按默认 0.5 判为中等能力；
- 候选不足时返回缺口及原因，请教师调整条件，不静默超范围或生成新题补足。

### 5.4 M2 验收

- 能查看学生的考点掌握度和数据置信度；
- 能展示最近错误、薄弱点和推荐复习内容；
- 推荐结果包含可解释的推荐理由；
- 新学生不会因一两次作答被过度判断。

## 6. M3：个性化组卷、教师调整与发布

### 6.1 核心流程

```text
创建 Assignment
→ 选择学生或班级
→ 设定章节、教学范围、题量和题型
→ 为每位学生生成 PaperInstance(draft)
→ 生成 PaperInstanceItem
→ 教师查看推荐理由、换题、删题、调序
→ 发布 PaperInstance
→ 冻结试卷与判分规则快照
```

### 6.2 新知识与旧知识配比

首版可提供简单默认值：

```text
新知识练习：60%~70%
旧知识回顾：30%~40%
```

教师可以按作业目的调整比例。

### 6.3 试卷版本规则

```text
draft：可编辑
published：题目与判分快照不可编辑；可通过生命周期操作撤回或被新版作废
```

发布后如需改题：

```text
创建新的 PaperInstance
version_no + 1
supersedes_instance_id 指向旧实例
```

不得修改旧版本的题目、答案或判分规则。草稿可以整份删除；已发布版本只能撤回，不能物理删除。已交作业始终指向当时版本。新版本生成新编号并自动作废其直接前版；查找旧编号仍返回旧版及明确的作废原因，不能静默重定向到最新版。

M3 实现 instance_code 及按编号查询；M6 从发布快照生成可打印正文和统一答题区，二者使用同一编号。草稿预览标记“未发布”，学生版不包含标答。教师在系统内完成替题后再导出；系统外修改需同步登记实际版本，否则暂停自动批改。

### 6.4 M3 验收

- 一次 Assignment 下，至少 5 名虚拟学生按各自历史生成独立试卷，选题差异有依据，不要求试卷两两不同；
- 教师可以替换、删除、排序，也可以删除整份草稿；
- 发布后试卷不可修改；
- 题库内容之后发生改变时，已发布试卷仍保留原始快照；
- 已发布版本可以撤回但保留快照与编号；
- 可通过 `instance_code` 唯一定位学生试卷；新版发布后旧版自动作废，旧编号仍正确定位旧版并返回作废状态；
- 编号与学生不符、版本不明时不能直接批改。

## 7. M4：手动批改、人工复核与画像更新

### 7.1 先完成手动录入

第一版批改页面应支持：

```text
选择学生试卷
→ 按题号录入学生答案
→ 自动判分
→ 展示低置信度或无法判定项
→ 教师修正或确认
→ 更新画像
```

手动录入是主流程的一部分，不只是 OCR 失败时的临时替代；它确保核心业务不依赖外部模型。

### 7.2 判分规则

第一版支持：

```text
choice：选项字母标准化后直接比较
exact：严格文本或格式比较
numeric：安全解析后进行数值 / 简单表达式等价判断
```

数学解析安全边界：

- 限制输入长度；
- 使用字符白名单；
- 禁止 `eval` 和任意 Python 代码；
- 限制 SymPy 解析与化简耗时；
- 解析失败、超时或规则不明时进入人工复核。

### 7.3 人工复核状态

```text
auto_confirmed    系统已确定判分
needs_review      需要教师确认
teacher_confirmed 教师已确认或改判
```

必须记录：

- 原始学生答案；
- 归一化结果；
- 自动判定；
- 图片识别状态与 OCR 自报分数（手动录入时为空）；
- 教师最终判定；
- 判定时间和审核时间。

### 7.4 重复提交与改判实现

- 同一试卷创建唯一 Submission，追加图片和补拍作为附件记录，重复请求复用已有结果；文件哈希仅辅助去重。
- 同一试卷题目创建唯一 Attempt；答案变化或人工改判追加 AttemptRevision，保存前后值、原因、操作人和时间。
- review 使用 expected_revision_no 检查并发冲突；未变化的重复操作不追加学习记录，识别重跑不覆盖教师确认。
- 按学生串行处理，在同一事务中更新当前结论、修订记录与受影响考点画像；失败整体回滚。
- 改判、撤销确认后从当前有效作答历史重算掌握度、错题和曲线；原作答时间不变，不在改判当天伪造一次学习。
- 真正再次练习创建新的作业或试卷实例；教师学情备注单独保存，不直接覆盖掌握度。

### 7.5 M4 验收

- 选择题可稳定自动批改；
- 简单填空题按题目规则正确判断 `1/2`、`0.5`、`2/4` 等情况；
- 无法确认的题目不会自动更新画像；
- 重复点击提交、补拍、手动修正同一份作业时，有效作答不重复计数；
- 教师修改历史判分或撤销确认后，画像与按当前有效记录全量重算结果一致；
- 并发请求不会重复计数，旧修订号不能覆盖最新结果；
- 每一次掌握度变化可追溯到对应 Attempt 和 PaperInstanceItem；
- 再次组卷时，错题和薄弱考点能影响选题权重。

至此，内部闭环原型（M0–M4）已完成；教师演示版还需 M5、M6。

## 8. M5：可视化、演示与质量保障

### 8.1 前端演示页面

第一版页面：

```text
1. 题库
2. 学生列表
3. 学生画像
4. 个性化组卷
5. 学生试卷预览 / 发布
6. 作业批改
7. 班级学情总览
```

重点可视化：

- 考点掌握度条形图；
- 能力雷达图（仅展示有教师核对过的考点映射及作答证据的维度；不足时用考点图表替代）；
- 掌握度变化曲线；
- 最近错题与薄弱点；
- 班级考点正确率；
- 推荐原因。

### 8.2 测试策略

单元测试：

- 答案归一化与等价判断；
- 掌握度更新；
- 推荐打分与约束；
- 发布后不可变规则；
- 题目快照与 Attempt 关联。

集成测试：

```text
导入题库
→ 创建学生
→ 生成学生试卷
→ 替题并发布
→ 录入答案
→ 判分 / 审核
→ 更新画像
→ 再次组卷
```

演示数据应固定，使每次演示的初始状态、作答结果和推荐变化可以重复。

必须覆盖的业务回归场景：

1. 老师发布前替换第 3 题，按替换后的题目和标答批改。
2. 发布 V2 后上传 V1 作答，仍按 V1 判分；编号不明则暂停。
3. 同一作业重复提交、补拍或并发提交，Attempt 数和画像不重复增加。
4. 将早期一次“错”改为“对”，及将已确认结果撤销为待复核；画像与全量重算一致。
5. 图片漏题、无法辨认与真实空白区分处理，不将识别失败记成错题（M6 接入后执行）。
6. 新学生和未评估能力不被展示成低分；题库不足时明确返回缺口。

### 8.3 M5 验收

- 可从空数据库导入种子数据并完成全流程；
- 一次完整演示不依赖 LLM 或 VLM；
- 核心测试通过；
- 页面展示能说明“推荐依据、批改依据、画像依据”。

## 9. M6：固定答题区与 VLM

本阶段在内部闭环稳定后实施，是教师演示版的必需阶段；自动二维码识别可后置。

### 9.1 答题卡与实例码

使用 M3 实现的 `instance_code`，从最终发布快照导出可打印试卷，优先在页底放统一答题区。正文和答题区必须打印同一短码，题号与空序号固定；可附加二维码，但先支持教师按纸面短码选择准确版本：

```text
instance_code
→ PaperInstance
→ Student
→ PaperInstanceItem
→ 题目顺序、答案快照、答题区域
```

教师替题后重新发布新版本，新旧实例并存。旧版上传仍按旧版处理，不能直接调取学生最新试卷。编号不清或与所选实例冲突时先人工确认。自动裁剪、透视校正和独立答题卡后置。

### 9.2 VLM 的职责边界

VLM 只做“读取学生最终答案”，不要求它求解题目。

建议标准输出：

```json
{
  "answers": [
    {"order_no": 1, "answer": "B", "recognition_status": "readable", "confidence": 0.98},
    {"order_no": 2, "answer": "-3", "recognition_status": "readable", "confidence": 0.92},
    {"order_no": 3, "answer": null, "recognition_status": "illegible", "confidence": 0.35}
  ]
}
```

recognition_status 还支持 blank（看到空白）、missing（缺失题号）和 ambiguous（多个可能答案）。后端核验题号范围、重复题号和缺失项；不把空值直接判错。识别请求不传标答，只提供答案图及预期题号、空序号。

模型自报 confidence 存入 ocr_confidence，不是判分正确概率。教师演示版初期，所有图片识别结果进入 `needs_review`，教师对照原图确认或修正后再调用规则判分。可批量确认清晰项目；重识别不能覆盖已确认的结论。后续实测识别策略满足要求后再开放部分自动确认。

### 9.3 隐私要求

- Demo 优先使用虚拟学生或匿名编号；
- 外部模型调用时不发送真实姓名、学号；
- 优先裁剪并上传答题区域；
- 图像保存时间和删除方式应可配置；
- 日志中不记录不必要的学生身份信息。

---

### 9.4 M6 验收与识别核对

- 完成真实照片上传、识别、原图核对、教师确认、规则判分、画像更新及下一轮组卷。
- 准备人工标注的小样本，覆盖选择题、负号、分数、空白、涂改、模糊和缺失题号；记录样本量、模型与提示版本。
- 统计逐题答案提取准确率、漏识别率、需修改比例和每份作业复核耗时；比较规范化文本，不用数学等价掩盖识别错误。
- 所有样本的不确定项能够人工处理，不能因低识别质量误更新画像；模拟 VLM 仅用于开发测试，不算真实识别验收。
- 验证 API 超时、编号不明、重复上传及教师修正场景，手动录入仍可完成业务。
- 报告实际识别效果和复核负担，不预先承诺未经核验的准确率。

## 12. 分阶段完成定义

### 12.1 内部闭环原型（M0–M4）

满足以下全部条件：

```text
□ 至少 30 道有理数选择 / 填空题经过核对后可导入和检索。
□ 至少 5 名虚拟学生拥有可追溯的不同学习记录。
□ 同一 Assignment 中，每名学生有独立 PaperInstance，选题差异有依据。
□ 教师可换题、调整顺序并发布；发布后快照不可改。
□ 手动录入答案后可完成选择题和简单填空题判分。
□ needs_review 在教师确认前不更新学生画像。
□ 重复提交和补拍不重复计数；改判、撤销确认后画像与重算结果一致。
□ 新旧版本按各自编号定位，编号不明时暂停批改。
□ 画像变化可回溯到具体 Attempt、有效修订和实际试卷题目快照。
□ 下一轮组卷能体现最新的错题和薄弱考点。
□ 在不调用任何 AI 服务的情况下，完整闭环仍可稳定演示。
```

### 12.2 教师演示版（M0–M6）

除满足内部闭环原型要求外，还须满足：

```text
□ M5 图表、证据说明、业务回归测试和演示材料完成。
□ 发布快照生成带唯一编号的学生试卷及统一答题区，学生版无标答。
□ 使用真实照片完成提取、教师确认、规则判分、画像更新的完整闭环。
□ 识别异常与真实空白区分处理，模型自报高分不能单独触发自动确认。
□ 已报告识别样本量、准确率、漏识别率、需修改比例与复核耗时。
□ VLM 失败时可手动录入，补拍和重试不重复更新画像。
□ 能力图表仅展示有证据的维度，无证据维度标为“暂未评估”。
```

二维码自动识别、自动透视校正、多页批量处理及独立答题卡不属于 M6 最小验收的必需条件；它们统一纳入 M6.1，不得与当前已经实现的“试卷末尾统一答题区”混称为已完成。

## 13. 后续阶段 M6.1：独立答题卡与自动定位

### 13.1 为什么需要独立答题卡

M6 第一版在学生试卷末尾生成统一答题区，教师手工裁剪后上传，足以验证“图片抄读—教师复核—规则判分—画像更新”的最小闭环。但它仍依赖人工裁剪，版面缺少稳定定位信息，不适合直接扩展到真实课堂的批量拍照。

M6.1 将从同一个 published PaperInstance 快照同时生成“学生试卷”和“独立答题卡”。学生只在固定答题框内填写最终答案，系统据此稳定建立：

```text
纸面位置
→ instance_code / version_no
→ order_no / blank_id
→ PaperInstanceItem
→ 学生最终答案
```

### 13.2 独立答题卡必须包含

- 作业名称、匿名学生编号、`instance_code`、版本号和 `layout_version`；
- 四角或边缘定位标记，用于方向判断、缩放和透视校正；
- 按 `order_no` 排列的固定答题框，多空题继续显示 `blank_id`；
- 选择题使用单字符框，填空题使用足够宽的书写框；
- 可选二维码只编码不含身份信息的实例码与布局版本，纸面短码仍作为人工兜底；
- 学生版不得包含标准答案、判分规则、解析、易错分析或推荐审计。

### 13.3 数据与处理链路

每个答题框保存可复现的模板坐标，例如：

```json
{
  "layout_version": "m6-answer-sheet-v1",
  "page": 1,
  "order_no": 2,
  "blank_id": "answer",
  "x": 0.12,
  "y": 0.36,
  "width": 0.76,
  "height": 0.08
}
```

坐标优先使用页面归一化比例而不是打印机像素。图片进入识别前依次执行方向检测、定位标记检测、透视矫正、页面归一化和逐题裁剪；任何定位失败都必须进入人工裁剪或手动录入，不能猜测题号。

### 13.4 实施顺序

1. 增加“试卷 + 答题卡”和“仅答题卡”两种打印模式；
2. 定义不可变 `layout_version`、分页规则和 `answer_region` 坐标合同；
3. 为每张答题卡加入稳定定位标记，并测试浏览器打印与 PDF 尺寸；
4. 实现方向检测、透视校正及逐题裁剪，保留原图与裁剪图审计关系；
5. 先继续使用一个主 VLM 识别裁剪结果，不同时堆叠多个模型；
6. 用真实匿名样本比较“整张统一答题区”和“逐题裁剪”的准确率及复核耗时；
7. 只有证据表明某类答案仍明显不足时，才评估 PP-OCRv5 或公式识别模型作为可替换 adapter；
8. 最后再考虑二维码自动定位、多页批量扫描和批量上传。

### 13.5 M6.1 验收

```text
□ published 快照可生成独立答题卡，题号、空序、短码和版本完全一致。
□ 相同 layout_version 的打印坐标可复现，分页变化会产生新版本。
□ 学生试卷和答题卡均不泄露任何答案或教师字段。
□ 正放、旋转、轻度透视和常见手机拍照均能定位页面与逐题裁剪。
□ 定位失败、页码缺失和二维码冲突时暂停处理，不错配试卷或题号。
□ 每个识别结果可追溯到原图、页面、裁剪区域和 PaperInstanceItem。
□ 仍保持全题教师确认边界，模型置信度不自动更新画像。
□ 报告相对 M6 第一版的准确率、漏识别率、修改比例和复核耗时变化。
```

M6.1 的优先级是“先稳定纸面输入，再按评测证据决定是否增加模型”。独立答题卡不是要求同时接入 Qwen3-VL、PaddleOCR、公式模型和普通 LLM；默认仍只使用一个视觉模型完成答案抄读。
