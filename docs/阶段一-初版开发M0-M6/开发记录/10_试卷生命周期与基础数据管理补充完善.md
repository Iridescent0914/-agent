# 试卷生命周期与基础数据管理补充完善

> 完成日期：2026-09-27  
> 当前数据库版本：0010  
> 适用范围：M3 个性化组卷、题库管理、学生管理

## 1. 补充背景

在 M3 主流程完成后，实际教师操作暴露出以下缺口：

1. 草稿试卷缺少直观的整份删除入口；
2. 已发布试卷需要支持撤回，撤回后还应能够重新发布；
3. 新版本发布后，旧版本需要明确显示为“已被更新”，不能继续创建修订版；
4. 教师需要从页面录入新题，并删除不再使用的题目；
5. 教师需要新增或删除学生；
6. 删除题目或学生时不能破坏历史试卷、作答和审计证据。

本次补充围绕以上问题完善了后端状态模型、数据库约束、前端交互和自动化测试。

## 2. 试卷生命周期

### 2.1 草稿删除

- draft PaperInstance 支持整份删除；
- 删除同时清理该草稿下的题目实例；
- 已发布版本禁止物理删除；
- 作业详情表格和单份试卷编辑页均提供“删除草稿”入口；
- 删除前需要教师二次确认，并使用 edit_revision 防止陈旧请求误删。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| DELETE | /api/v1/paper-instances/{paper_id} | 删除整份草稿 |

### 2.2 发布撤回

- 当前有效的 published 版本可以撤回；
- 撤回后保留实例码、发布时间、题目快照和历史查询能力；
- 撤回版本不再视为当前有效发布版本；
- 撤回原因、操作人和时间写入生命周期字段与 edit_history；
- 已撤回版本不能重复撤回。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /api/v1/paper-instances/{paper_id}/withdraw | 撤回当前有效发布版本 |

### 2.3 撤回后重新发布

- invalidation_type 为 withdrawn 的版本可以重新发布；
- 重新发布复用原版本、原实例码和原试卷内容；
- 重新发布清除撤回状态，并增加 republish 审计事件；
- 如果同一作业与学生已经存在其他有效发布版本，则拒绝恢复；
- superseded 版本永远不能重新发布。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /api/v1/paper-instances/{paper_id}/republish | 重新发布已撤回版本 |

### 2.4 新版本替代旧版本

- 修订版发布后，直接前版自动标记为 superseded；
- 前端统一显示“已被更新”，不再显示为“已发布”或笼统的“已作废”；
- 旧实例码仍然定位旧版，不会重定向到新版；
- 旧版本页面只保留“查看新版本”，不再允许创建修订版；
- 同一 Assignment × Student 最多存在一个有效发布版本。

### 2.5 历史数据兼容

0008 迁移会处理迁移前已经存在的多发布版本链：

- 每条链仅保留最新发布版本为有效版本；
- 其他版本按顺序标记为 superseded；
- 自动补齐 superseded_by_instance_id 和生命周期审计事件；
- 原实例码和试卷快照全部保留。

## 3. 教师题库管理

### 3.1 手动录入新题

题库页面右上角新增“上传新题”入口，当前采用页面表单录题。教师可填写：

- 可选的自定义题目编号；
- 题型；
- 难度；
- 主考点；
- 所属小节；
- 题干；
- 选择题选项；
- 原始参考答案；
- 解析；
- 易错分析；
- 录入教师。

新题保存后的规则：

- 自动生成或校验全局唯一 original_qid；
- 根据主考点关联知识点和章节；
- 初始进入 raw_answer_only 待审核状态；
- 选择题和填空题可继续使用既有审核流程；
- 完成结构化答案校验后才能进入 machine_ready 自动组卷池；
- 新增操作写入 review_history。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /api/v1/questions | 教师手动录入新题 |

当前“上传新题”不包含 Word、Excel、PDF 或图片批量导入，文件解析和批量导入仍属于后续扩展。

### 3.2 删除题目

题库表格每行提供“删除”操作。删除采用业务归档，而不是物理删除：

- 从题库列表和统计中移除；
- 不再进入题目审核；
- 不再进入推荐、自动组卷和备选换题；
- 保留 PaperInstanceItem 中的既有快照；
- 保留历史作答、判分和审计引用；
- 记录 archived_at 和 archived_by。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| DELETE | /api/v1/questions/{question_id} | 业务删除题目 |

## 4. 学生管理

### 4.1 新增学生

学生页面已由“虚拟学生”调整为“学生管理”，右上角提供“添加学生”。

教师可填写：

- 学生编号；
- 学生姓名；
- 班级。

约束：

- student_code 全局唯一；
- 编号只允许字母、数字、点、下划线和短横线；
- 教师新增学生标记为非演示数据；
- 新学生初始没有作答记录和画像证据，但可以立即参与新建作业。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /api/v1/students | 新增学生 |

### 4.2 删除学生

学生表格每行提供“删除”操作，同样采用业务归档：

- 从学生列表中移除；
- 不再出现在新建作业的学生选择中；
- 学生详情、画像和作答入口不再对当前管理界面开放；
- 历史 Assignment、PaperInstance、Submission、Attempt 和 StudentMastery 保留；
- 历史试卷仍可正常显示学生编号与姓名；
- 记录 archived_at 和 archived_by。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| DELETE | /api/v1/students/{student_id} | 业务删除学生 |

## 5. 数据库迁移

本次补充包含三段迁移：

| 版本 | 文件 | 作用 |
| --- | --- | --- |
| 0008 | 0008_add_paper_lifecycle.py | 增加撤回、替代和版本链字段，回填历史多发布版本 |
| 0009 | 0009_allow_withdrawn_paper_republish.py | 仅允许 withdrawn 版本恢复发布 |
| 0010 | 0010_add_catalog_archiving.py | 为 questions 和 students 增加业务归档字段 |

新增的主要字段：

- PaperInstance：invalidated_at、invalidation_type、invalidation_reason、invalidated_by、superseded_by_instance_id；
- Question：archived_at、archived_by；
- Student：archived_at、archived_by。

数据库约束继续保证：

- 已发布试卷的题目、答案、判分规则、实例码和发布时间不可修改；
- superseded 生命周期不可撤销；
- withdrawn 只能恢复为有效状态，不能改写为其他失效类型；
- 同一作业与学生最多存在一个有效发布版本；
- 归档时间和归档操作人必须同时存在或同时为空。

## 6. 前端页面变化

### 6.1 作业详情

- 草稿行显示“编辑”和“删除草稿”；
- 有效发布行显示“查看”和“撤回”；
- 已撤回行显示“查看”和“重新发布”；
- 已被更新行只允许查看；
- 状态区分为草稿、有效发布、已撤回、已被更新。

### 6.2 单份试卷详情

- 草稿支持删除和发布；
- 有效发布版本支持撤回和创建修订版；
- 已撤回版本支持重新发布或创建修订版；
- 已被更新版本只提供“查看新版本”。

### 6.3 题库

- 新增“上传新题”按钮和录题表单；
- 每行新增“删除”按钮；
- 新建完成后自动定位到新题；
- 删除后自动刷新题库列表和统计。

### 6.4 学生管理

- 新增“添加学生”按钮和表单；
- 每行新增“删除”按钮；
- 区分“演示数据”和“教师添加”；
- 新增或删除后自动刷新列表。

## 7. 运行问题修复

开发过程中曾出现前端仍返回旧模块的问题：

- Docker 挂载目录中的源码已经更新；
- Vite 开发服务器仍返回旧的转换缓存；
- 浏览器强制刷新无法解决；
- 重启 frontend 容器后恢复。

后续如果页面代码已更新但操作入口仍未出现，可执行：

    docker compose restart frontend

数据库代码更新后如出现字段不存在，应先检查：

    docker compose exec -T backend python -m alembic current
    docker compose exec -T backend python -m alembic upgrade head
